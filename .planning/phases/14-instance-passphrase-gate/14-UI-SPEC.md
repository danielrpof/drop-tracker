# Phase 14 — UI Design Contract

> Visual and interaction contract for the instance passphrase gate's frontend surface.
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Scope of this phase's UI:** exactly two new surfaces — (1) a full-screen
> `<PassphraseScreen>` rendered by `<App>` when `authStore` is unauthenticated
> (GATE-05, D-16), and (2) a **Log out** control in the existing top nav
> (GATE-06, D-10). No other screen changes. The design system, tokens, theme,
> and component library are already locked by the Phase 6 UI spec and live in
> `web/app/app.css`; this phase adds **zero** new tokens and **zero** new
> third-party dependencies.

| 2xl | 48px | Not used this phase |
| 3xl | 64px | Not used this phase |

**Passphrase screen layout:** full-viewport flex center — `min-h-screen flex items-center justify-center p-8`. Card: `w-full max-w-sm` (~384px), `rounded-md bg-card p-8`, inner `flex flex-col gap-6`.

Exceptions: none.

## Typography

Unchanged from Phase 6. Exactly 4 sizes, exactly 2 weights. Named theme tokens (`text-display`, `text-heading`, `text-body`, `text-label`) carry size + line-height + weight together.

| Role | Size | Weight | Line Height | Where used this phase |
|------|------|--------|-------------|-----------------------|
| Display | 28px (1.75rem) | 600 semibold | 1.2 | Not used (reserved for route `<h1>`s) |
| Heading | 20px (1.25rem) | 600 semibold | 1.2 | Passphrase screen `<h1>` ("Enter the instance passphrase") |
| Body | 16px (1rem) | 400 regular | 1.5 | Passphrase screen body paragraph; input text; button label |
| Label | 14px (0.875rem) | 400 regular | 1.5 | "Passphrase" field label; inline error message; Log out button label |

Weights available: **400 (regular)** and **600 (semibold)** only. No third weight. The Log out button and the Unlock button both use the button component's built-in `font-medium` (500) — this is a pre-existing component-level exception from Phase 6, not a new weight introduced here.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Screen heading | `Enter the instance passphrase` |
| Screen body | `This drop-tracker instance is private. Enter the passphrase to view the watchlist and release history.` |
| Field label | `Passphrase` |
| Field | `<input type="password">`, no placeholder, `autofocus`, `autocomplete="current-password"` |
| Primary CTA (idle) | `Unlock` |
| Primary CTA (submitting) | `Unlocking…` — button `disabled`, same width, no layout shift |
| Error — wrong passphrase (401) | `That passphrase isn't correct. Check it and try again.` |
| Error — throttled (429) | `Too many attempts. Wait about a minute, then try again.` |
| Error — network / 5xx | `Couldn't reach the server. Check your connection and try again.` |
| Success (login) | No toast, no message. `<App>` re-renders to the routed page (D-16); focus moves to the now-visible page `<h1>`. |
| Log out control | `Log out` — `<Button variant="ghost" size="sm">` with a leading `LogOut` (lucide) icon, right-aligned in the nav (`ml-auto`). |
| Destructive confirmation — Log out | **None.** Matches the project's existing destructive policy (see `watchlist.tsx` remove flow): no blocking dialog. Single click → `DELETE /session` → cookie cleared → `<App>` re-renders to `<PassphraseScreen>`. A `sonner` toast `Logged out.` confirms — **no Undo action** (re-auth is a passphrase entry away; there is nothing to restore). |

**Empty-state note:** this phase has no data collection, so there is no list empty state. The "empty" case here is the passphrase form's own first paint — covered by the heading + body copy above. Reuse the existing `EmptyState` component ONLY if the planner needs a non-form error block; the passphrase screen itself is a `<form>`, not an `EmptyState`.

**Secret-safety copy rule:** no error message, toast, log line, or DOM node ever echoes the submitted passphrase value (D-13). The field is `type="password"`; on a wrong attempt the entered value is **kept** (not cleared) so the user can correct a typo, and keeps focus.

## UI Considerations

Applicable state considerations resolved: **6 covered, 1 backstop, 1 unresolved**

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | passphrase form — first paint | ✅ covered | The gated app's first paint renders `<PassphraseScreen>` with the documented heading + body copy — never a blank screen, bare spinner, or generic error (success criterion 2, PITFALLS #23). |
| loading | initial auth flash before first 401 | ✅ covered | `authStore` is optimistically `authed=true` (D-16); the routed page renders for the moment between mount and the first `401`, then `<PassphraseScreen>` replaces it. This brief flash is explicitly accepted (D-16) — no boot-time `GET /session` check, no full-screen spinner is added. |
| loading | submit in flight | ✅ covered | While `POST /session` is pending, the Unlock button is `disabled` and shows the `Unlocking…` label (see Copywriting Contract); the input is `disabled`; no spinner overlay. |
| error | wrong passphrase (401) | ✅ covered | Documented incorrect-passphrase copy renders inline below the field as `text-destructive text-label`; entered value retained; field keeps focus; button returns to `Unlock` and re-enables once the field is edited. |
| error | throttled (429) | ✅ covered | Documented 429 copy renders in the same inline error slot; the Unlock button stays disabled until the user edits the field, discouraging immediate re-submit. |
| error | network failure / 5xx | 🧪 backstop | Documented network-error copy renders in the same inline slot. Held-out UI-state test: simulate `fetch` reject / 503 from `POST /session` and assert the network copy (not the 401 copy) appears and the form stays usable. |
| populated | authenticated app after login | ✅ covered | On success `authStore.markAuthenticated()` → `<App>` re-renders → `<Outlet/>` remounts → each route's `useEffect` re-fetches (D-16). Nav now shows the **Log out** control. |
| overflow / long-text | passphrase input value | ✅ covered | Single-line `type="password"` field; long values scroll horizontally within the fixed-height input (`h-9`), never wrap or grow the card. `max-w-sm` card width is fixed regardless of copy or error length (error text wraps to 2–3 lines within the card). |
| zero-one-many | — | ⚠ unresolved | **Log out control visibility when the gate is unconfigured.** With no `INSTANCE_PASSPHRASE` set there is no `/session` endpoint, so a rendered Log out button would 404. Recommendation: render the Log out control only after a successful login has occurred in the current session (track a third `authStore` signal), OR never render it while `authed` is still the optimistic default. Planner to confirm the `authStore` shape; treated as an assumption until then. |
