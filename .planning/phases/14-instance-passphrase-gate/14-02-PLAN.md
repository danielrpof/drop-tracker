<objective>
Expand the proven gate slice sideways with brute-force defense and auditability: a per-IP token
bucket that answers a sixth rapid login attempt with 429, a fixed jittered delay on every
`/session` response, a process-wide failed-attempt counter that raises one Discord alert per
cooldown, and structured audit lines for every authentication outcome.

Purpose: GATE-04 and D-12/D-13. The single shared secret is the whole attack surface of this
instance, so bounding guess throughput and making attempts observable are the two controls that
matter most (Pitfall 18).

Output: the throttle and global-counter machinery inside `internal/authgate/login.go`, the
Discord-backed `Alerter` implementation and `SelectAlerter` in `alerter.go`, the audit log lines,
and the wiring line in `cmd/server/main.go`.
</objective>

Add an unexported `ipLimiter` struct holding a `*rate.Limiter` and a `lastSeen time.Time`, and an
unexported `loginThrottle` struct holding a `sync.Mutex`, a `map[string]*ipLimiter`, the rate and
the burst. Give it `getLimiter(ip string) *rate.Limiter` which locks, upserts a limiter built from
the package `var`s, refreshes `lastSeen`, and returns it; and `sweep(now time.Time)` which locks and
deletes every entry whose `lastSeen` is older than the idle threshold.

Declare the tunables as package-level `var`s so tests can shrink them, following the
`internal/notifier` idiom: `loginRate` set to `rate.Every(12 * time.Second)`, `loginBurst` set to 5,
`loginDelayMin` set to 250 milliseconds, `loginDelayJitter` set to 750 milliseconds,
`limiterSweepInterval` set to 10 minutes and `limiterIdleTTL` set to 15 minutes. Add a doc comment
on the block recording that these are engineering judgement per research assumption A2, that
CONTEXT.md leaves them to the planner, and that they are single greppable literals precisely so an
operator locked out during their own testing can retune them.

Construct the throttle in `NewManager` and start the sweeper there as a goroutine driven by a
`time.Ticker` at `limiterSweepInterval`. Give `Manager` a `Close()` method that stops the ticker and
signals the goroutine to return, and call it from a `defer` in `cmd/server/main.go` alongside the
existing shutdown wiring — the process exit would reclaim it anyway, but a `Close` keeps the test
suite free of goroutines that outlive their server.

In `HandleLogin`, resolve the client address by taking the host portion of `r.RemoteAddr` with
`net.SplitHostPort`, falling back to the raw value when it carries no port. `middleware.RealIP` has
already rewritten `RemoteAddr` from the proxy headers by this point (D-14). Call `Allow()` on that
address's limiter as the very first step, before reading or decoding the body: when it returns
false, apply the delay and respond 429 with `{"error":"too many attempts"}`, emit the audit line,
and return without touching the passphrase comparison. This ordering matters — a throttled request
must never reach the digest compare, and must never increment the global counter added in Task 2.

Apply the delay in exactly one place so no response path can skip it. Compute it once as
`loginDelayMin` plus a `math/rand/v2` jitter bounded by `loginDelayJitter`, and sleep before writing
any response — success, 401 and 429 alike (D-12). Use `math/rand/v2` here deliberately and note in
the comment that this value is anti-hammer pacing, not a security primitive, and that `crypto/rand`
is reserved for the session nonce.

Write the tests first in `internal/authgate/login_test.go`, shrinking `loginDelayMin` and
`loginDelayJitter` through the `export_test.go` setters so the suite stays fast, and asserting the
delay by measuring that the elapsed time of a single request is at least the shrunk minimum. Drive
distinct client addresses by setting `RemoteAddr` on the request when calling the handler directly,
which is the reliable way to exercise per-IP behaviour without a real proxy. Cover the boundary
explicitly: attempts one through five not throttled, attempt six throttled, second address not
throttled, and refill restoring service. Add a sweeper test that inserts an entry, advances the
clock via an injected `now`, calls `sweep`, and asserts the map shrank. Add a parallel test firing
simultaneous attempts from one address and asserting no panic and a consistent final state.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Public internet → `POST /session` | The only endpoint that accepts the secret; unauthenticated and unlimited by default. |
| Reverse proxy → `middleware.RealIP` → limiter key | The throttle's fairness depends entirely on the trustworthiness of the resolved address (D-14). |
| App → Discord webhook | An outbound sink whose URL is itself a credential. |
| App → `slog` / stdout → CI and proxy logs | Everything written here may end up in a log aggregator or a public CI run. |
