<objective>
Close G-14-2. The instance passphrase gate itself is correct, verified, and passing UAT Tests 1-4 —
this plan does not touch server-side enforcement, the cookie, the 401 contract, or the login flow.
It repairs one presentation defect: `gateActive` in `web/app/lib/authStore.ts` is volatile module
state, so a full document reload while the `dt_session` cookie is still valid re-initialises it to
`false`, the loader fetch returns 200, no 401 fires, and the **Log out** control vanishes from the
nav of a user who is still fully logged in.

D-18 already says what the correct scope is: `gateActive` is set the first time the app observes a
401 **or completes a login in this browser session**. "In this browser session" is `sessionStorage`,
not a module-level `let`. This plan makes the storage match the decision.

Purpose: restore GATE-06's user-facing half — a logged-in user can always find the control that ends
their session — without giving the client any new authority. `gateActive` stays presentation-only;
the server 401 remains the sole enforcement (14-03 prohibition, carried forward).

Output:
- `authStore.ts` seeds `gateActive` from `sessionStorage` at module load and writes through on both
  `mark*` functions, with every storage access guarded against an undefined or throwing store.
- A regression test proving the Log out control survives a simulated document reload.
- A 14-UAT.md Test 5 precondition so the operator's re-run is deterministic.

Sizing note: one source file of ~90 lines and two existing test files. Three small tasks, well inside
the context target. Splitting further would cost more orchestration than the work itself.
</objective>
