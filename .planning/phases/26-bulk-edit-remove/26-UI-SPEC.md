# Phase 26 — UI Design Contract

> Visual and interaction contract for **multi-select on the Watchlist**: a leading checkbox on every
> card, a tri-state **Select all visible**, a **sticky bottom action bar** (Add tag, Remove tag,
> Preferences, Remove, Clear), an inline bulk tag picker, a tri-state **Preferences popover**, and a
> count-stating **remove confirmation**. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope of this phase's UI:**
- `WatchlistRow` gains a leading selection checkbox and a neutral selected-state ring (D-09).
- The "Your artists" heading row gains the tri-state `Select all visible` checkbox, placed next to `N of M artists` (D-09).
- A new `web/app/components/watchlist/BulkActionBar.tsx` docks at the bottom of the viewport while one or more artists are selected (D-10). It hosts the inline add-tag (`TagCombobox`, D-12) and remove-tag pickers, the Preferences popover (D-06, D-07), and the Remove trigger for `ConfirmDialog` (D-16).
- `web/app/routes/watchlist.tsx` owns selection state, pruning (D-11), stickiness (D-13), and the post-action clear (D-14).

No new route, nav entry, or theme token. No change to History, System, the search columns, the filter toolbar's controls, or the Manage tags dialog.

**Design system is already locked.** Tokens, theme, fonts, and components come from `06-UI-SPEC.md`
(`web/app/app.css`), extended by `19`, `20`, `24`, and `25-UI-SPEC.md`. This phase adds **zero** theme

### Vendored-file edit (one, in `web/app/components/ui/checkbox.tsx`)

The vendored `Checkbox` always renders `CheckIcon`, and its fill keys only on `data-checked`. base-ui
sets `data-indeterminate` and `aria-checked="mixed"` (not `data-checked`) when `indeterminate` is
true, so an indeterminate box currently renders unfilled and without a glyph. Make this change:
1. Mirror the checked fill for indeterminate: add `data-indeterminate:border-primary data-indeterminate:bg-primary data-indeterminate:text-primary-foreground`.
2. Inside `CheckboxPrimitive.Indicator`, render `MinusIcon` when the root carries `data-indeterminate` and `CheckIcon` otherwise. One way to do this is a `group/checkbox` class on the root plus `group-data-indeterminate/checkbox:hidden` / `hidden group-data-indeterminate/checkbox:block` on the two icons.

The existing card `PreferenceToggles` never pass `indeterminate`, so their rendering is unchanged.

### Deliberately NOT used

- **A separate selection mode or an "Edit" toggle.** D-09 locks always-visible checkboxes.
- **`Dialog` for Preferences.** D-07 locks a popover anchored to the bar.
- **A Popover for add-tag or remove-tag.** A `TagCombobox` nested in a Popover means two stacked portals and two Esc layers. Both tag pickers instead swap **inline into the bar**, mirroring the card's "+ tag" swap (Phase 24). Their listbox flips upward on its own because the bar sits at the viewport bottom.
- **Undo for bulk remove** (D-15, deferred).
- **`variant="destructive"` on the bar's Remove button.** The destructive token on `--popover` text measures about 3.7:1 (24-UI-SPEC [R8] flag), and red is kept for the confirm action. The bar's Remove is neutral `ghost` with `hover:text-destructive`, following the remove-artist × precedent.
- **`Switch`.** Its checked fill would read as an immediate-apply toggle, and Preferences applies on `Apply` only.

## Spacing Scale

This is the same Tailwind v4 default scale through default utilities that Phases 6, 19, 20, 24, and 25 use. **There are no custom spacing tokens.**

| Token | Value | Usage in this phase |
|-------|-------|----------------------|
| xs | 4px | `gap-1` between the card's selection-checkbox label and the cover art; icon-to-text gap inside bar buttons (Button built-in `gap-1.5` stays as shipped) |
| sm | 8px | Action bar inner padding `p-2` and `gap-2` between its items; `gap-2` between `Select all visible` and its text; `gap-2` between the popover's checkbox options |
| md | 16px | Popover built-in `p-4 gap-4`; `gap-4` between the select-all control and the `N of M artists` count; bar viewport inset `bottom-4 px-4` below `sm`; card `p-4` (unchanged) |
| lg | 24px | Bar viewport inset `sm:bottom-6`; dialog built-in `p-6` (unchanged) |
| xl | 32px | `p-8` page gutter (unchanged); `sm:px-8` horizontal inset of the bar wrapper, so the bar aligns with the page gutter |
| 2xl | 48px | Not used |
| 3xl | 64px | `EmptyState`'s built-in `py-16` (unchanged) |

**Control sizes (multiples of 4):** checkbox box `size-4` (16px); selection hit area `size-11` (44px); bar buttons `h-9` (36px) at `sm` and up and `h-11` (44px) icon-only below `sm`; inline picker input `h-9`, `sm:w-60` (240px); popover `w-80` (320px); remove-tag listbox `max-h-72` (288px).

**Exceptions:**
- **44px selection hit area.** Each selection checkbox (card and select-all) is wrapped in a `<label class="flex size-11 shrink-0 cursor-pointer select-none items-center justify-center">`. On the card the label also takes `-ml-3`, so the 16px box sits 18px from the card edge instead of floating 30px in. `select-none` stops a shift-click from selecting text.
- **Page bottom clearance is computed, not a token.** While the bar is mounted, it measures itself (a `ResizeObserver` on the bar's outer box) and writes `--bulk-bar-clearance` on `document.documentElement` as `{bar height + its bottom inset + 8}px`. It removes the variable on unmount. The page container's bottom padding becomes `pb-[calc(2rem+var(--bulk-bar-clearance,0px))]`, so the last card can always scroll clear of the bar.
- **Registry-internal paddings stay as shipped** (`PopoverContent p-4`, `ComboboxInput`, `Button` sizes), the same treatment Phases 20, 24, and 25 gave vendored internals.

## Interaction Contract

### Selection model (BULK-01, D-09, D-11)

- **State:** `selectedIds: Set<number>` in `watchlist.tsx`. The **effective selection** is `visible.filter(e => selectedIds.has(e.id))`, where `visible` is the same `selectVisible(entries, view, stickyIds)` result the list renders, sticky cards included.
- **Pruning:** whenever the visible id set changes (search text, tag filter, toggles, Clear filters, Back/Forward, a single-card remove, a refresh), `selectedIds` is replaced by its intersection with the visible ids. A pruned artist does **not** come back when the filter is undone. A sort change never prunes, because it never changes the set.
- **Card checkbox:** a click, Space, or a click on its 44px label toggles that artist. Focus stays on the checkbox.
- **Shift-click range:** with an anchor set (the last card checkbox toggled without Shift), Shift+click on another card's checkbox sets **every card between the anchor and the clicked card, inclusive, in current visible order** to the clicked card's new state. The anchor moves to the clicked card. The anchor resets to none on any visibility or sort change. Without an anchor, Shift+click behaves like a plain click.
- **Keyboard:** Tab reaches each card checkbox in list order, and Space toggles it. Range selection by keyboard is not provided; `Select all visible` covers the bulk case.
- **Select all visible:** when unchecked or indeterminate, activation selects **every visible artist**. When checked, it clears the selection. State: `checked` when the effective selection equals N > 0; `indeterminate` when 0 < effective < N; unchecked otherwise.
- **Clear** (bar): empties the selection. **Esc** with focus inside the bar, and no inline picker or popover open, does the same. When an inline picker or popover is open, Esc closes only that layer.

### Action bar visibility (D-10, D-14)

- The bar mounts when the effective selection becomes ≥ 1 and unmounts when it returns to 0.
- It never renders during the first-load skeletons, the error state, or the `No artists yet` state, because no selection can exist then.

### Bulk add tag (BULK-02, D-01, D-02, D-12, D-13)

1. `Add tag` → inline mode. Focus moves into the picker input.
2. Committing an option (Enter or click, existing or `Create “x”`) sends **one** request with the effective selection's ids and the tag name. The input disables and shows the pending label.
3. **Success** (2xx, including partial skips):
   - Every artist in `applied` is merged from the response's entries and marked sticky (D-13).
   - The selection clears, the bar unmounts, and the outcome toast fires (copy below).
   - Focus moves per the focus fallback chain.
   - If any id came back `gone`, `refresh()` runs, with no skeletons.
4. **Failure** (network or non-2xx): inline mode closes, focus returns to `Add tag`, **the selection is kept**, and the failure toast fires. Nothing changed on the server, so the cards are not touched.
5. **Esc or Cancel:** inline mode closes and focus returns to `Add tag`. Nothing is sent.

### Bulk remove tag (BULK-02, D-02, D-12)

The flow is the same as add tag. The picker offers only tags that at least one selected artist carries.
Artists lacking the tag are unaffected. Affected artists are merged from the response and marked
sticky, so under an active filter on that tag the cards stay visible with the chip gone (D-13).

### Bulk preferences (BULK-03, D-05…D-08)

- **Opening:** clicking `Preferences` opens the popover, and focus moves to the first checkbox (`Album`). Each box's initial state is computed over the effective selection:

| Selection's values for this type | Initial state |
|----------------------------------|---------------|
| every selected artist has it on | checked |
| none has it on | unchecked |
| mixed | indeterminate (`Minus`) |

- **Cycling:** a type that **started mixed** cycles on click: indeterminate → checked → unchecked → indeterminate. Returning to indeterminate means "leave untouched". A type that **started uniform** toggles checked ↔ unchecked, and returning to its initial value means "leave untouched".
- **Delta:** only types whose current state differs from their initial state are sent. Checked means `set` and unchecked means `unset`, on that type's axis. "On" for a mute type means muted. The request never carries full sets and never carries notes (D-05, 24 D-25).
- **Apply** is `disabled` until at least one type differs from its initial state. While in flight it reads `Applying…`, and both buttons and every checkbox are disabled.
- **Success:** the popover closes. Affected cards are merged from the response and marked sticky. The selection clears, the bar unmounts, the toast fires, and focus follows the fallback chain.
- **Failure:** **the popover stays open with the user's choices intact**, Apply re-enables for a retry, and the failure toast fires. This keeps the user's work, as Phase 24 [R2] does for note-save failures.
- **Cancel, Esc, or an outside click** closes the popover without sending, and focus returns to `Preferences` (base-ui default). The next opening recomputes the initial states from scratch.
- An empty release-type set is allowed (D-08). The UI never blocks unchecking all four.

### Bulk remove (BULK-04, D-03, D-15…D-18)

- `Remove` opens `ConfirmDialog` (`variant="destructive"`). base-ui's initial focus lands on `Cancel`, which renders first.
- **Confirm** sends one request with every effective-selection id. While in flight, the action reads `Removing…` and both buttons are disabled (existing ConfirmDialog behavior).
- **Success** (ids already gone count as removed, per D-03): the dialog closes and removed cards disappear. The selection clears and the bar unmounts. The toast fires with **no Undo**. `refresh()` runs if any id was already gone. `finalFocus` follows the fallback chain.
- **Failure:** the dialog closes and **nothing was removed**. The selection is kept, focus returns to the bar's `Remove`, and the failure toast fires.
- **Cancel or Esc:** the dialog closes and focus returns to `Remove`.

### After any bulk action (BULK-05, D-14)

- The selection is re-derived **from the refreshed entries**, so it is empty and every checkbox is unchecked. No checkbox can point at a removed artist.
- No page reload happens, and no skeletons flash, because `refresh()` keeps the current entries until the new rows arrive.

### Focus management

| Surface | Event | Focus goes to |
|---------|-------|---------------|
| Card checkbox / select-all | toggled | stays on the control |
| `Add tag` / `Remove tag` | activated | the inline picker input |
| Inline picker | Esc or Cancel | the button that opened it |
| Inline picker | request failed | the button that opened it |
| `Preferences` | activated | first checkbox in the popover (`Album`) |
| Popover | Cancel, Esc, or outside click | `Preferences` |
| Popover | Apply failed | stays on `Apply` |
| `Remove` | activated | ConfirmDialog `Cancel` |
| ConfirmDialog | Cancel, Esc, or confirm failed | bar `Remove` |
| `Clear` or bar Esc | selection cleared | **fallback chain** |
| Any bulk action | succeeded (bar unmounts) | **fallback chain** |

**Fallback chain** (the first one that exists and is enabled):
1. The `Select all visible` checkbox (the section is rendered and N > 0).
2. The filtered-to-zero `EmptyState` `Clear filters` button (M > 0, N = 0).
3. `<h1>Watchlist</h1>` (made `tabIndex={-1}`) when no artists remain (M = 0).

Pass it to `ConfirmDialog` as `finalFocus` on success, and focus it directly in the other success paths after the bar unmounts.

### Live announcements

These reuse the **one** route-level `role="status"` region through `announce()` (24 [R6]). Toasts are
sonner's own polite live region, so outcomes are not duplicated into the status region.

| Trigger | Timing | Message |
|---------|--------|---------|

### Primary CTA, empty, error, destructive (checker summary)

- **Primary CTA this phase:** `Apply` in the Preferences popover, the only `variant="default"` button the phase adds. The bar's actions are verb-first (`Add tag`, `Remove tag`, `Remove`) but deliberately neutral.
- **Empty states:**
  - With no selection, no bar renders.
  - The remove-tag picker shows `None of the selected artists have tags.`
  - The add-tag picker keeps its existing empty-vocabulary line.
  - Filtered-to-zero disables `Select all visible`, and the existing `No artists match these filters` state stays.
- **Error states:** one failure toast per action, each naming what failed and that a retry is safe. The remove failure explicitly says nothing was removed (all-or-nothing). Preferences keeps the user's edits open for retry.
- **Destructive actions:** **one**, bulk remove. It is confirmed through `ConfirmDialog` with the count in both title and action label, the first three names, and the notes/tags/seed-mode sentence. There is no Undo (D-15). Bulk tag removal is reversible and gets no confirmation (FEATURES.md).
