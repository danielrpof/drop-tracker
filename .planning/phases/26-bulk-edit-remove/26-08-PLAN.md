## Flagged assumptions

- **A3 / RESEARCH Open Question 1:** `{n}` in `Added “{tag}” to {n} artists.` is `applied.length`, the post-state count,
  which includes artists that already carried the tag. If the owner wants a new-links-only count, the server needs an extra
  `added` field. That is a copy and contract change, not a bug.
- **Planner resolution (all ids gone):** when every selected id is gone (n = 0 with no cap skips), the toast is
  `toast.success` `Added “{tag}” to 0 artists.`, with the gone sentence as its description. This applies the UI-SPEC rule
  "appended to the description, or as the description when there is none".
