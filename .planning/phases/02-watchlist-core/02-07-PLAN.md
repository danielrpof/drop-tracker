<objective>
Close gap G-02-1, which bundles two Warning findings from the phase 02 full review.

WR-01: `Service.UpdatePreferences` enforces every rule about preference values but not the rule
about supplying none of them. The "reject a call that supplies neither axis" contract for WLST-05
and WLST-06 lives exclusively in `handleUpdateWatchlist`, one layer above the boundary that
`watchlist.Store` documents itself to be — "the reusable API surface" later phases build on. Any
caller reaching the service directly gets a success, a bumped `updated_at`, and no change.

WR-02: both JSON decoders in `internal/httpserver/watchlist.go` call `dec.Decode` exactly once and
treat a nil error as "the whole body was valid." `json.Decoder.Decode` consumes one JSON value and
does not assert end-of-stream, and `DisallowUnknownFields` constrains keys inside the decoded
object, not values after it. A body of two concatenated JSON objects is accepted, processed as the
first one, and the second is silently discarded.

The developer's UAT disposition on test 1 was "fix" for both.

Purpose: these are the two remaining places in the phase where a contract is asserted by a comment
rather than by code that runs. Phase 3 adds the search proxy and Phase 4 adds a poller — both are
non-HTTP callers of `watchlist.Store`, which is exactly the population WR-01's guard protects, and
both add request bodies to a file whose decode pattern is currently copied by hand.

Output: an `ErrNoPreferencesSupplied` sentinel enforced at the domain boundary with the handler's
duplicate check collapsed onto it, a single shared body-decode path that rejects trailing values on
both JSON routes, and six tests covering all of it.
</objective>
