   plus the commit SHA, restore-key prefix `coverage-baseline-main-backend-`; frontend primary
   key `coverage-baseline-main-frontend-` plus the commit SHA, restore-key prefix

   `coverage-comment` AND per-step tolerance on both download steps, the render step and the
   comment step. Job-level alone would let the job report success while silently skipping the
   render after a failed download. The two cache-save steps' tolerance is mandatory per D-04,
   not discretionary.
3. **Frontend sidecar writer** — a Node one-liner step inside `frontend-test`, not the Go tool.
   That job sets up Node and pnpm but no Go toolchain, and relying on the runner image's
   preinstalled Go against a `go.mod` pinned to a newer language version is fragile. The
   Node step emits the identical flat key set the Go tool's sidecar mode writes, and plan
   15-01's single sidecar decoder reads both files.
4. **Workflow linting** — `actionlint` is run locally as a task verification step, installed
   with a pinned `go install`. It is not added to the pre-commit config or to CI; CONTEXT does
   not require it and this phase is already touching the shared workflow file.
