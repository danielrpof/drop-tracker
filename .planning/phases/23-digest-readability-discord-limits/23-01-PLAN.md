<objective>
Deliver a chunked, window-stamped digest end to end: the window header line every
digest message opens with (DGST-11), the chunk data structures that carry each
rendered line's event id alongside its text, a pure splitter that never exceeds
Discord's 4096-rune Description ceiling and never cuts inside a line, and the
`SendDigestIfDue` send/ack loop that delivers N ordered messages and acks each one
as it lands (DGST-12).

The single-chunk path is the tracer: for a digest that fits one message this
collapses to exactly Phase 22's behavior — one `Send`, one `AckDigestBatch` — plus
one new header line. That is the regression-safety property (D-14) and the reason
this slice is shaped this way.

Purpose: prove the whole architecture (compose -> split -> send -> per-chunk ack)
on one real path before plans 23-03 and 23-04 expand boundary policy, position
indicators, continuation markers, the chunk cap, and the time budget onto it.
Output: `internal/notifier/digest_chunk.go`, the `AckEventsOnly` query plus its
regenerated sqlc output, a rewritten `SendDigestIfDue` middle, and a trimmed
`digest_format.go`.
</objective>
