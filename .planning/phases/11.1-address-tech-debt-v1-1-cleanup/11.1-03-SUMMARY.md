# Phase 11.1 Plan 03: Detection Loss-Window Signal + PoolConfig Error Differentiation Summary

**Sharpened the detectDeluxeChanges doc comment, added a static `window` slog field proving the notification-loss window is now identifiable in logs, and split PoolConfig's two identically-worded parse errors into distinguishable messages.**

## Accomplishments
- D-10: `detectDeluxeChanges`'s doc comment now explicitly states the second, distinct consequence of an InsertEvent failure — every group after the failing one in `freshGroups` is skipped for the cycle but merely delayed (not lost), since its baseline was never advanced
- D-12: the existing insert-failure `Warn` call carries a new static `slog.String("window", "baseline_advanced_insert_failed")` field, and an automated test (`TestDetectMusicBrainz_DeluxeChange_InsertFailureLogsWindowSignal`) drives the real baseline-advanced/insert-failed path via a test-only `sqlc.Querier` decorator and asserts the field fires — confirmed red when the field was temporarily removed, green when restored
- D-11: `PoolConfig`'s second parse-failure message changed from the shared `"parse pool config for %s: %w"` to a distinct `"parse pool_max_conns override for %s: %w"`, with both sites still interpolating `redactedTarget(dsn)`; `TestPoolConfig_ParseErrorPathsAreDistinguishable` pins the differentiation, the no-password-in-error-text invariant, and the (empirically confirmed) unreachability of the second parse's own error path

## Decisions Made
- Confirmed empirically (via a throwaway probe program comparing `pgxpool.ParseConfig` and `pgx.ParseConfig` against several malformed `pool_max_conns` DSNs) that `dsnSetsMaxConns`'s own parse call cannot fail independently of `PoolConfig`'s first `pgxpool.ParseConfig` call — `pgx.ParseConfig` doesn't validate `pool_max_conns`'s value at all, it just retains it verbatim in `RuntimeParams`. This matches the plan's anticipated fallback exactly: the test drives the reachable first-parse-failure path live, and pins the second error-wrapping line's literal text plus its `redactedTarget(dsn)` usage by reading `pool.go`'s source directly (`os.ReadFile`), rather than asserting on an error path that cannot occur.
- Swapped the new `PoolConfig` test's distinctive password fixture from a high-entropy placeholder to the codebase's existing `local-test-fixture-password` marker (already used in `internal/db/migrate_test.go`) after gitleaks' `generic-api-key` rule flagged the first attempt on commit.
