## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 4 - Architectural, user-approved] Replaced the CSS-only D-13 fix with a hand-rolled Combobox component**
- **Found during:** Task 4 (human-verify checkpoint)
- **Issue:** The plan's specified fix — appending `[color-scheme:dark]` to `selectClassName` (commit `8844812`) — only affects computed styles. On Windows Chrome, the native `<select>` popup is rendered by the OS's own combobox control, which only themes the hover/selected row; every idle option stayed light-mode white background with near-white text, so the bug persisted in the real rendered UI despite correct computed CSS.
- **Fix:** Replaced both the Artist and Event type native `<select>` elements with a shared, hand-rolled `Combobox` component (button trigger with `role="combobox"` + `aria-expanded`/`aria-haspopup`, DOM-rendered `role="listbox"` panel styled with the app's own `bg-popover`/`text-popover-foreground` tokens) — not a Radix/shadcn import, preserving CONTEXT.md's no-component-library constraint. Accessible name resolution and the `onChange` contract (full new value, `null` not `0`/`""` on "All ...") are unchanged from the outside.
- **Files modified:** `web/app/components/history/HistoryFilters.tsx`, `web/app/components/history/HistoryFilters.test.tsx`
- **Verification:** Live browser session (Windows Chrome, Vite dev server) — screenshot confirmed legible option text in both dropdowns; direct functional test confirmed open -> select -> value updates -> panel closes correctly. `web/app/app.css` remained untouched and no files were added under `web/app/components/ui/`, preserving the plan's blast-radius and no-new-dependency constraints.
- **Committed in:** `8f206be`

**2. [Rule 1 - Bug] Fixed two `history.test.tsx` tests broken by the D-13 combobox rewrite**
- **Found during:** Post-checkpoint plan-level verification (`cd web && pnpm test`)
- **Issue:** `history.test.tsx`'s two filter-interaction tests still called `userEvent.selectOptions(screen.getByRole("combobox", ...), "new_release")`, which only works against a native `<select>`. After the D-13 rewrite, the Event type control is a button + DOM listbox, so both tests failed with `Value "new_release" not found in options`.
- **Fix:** Updated both tests to the click-trigger-then-click-option pattern already established in `HistoryFilters.test.tsx` (`userEvent.click` the trigger, then `userEvent.click` the `role="option"` element for "New release").
- **Files modified:** `web/app/routes/history.test.tsx`
- **Verification:** `cd web && pnpm test` — all 50 tests pass (was 46 before this fix's file changes, 48 failing before either fix in this entry or entry 3).
- **Committed in:** `179dfd8`

**3. [Rule 2 - Missing critical] Restored branch coverage above the 70% CICD-12 floor**
- **Found during:** Post-checkpoint plan-level verification (`cd web && pnpm test`)
- **Issue:** The Combobox rewrite added substantial new branching logic (click-outside handling, keyboard navigation for ArrowDown/ArrowUp/Enter/Space/Escape, both open and closed states) with no corresponding test coverage, dropping overall branch coverage to 66.08% — below the plan's own `<verification>` requirement ("Vitest's inline coverage thresholds... still pass; this plan only adds tests, so measured coverage must not drop").
- **Fix:** Added four tests to `HistoryFilters.test.tsx`: click-outside closes the dropdown, ArrowDown-while-closed opens and Enter commits the highlighted option, ArrowUp moves the highlight back up and Escape closes without changing the value (and returns focus to the trigger), and the `listWatchlist` rejection fallback (only "All artists" renders).
- **Files modified:** `web/app/components/history/HistoryFilters.test.tsx`
- **Verification:** `cd web && pnpm test` — branch coverage now 73.04% (up from 66.08%), all coverage categories above the 70% floor except pre-existing, out-of-scope gaps in unrelated files (`ReleaseToggles.tsx`, `SearchBox.tsx`, `watchlist.tsx`) that this plan did not touch and are not part of this plan's `files_modified`.
- **Committed in:** `179dfd8`
