    - The SAME test's post-`cancel()` block (currently lines 101-110) — a `select` over `done` and `time.After(shutdownTimeout + 5*time.Second)`. That block is already correct and is the exact idiom this fix converges the poll loop toward. It must stay unchanged.

  <action>
Replace the health-poll loop and its trailing `if lastErr != nil` block (currently lines 78-99) with a loop whose body is a `select` over three cases. Everything above line 78 and everything from `cancel()` (currently line 101) onward stays exactly as it is.

The replacement:
- A `deadline := time.After(10 * time.Second)` channel (replacing the `time.Now().Add(...)` wall-clock comparison) and a `ticker := time.NewTicker(50 * time.Millisecond)` with `defer ticker.Stop()`, preserving the existing 10s budget and 50ms poll cadence.
- Case 1 — `case runErr := <-done:` — `run()` returned before the server ever became healthy. `t.Fatalf` reporting `runErr` directly. This is the entire point of the fix: an early boot failure (bad DSN, migration failure, port already bound) now names its real cause instead of surfacing as a connection-refused timeout.
- Case 2 — `case <-deadline:` — `t.Fatal` stating the server never became healthy before the deadline.
- Case 3 — `case <-ticker.C:` — issue the `http.Get(healthURL)`; on a nil error and `http.StatusOK`, close the body and leave the loop. Close the response body on every iteration where the GET succeeded, including non-200 responses — the current code closes it unconditionally after a successful GET and that must not regress into a leak.

Break out of the loop with a labeled `break` (label the `for` statement, e.g. `pollHealthy:`, and use `break pollHealthy` from inside the `select`). A bare `break` inside a `select` only exits the `select`, not the enclosing `for` — that is the single most likely way to get this rewrite subtly wrong and produce an infinite loop. A `goto` to a label after the loop also works, but the labeled break is more idiomatic and avoids `goto`'s jump-over-declaration restrictions.

Remove the now-unused `lastErr` variable and, if `fmt` becomes unused as a result, remove it from the import block. Do not add a new import beyond what the rewrite needs.

Do not change the reserved-port logic, the `t.Setenv` calls, the goroutine, or the post-`cancel()` shutdown `select`.
