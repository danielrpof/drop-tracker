Finish `web/app/routes/system.tsx`.

Add a pure `deriveLoadedShape` function that takes the payload and returns which of the two
data-bearing shapes applies, computed during render from the freshest payload and never stored in
component state. The first-run predicate requires all three clauses on every source: a null last
run, an empty history, and a zero consecutive-skips count. The skips clause is load-bearing, not
defensive: a source whose every first cycle is overlap-skipped records no run row but does bump
that counter, and without the clause such an instance would show reassuring first-run copy while
every cycle is in fact failing to run — the exact failure this view exists to surface. Deriving
during render is what makes the buffer-reset transition work: a Refresh after a restart really
does return an empty buffer, and the view must be allowed to fall back to first-run rather than
holding stale panels.

Fill in the three branches of the render-precedence chain plan 19-01 established. The error branch
renders the `EmptyState` with its locked heading and body and a secondary Retry button bound to
the reload-token bump, and must not render the header Refresh control at all — Retry is the sole
recovery affordance until there is data to refresh. The loading branch renders a skeleton that
mirrors the loaded layout rather than a bare spinner: a header row with the Refresh control
present but disabled, an About-block card skeleton, and two source-panel card skeletons. The data
branch renders the About block, the freshness stamp, the empty-watchlist callout when applicable,
then either the first-run block or the source panels according to the derived shape.

The first-run block is an `EmptyState` with the locked heading and a body naming the humanized
poll interval, and no action button — the header Refresh already covers a manual re-check. When
the schema version is null the body instead names the database problem, because the promise that
results appear after the next cycle is false when a cycle cannot record; that payload still
loaded successfully and is not the error state.

Add the header row: the page heading on the left, the Refresh control and the freshness stamp on
the right. Adapt the busy-button pattern from the history route's "Load more" control — secondary
variant, a leading refresh icon when idle and a spinning loader icon when busy, the locked idle
and busy labels, disabled and reporting busy to assistive technology while in flight, at the same
width so nothing shifts.

Write `handleRefresh` as its own handler, not a reuse of the mount effect. It returns immediately
if a refresh is already in flight; it never clears the existing data and never falls back to the
skeleton, because this is a status dashboard an operator watches rather than a feed. On success it
replaces the data and sets the freshness stamp from the client clock at the moment the fetch
resolved — not from any payload field, since its whole job is to tell the operator how stale the
frozen times below it are. On a session-expiry rejection it returns without setting any state: the
shared client already flipped the auth store and the app shell has swapped to the passphrase
screen. On any other rejection it keeps the stale data, holds the stamp at the last success, and
raises the inline failure flag.

The handler must carry its own mounted guard, checked before every state write. The mount effect's
cleanup flag covers only the mount effect; a manual Refresh that resolves after the session expired
and the outlet remounted would otherwise write state on a dead component and leave a request in
flight behind the login screen — that is ROADMAP success criterion 5, not a warning to tolerate.

Render the inline failure line directly under the header row when that flag is set: the label type
token in the destructive color, the locked copy naming the last successful stamp, inside a polite
live region so it is announced without stealing focus. A failed initial load still goes to the full
error state, not to this line.

Fetching happens on mount, on a reload-token bump, and on a Refresh click — and nowhere else.
Register no interval timer, no page-visibility listener, and no window-focus listener anywhere;
