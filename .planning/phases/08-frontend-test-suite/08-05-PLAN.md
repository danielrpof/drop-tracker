Close the third and last folded todo: `guestFeatureHref` drops `event.external_id` straight into a URL

proof runs through the rendered anchor. The badge-fallback work is 08-04's and is not restated here.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MusicBrainz / Deezer -> `events.external_id` -> React client | A third-party-supplied string is stored verbatim and crosses into the client typed only as `string`; nothing between the upstream API and the anchor validates its character set |
| Rendered anchor -> user's browser | The user clicks whatever URL this string was interpolated into; a malformed path is indistinguishable from a correct one until it 404s or lands elsewhere |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-08-10 | Tampering | `guestFeatureHref` in `EventCard.tsx` | low | mitigate | Task 2 escapes `external_id` with `encodeURIComponent` at both interpolation sites, so an id containing `/`, `?` or `#` can no longer alter the path structure, append a query, or truncate the path at a fragment. This is RESEARCH.md's ASVS V5 item for this phase. Severity is low because today's upstreams emit UUIDs and numeric ids and the scheme+host are literals — but that is a property of the current data, not an enforced invariant, and Task 1's tests are the standing guard. |
| T-08-11 | Denial of Service | Over-broad fix escaping the whole URL | low | mitigate | Escaping the full template string rather than the id alone would percent-encode `:` and `/` and break every guest-feature link at once — a worse outcome than the bug. Task 1's third test pins an ordinary UUID id to its exact unchanged URL, and Task 2's acceptance criteria cap the call count at two, so an over-broad fix fails both. |
| T-08-12 | Elevation of Privilege | Anchor `href` scheme | low | accept | A `javascript:` or `data:` URL is not constructible here even unescaped: the scheme, host and leading path segment are literals in the template and the untrusted value can only land in a later path segment. The anchor also already carries `rel="noreferrer"` with `target="_blank"`. Accepted, no new mitigation. |
| T-08-08 | Repudiation | RED-then-GREEN pair collapsed into one commit | low | mitigate | Task 1's acceptance criteria require the RED commit to touch only the test file, to add lines only, and to be observed exiting non-zero; Task 2's require the RED-to-GREEN diff to touch only the component file. A collapsed pair cannot satisfy both. |
