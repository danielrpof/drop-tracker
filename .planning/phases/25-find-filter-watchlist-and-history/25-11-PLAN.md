<objective>
Close UAT gap G-25-4 (major). Clicking a card's chip label far down a 50+ artist Watchlist drops `window.scrollY` to 0.

Diagnosis (`.planning/debug/chip-click-scroll-reset.md`): nothing calls a scroll API, and `preventScrollReset` already works. The filter
collapses the list under the viewport. The document gets no taller than the window (body is `min-h-screen`), so the browser clamps
`scrollY` to `max(0, scrollHeight - innerHeight)`, which is 0. UI-SPEC D-12 treated `<ScrollRestoration />` as the only cause of a jump.

User decision (2026-10-11, binding): anchor the clicked card. After a chip-label filter, the clicked chip and card keep their on-screen
position, and the browser clamps it when the page is short. The UI-SPEC D-12 and UAT truth rewording is done in 25-14 (shared doc
files), not here.

Purpose: WLVW-04's chip click-to-filter (D-08) stops throwing the user's place away.
Output: `useScrollAnchor` hook, the chip label passing itself as the anchor, route wiring, and jsdom tests with stubbed layout.

Browser-level evidence: the repo has no browser test runner, and adding Playwright would add an npm package this milestone rules out
(the 25-10 blast-radius gate pins `web/package.json`). The jsdom tests stub `getBoundingClientRect` and spy on `window.scrollBy` to pin
the arithmetic. The real-browser check is a `human-check` (human_verify_mode: end-of-phase) that re-runs UAT test 4.

Create `web/app/lib/useScrollAnchor.ts` exporting `useScrollAnchor(key: string): (el: HTMLElement) => void`:
- Keep a ref holding `{ el, top } | null`.
- The returned `capture(el)` is a stable `useCallback` that stores the element and its current `getBoundingClientRect().top`.
- A `useLayoutEffect` with deps `[key]` reads the ref and clears it. It returns early when there is no anchor or `el.isConnected` is
  false. Otherwise it computes `delta = el.getBoundingClientRect().top - top` and calls `window.scrollBy(0, delta)` only when `delta !== 0`.
- Why a layout effect keyed on the filter key: the router commits the new search params in its own render, possibly after the
  sticky-clear render. The correction must wait for the commit that actually changes the filter, and it must run before paint so the
  user never sees the jump. Measuring the element's final position covers browser clamping and Chrome scroll anchoring alike, because
  only the remaining drift is corrected.
- One short comment (1-2 lines) stating intent and citing G-25-4.
