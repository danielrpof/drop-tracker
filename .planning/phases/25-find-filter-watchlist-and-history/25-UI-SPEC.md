`ComboboxChip`'s remove button ships with `opacity-50 hover:opacity-100` and has no accessible-name
hook. Phase 24 rejected the 50%-opacity × because it risks failing the 3:1 non-text contrast check
[R1, R8]. Make this change:

No other consumer uses `ComboboxChip` today (Phase 24 deliberately avoided it), so the edit is local.

### Tag filter combobox (3)

- **Container:** `ComboboxChips` (`min-h-9`, flex-wrap). Selected tags render as `ComboboxChip` with `className="h-6 max-w-full bg-secondary text-label font-normal text-secondary-foreground"`. The label is an inner `<span class="min-w-0 truncate" title={name}>`, and `removeLabel` is `Remove {tag} from tag filter`.
- **Overflow:** chips wrap and the container grows taller. It never clips and never shows a "+n" disclosure (ui-ux-pro-max "Chip Collection Reflow"; the selection is bounded by the vocabulary).
- **Chip order:** sorted by tag name (`Intl.Collator`, `sensitivity: "base"`), ties broken by id, independent of click order.
- **Popup options:** the union of `entries[].tags` (D-07), sorted the same way. Each `ComboboxItem` reads `{name}` with a trailing `<span class="ml-auto text-muted-foreground tabular-nums">{n}</span>`, where n is how many watched artists carry it. The built-in selected `CheckIcon` stays. Typing in the chips input narrows options with a case-insensitive *contains* match. There is no create option.
- **Input placeholder:** `All tags` while nothing is selected. Once one or more tags are selected it has no placeholder, and the chips speak for themselves.

## Interaction Contract

### Name filter (WLVW-01, D-04)

- **Match:** case-insensitive and accent-insensitive substring on `entry.name` only (NFD → strip `\p{M}` → lowercase → fold `$→s`, `ø→o`, `æ→ae`, `ß→ss` (G5) → `includes`, applied to both sides). `asap` matches `A$AP Rocky`. The disambiguation is not searched. `beyonce` matches `Beyoncé`, and `BAD` matches `Bad Bunny`.
- **Trim:** leading and trailing whitespace in the query is ignored, so a whitespace-only query matches everything.
- **Timing:** the list re-filters on **every keystroke with no debounce**. Filtering about 100 rows in memory is instant (SC5).
- **URL write:** the `q` param is written with `replace` (D-12), **trailing-debounced 300ms**. That matches `SearchBox`'s 300ms and stays under browsers' `history.replaceState` rate limits. The visible input value is local state that re-syncs from the URL on back/forward.
- **Clear ×:** renders only when the value is non-empty. Activating it empties the field and keeps focus in the input.
- **Esc** in the input clears a non-empty value. On an empty value it does nothing.
- **Input attributes:** `type="text"`, `enterKeyHint="search"`, `autoComplete="off"`, `spellCheck={false}`. Enter does nothing, because filtering is already live.

### Sort (WLVW-02, WLVW-03, D-02, D-15, D-16)

**One Select with six options** (D-01 discretion). A single control is one tab stop with one
announcement per change, and all six modes are visible at once.

| Option label | URL `sort=` | Order | Tie-break |
|--------------|-------------|-------|-----------|
| `Name (A–Z)` **default** | *(omitted)* | `Intl.Collator(undefined, { sensitivity: "base" })` ascending | artist id asc |
| `Name (Z–A)` | `name-desc` | collator descending | artist id asc |
| `Date added (newest)` | `added-desc` | watchlist row `created_at` desc | artist id asc |
| `Date added (oldest)` | `added-asc` | `created_at` asc | artist id asc |
| `Latest release (newest)` | `latest-desc` | raw `latest_release_date` text, lexicographic desc | artist id asc |
| `Latest release (oldest)` | `latest-asc` | raw text, lexicographic asc | artist id asc |

- **Missing values:** `null` latest release sorts **last in both directions** (WLVW-03). `next_release_date` never affects the sort (G3). Among themselves, those artists keep the id tie-break.
- **Stable tie-break:** it is always artist id **ascending**, in every direction, so equal-valued artists never swap places when the user flips direction (SC2).
- **Sort is not a filter:** it never counts as "filtered" and Clear filters never resets it (D-10).
- **URL write:** a change is written with `push`, and the default value removes the param.

### Tag filter (WLVW-04, D-05, D-06, D-07)

- **Semantics:** **any-of (OR).** An artist matches if it carries at least one selected tag. An empty selection means no tag constraint.
- **Selecting:** picking an option adds it as a chip. The popup **stays open**, the chips input is cleared, and focus stays in the input, so several tags can be picked in a row. Picking a selected option again deselects it (base-ui `multiple` default).
- **Removing:** a toolbar chip × or Backspace in an empty chips input removes the last chip. Focus stays in, or returns to, the chips input.
- **Esc** closes the popup. A second Esc does nothing.
- **Empty states inside the popup:**
  - When no watched artist carries any tag, the popup shows `ComboboxEmpty` with `No tags yet — add one with “+ tag” on any artist's card.` and nothing is selectable.
  - When the typed text matches no option, it shows `No tags match “{q}”`.
- **URL write:** `tags=` holds comma-separated ids in ascending order, and the param is removed when empty. Each add or remove is written with `push`.

### Preference toggles (WLVW-05, D-09)

- `Has muted events`: matches `muted_event_types.length > 0`.
- `Custom release types`: matches when `release_types`, compared **as a set**, differs from `{album, single, ep, deluxe}`.
- **Composition:** the toggles are independent. Each is a `Button` with `aria-pressed`, styled per the Color table. When both are on, an artist must satisfy both (AND, D-09).
- **Click behavior:** a click toggles the state, focus stays on the button, and the change is written with `push`. The URL carries `muted=1` / `custom=1`, and each param is absent when off.

### Card chip click-to-filter (D-08)

- **Toggle:** activating a chip label (click, Enter, or Space) toggles that tag in the **same** tag-filter state the toolbar combobox shows, so both surfaces always agree. Adding the tag to the filter shows its toolbar chip, and the card chip gains the Check icon and ring.
- **Focus:** focus stays on the chip's label button. A chip click is a filter change, so it also clears stickiness (G4).
- **× behavior:** the × behaves exactly as in Phase 24 and detaches the tag. It never changes the filter.

### Composition, count, and Clear filters (WLVW-06, D-10)

- **Order of operations:** visible list = `entries` → name filter → tag filter (OR within) → muted toggle → custom toggle (AND across all of these) → sort. N = visible length, and M = `entries.length`.
- **Sticky cards (G4):** an in-card edit (preference checkbox, chip ×, note) never removes its own card, even when the card stops matching. It stays visible with no cue until the next change to search text, sort, tag selection, a toggle, or Clear filters, a chip-click filter change, or a reload. Then the list re-filters. N counts **visible** cards, sticky ones included.
- **Tags that lose their last carrier:** an in-session chip detach **never prunes** the active tag filter. A tag whose last carrier lost it stays selected until the payload next reloads, and is pruned then (D-13).
- **Filtered-to-zero:** when N = 0 and M > 0, the `<ul>` is replaced by the filtered `EmptyState` with **one** action, `Clear filters` (`Button variant="default"`).
- **Clear filters** (toolbar or empty state):
  - It resets `q`, `tags`, `muted`, and `custom` in one `push` and **preserves `sort`**.
  - Focus moves to the name filter input.

### URL state (D-12, D-13)

| Route | Params (planner owns the final names per D-12; these are the recommended encoding) |
|-------|------------------------------------------------------------------------------------|
| `/` (Watchlist) | `q` (text), `sort` (`name-desc` / `added-desc` / `added-asc` / `latest-desc` / `latest-asc`; absent = name A–Z), `tags` (`3,7`), `muted=1`, `custom=1` |
| `/history` | `artist` (artist id), `type` (`new_release` / `guest_feature` / `deluxe_change`), `tag` (tag id) |

- **Write mode:** typing writes with `replace` (debounced, as above), and every discrete change (sort, tag add/remove, toggle, History control, Clear filters) writes with `push`. Back then undoes the last deliberate change, and reload reproduces the view.
- **Invalid params** are dropped silently and the URL is rewritten with `replace`. Invalid means an unknown sort value; a non-integer, zero, or negative id; a tag id absent from the payload-derived set (Watchlist), checked when the payload loads; or a tag id absent from `GET /tags` (History), checked once tags load. This never raises a toast or an error state.
- **Manage tags callbacks (D-13):**
  - `onDeleted(id)` removes `id` from `tags`.
  - `onMerged(source, target)` replaces `source` with `target`, de-duplicates, and re-sorts.
  - `onRenamed` needs no URL change, because names are read from the payload.
  - Each of these writes with `replace`.
- **Tab links:** the nav `NavLink`s (`/`, `/history`) stay param-free, so switching tabs starts the other tab from its own last URL in history, not a shared one. Watchlist and History filter state never cross-link (D-13).

### History Tag filter (HIST-02, D-11)

- **Options:** `All tags` first, then `GET /tags` sorted by name (collator, ties broken by id). This includes tags only removed artists carry. `GET /tags` is fetched once on History mount, alongside the existing `listWatchlist()` call in `HistoryFilters`.
- **While tags load:**
  - With no `tag` param, the trigger reads `All tags`.
  - With a `tag` param, it reads `Loading tags…` and the feed already shows filtered results, because the request carries `tag_id`.
- **If `GET /tags` fails:** the menu offers only `All tags`.
  - With no `tag` param, the trigger reads `All tags`.
  - With a `tag` param, it reads `Tag unavailable` and the server-side filter stays applied until the user picks `All tags`. A failed fetch is not proof the id is stale, so it is never dropped silently.
- **Selection** composes with Artist and Event type (AND). Changing it resets the accumulated pages and refetches page one, the same as the other two. `filters.tagId` joins the effect deps and the `listEvents` params.
- **Load more** carries the same `tag_id`. Retention is enforced server-side on every page (SC4), so the UI needs no retention logic of its own.

### Focus management

| Surface | Event | Focus goes to |
|---------|-------|---------------|
| Name filter | Clear × activated | stays in the input |
| Name filter | Esc clears the value | stays in the input |
| Tag filter | Option picked or deselected | stays in the chips input (popup open) |
| Tag filter | Toolbar chip × activated | the chips input |
| Toggle / Sort | Changed | stays on the control (Select returns focus to its trigger) |
| Card chip label | Toggled, card still visible | stays on that label button |
| Clear filters (either button) | Activated | the name filter input |
| History Tag control | Option committed | the Tag trigger (existing `Combobox<T>` behavior) |

### Live announcements

All announcements reuse the **one** existing route-level `role="status"` region on the Watchlist
(Phase 24 [R6]) through the existing `announce()` function. The visible count is plain text and is
**not** itself a live region, so it isn't re-read on every keystroke.

| Trigger | Timing | Message |
