Close G-25-11. Apply the user's 2026-10-12 decision on review WR-01 ("widen") so a run of adjacent leaving cards can't bring back
the G-25-4 collapse.

Gap (25-UAT.md G-25-11, verifier probe in 25-VERIFICATION.md): `anchorCandidates` returns only `[chip, next card, previous card]`.
Tag filtering is any-of (D-05), and the default name sort interleaves cards, so un-pressing a chip at `?tags=A,B` often removes the
clicked card and both of its neighbours. Then no candidate is connected and `scrollBy` never runs (probe: cards A1..E5, clicked C3, B2
and D4 leave too, A1 and E5 survive).

Locked decision (binding). Cite it as "user decision 2026-10-12 (G-25-11)": the fallback search widens to the nearest surviving
card. Claude's discretion (recorded): at each distance the next card is tried before the previous one. This keeps the existing
next-then-previous order (25-17, WR-02 2026-10-11) as the distance-1 special case, so the A1..E5 probe anchors on E5. There is no
distance cap, because a cap would bring back the collapse for a longer run.

25-CONTEXT.md stays unchanged even though the gap's `missing` list says "UI-SPEC/CONTEXT": no CONTEXT decision states the anchor's
fallback order (its D-12 covers URL params, D-08 the chip toggle, G4 sticky cards), so the UI-SPEC D-12 scroll bullet is the only
decision text that records the rule, and Task 2 rewrites it.

Purpose: the clicked card's neighbourhood stays put on screen for any run length. G-25-12 (plan 25-20) builds its focus target on this
same fallback card.
Output: the widened `anchorCandidates`, hook and route tests for the run case, and the D-12 bullet in 25-UI-SPEC rewritten to match.
</objective>
