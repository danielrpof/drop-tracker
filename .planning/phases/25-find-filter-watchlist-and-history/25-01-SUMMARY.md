# Phase 25 Plan 01: Latest and Next Release Dates Summary

**GET /watchlist now carries `latest_release_date` and `next_release_date` per entry, computed by two `LEFT JOIN LATERAL ... LIMIT 1` joins inside the single ListWatchlist statement, with Postgres deciding "upcoming" at each date's own precision against UTC today.**

## Accomplishments
- Both ListWatchlist and GetWatchlistEntry gained identical `latest`/`upcoming` lateral joins; sqlc regenerated `LatestReleaseDate`/`NextReleaseDate` as `*string` on both row types, so the `sqlc.ListWatchlistRow(row)` conversion still compiles.
- `watchlist.Entry` exposes the two fields as always-present nullable JSON keys; no retention setting was added (G1).
- Service-level tests pin past/upcoming split, mixed precision (`1999-06` over `1999-05-17` over `1999`; `2999` over `2999-12-25` over `3000-01`), non-release event types and NULL dates being ignored, 400-day-old events still counting, and the current UTC year / next year boundary.
