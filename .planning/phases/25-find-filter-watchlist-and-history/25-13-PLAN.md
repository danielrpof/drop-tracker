<objective>
Close UAT gap G-25-9 (minor). At 375px, searching for an artist shows only its first letter.

Diagnosis (`.planning/debug/search-input-squeezed-375.md`): the squeezed text is the artist name in the Deezer search-result row
(`SearchResultRow` in `SearchResultsColumns.tsx`), not the search input. The disabled `Search MusicBrainz to add` button is `shrink-0`
with no width cap (205px), and the name column is `flex-1 min-w-0` with a zero flex basis, so at 375px it gets 10px. At 640px (the `sm`
two-column grid) it gets 0px. Making the button shrinkable alone changes nothing (experiment B). Capping it does (experiment E: name
column 119px). The type span (line 178) also lacks `truncate`. This layout dates from Phase 6.

User direction (UAT report): truncate the MusicBrainz button so more of the artist name shows. This plan caps the button and truncates
its label, which is the user's ask, and keeps the full label as the accessible name. Discretion: the cap is 40% of the row and lifts at
`lg` (1024px+), where both columns have room for the full 205px label (the debug run measured a 167px name column at 1024px). Only the
Deezer button changes. `Add to Watchlist` is the primary action and wasn't reported, so it stays.

Purpose: the 375px search-and-add flow (surfaced in the WLVW-01 375px UAT pass) shows readable names.
Output: the capped, truncating button, the truncating type line, and class-level tests. A held-out visual check runs at 375, 640, and
1024px.

prettier-plugin-tailwindcss decides the class order. Stage only this plan's files (wave 1 runs in parallel). Comments are 1-3 lines.
Hooks stay on, and no AI attribution trailer.
