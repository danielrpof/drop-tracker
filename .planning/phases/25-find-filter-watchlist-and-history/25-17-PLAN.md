<objective>
Apply the user's WR-02 decision so the G-25-4 collapse doesn't come back when the clicked card itself leaves the filtered list.

Review finding (25-REVIEW WR-02): tag filtering is any-of (D-05). Un-pressing a chip while two or more tags are selected removes every
card that carries only that tag, including the clicked one. `useScrollAnchor` then sees a disconnected chip, skips the correction, and
the page collapses under the viewport, which is the original G-25-4 symptom. Plan 25-11 pinned that skip as intended. The user has now
overruled it.

Locked decision (binding). Cite it as "user decision 2026-10-11 (gap planning)": FALLBACK ANCHOR. `useScrollAnchor` captures several
candidates at click time: the chip, then the clicked card's next sibling card, then its previous sibling card (the list heading is
optional). It corrects using the first candidate still connected. Update the existing "card leaves the list: no call" test
(watchlist.test.tsx ~2182-2210) to expect a correction from the surviving neighbour, and add hook unit cases.

Discretion (recorded): the list heading is left out. It sits above the list, so filtering never moves it within the document, and a
correction based on it could only fight the browser clamp. Candidate selection happens inside the hook (`capture(el)` calls
`anchorCandidates(el)`), so the route and TagChips keep their current calls unchanged.

Purpose: WLVW-04's chip click-to-filter keeps the user's place even when the clicked card filters itself out.
Output: the fallback-capable hook, its unit cases, and two route cases.
