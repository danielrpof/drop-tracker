## Scope fence

This plan declares the `RunRecorder` seam, its no-op default, the recorder field and the
option. It does **not** call the recorder from `runCycle`, does not aggregate per-cycle
counters, and does not widen `EventRecorder` — all three are Phase 18.1, deliberately
split out so the riskiest change in the codebase is reviewed on its own. It also does not
touch `cmd/server/main.go`: the single shared store instance is constructed and wired to
both its consumers in plan 18-04, the plan that creates it.

## Locked decisions this plan implements

| Decision | Shape locked here |
|---|---|
| D-05 superseded | A skipped tick is a per-source scalar signal, not a run entry. |
| D-06 superseded | `Outcome` is a plain Go string over a three-value set; no SQL constraint exists to enforce it, so `RecordRun` closes the set itself. |
| D-07 superseded | `RecordRun` is a synchronous in-memory append. `ctx` stays in the signature for symmetry with `EventRecorder` and `Notifier` and is not load-bearing. |
| D-08 superseded | Ring buffer, cap `N = 50`, one mutex on the store. |
| D-09 | `Summary` is composed deterministically from the counts and the outcome enum, never from error text. |
| D-10 superseded | `RunResult` is a plain Go struct — no migration, no sqlc for run history. |

**Planner calls made under D-11's discretion grant, locked here:**

- **Package layering:** `RunResult`, `N` and `Store` live in `internal/pollruns`; `poller`
  declares only the interface and imports the package for the DTO (18-RESEARCH.md's
  recommendation, so `httpserver` never transitively depends on `robfig/cron`).
- **Ring shape:** bounded slice plus trim, not a head/count ring and not `container/ring`.
  Three lines, inspectable by eye; the sliding-offset reallocation is amortized and bounded
  at roughly `2N` values, which is irrelevant at a 15-minute cadence.
- **Mutex, not RWMutex:** the read path is one operator page view per refresh; an
  `RWMutex` would buy nothing and adds a second locking mode to reason about.
- **`Summary` is owned by `RecordRun`,** not by the caller. A caller-supplied value is
  discarded. This turns D-09 from a convention into a structural guarantee.
- **`NewStore` pre-seeds both known source keys** so a snapshot always carries
  `musicbrainz` and `deezer`, which is what lets plan 18-04's `/status` body have a stable
  shape on a fresh instance instead of a map that grows a key on first poll.
