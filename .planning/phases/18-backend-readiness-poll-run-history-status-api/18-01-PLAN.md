## Locked decisions this plan implements

| Decision | Shape locked here |
|---|---|
| D-01 | Ready iff `!dirty && applied >= expected`. Never equality. |
| D-02 | 503 `reason` vocabulary for a configured instance: `db_unreachable`, `schema_behind`, `schema_dirty`. |
| D-03 | 200 body `{"status":"ready","schema_applied":<int>,"schema_expected":<int>}`; 503 adds `"reason":"<enum>"` and may carry `"schema_applied":null`. |
| D-04 | Registered on the root router once, immediately after `/health`, outside the gate branch. |
| CONTEXT "NEW" | One `db.SchemaVersion` helper, shared with `/status` (plan 18-04). |

**Planner deviation, flagged:** a fourth `reason` value, `not_configured`, is emitted when
`WithReadiness` was not supplied. D-02's three-value vocabulary governs every reason a
*configured* instance can produce; `not_configured` exists solely so the route table is
byte-identical with and without the option, and a `cmd/server`-built binary can never
produce it (task 1 wires the option unconditionally). It is pinned by a test so the
distinction stays deliberate rather than accidental.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated client → `/ready` | An uptime monitor, an orchestrator probe, or any internet caller on a gated instance reaches this handler with no credential. |
| handler → Postgres | The handler issues one read on the process-wide pool; a connection failure produces an error value whose text embeds the DSN. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-18-01 | Information Disclosure | `handleReady` 503 path | medium | mitigate | Raw cause goes to `httplog.SetAttrs` under `ready_db_error` / `ready_schema_error`; the response struct has no error-derived field. Pinned by `TestReady_NoLeak` asserting the body carries neither the error text, a URL scheme separator, nor the word password. |
