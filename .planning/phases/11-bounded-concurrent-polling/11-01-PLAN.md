## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator environment → process config | `MUSICBRAINZ_POLL_WORKERS` / `DEEZER_POLL_WORKERS` are operator-supplied integers that directly size a goroutine pool |
| MusicBrainz API → worker closure | externally-supplied release-group slices are processed inside concurrent goroutines |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-01 | Denial of Service | `config.Load` / `poller.New` worker-pool sizing | medium | mitigate | `envDefault:"3"` / `envDefault:"5"` guarantee a bounded pool when the variables are unset; `Load` rejects `<= 0` with a named error (Task 1 step 1, Task 2); `New` independently rejects `<= 0` so a programmatic caller cannot bypass config validation. `caarlos0/env/v11` has no numeric-minimum tag, which is exactly why both guards are manual. |
| T-11-02 | Denial of Service (self-inflicted) | `RunMusicBrainzCycle` worker closure | medium | mitigate | Buffered-channel semaphore with no shared error or cancellation object; the x/sync group constructor that derives a cancellable context is prohibited (11-RESEARCH.md Pitfall 3) and grep-gated in Task 1's acceptance criteria. A worker's error is logged and swallowed inside the closure. |
| T-11-03 | Denial of Service | goroutine lifetime on context cancellation | medium | mitigate | Semaphore acquisition selects on `ctx.Done()`; the dispatch loop breaks rather than returning mid-flight, so `wg.Wait()` is always reached and no goroutine outlives the cycle method (Task 1 step 4). |
| T-11-04 | Information Disclosure | new `poll cycle complete` log line | low | accept | The line carries only `artist_count` and `duration_ms` — two integers derived from watchlist size and elapsed time, no artist identity, no credential, no DSN. Existing per-artist lines already carry `artist_mbid`/`artist_name` and are unchanged by this plan. |
| T-11-05 | Tampering | MusicBrainz release-group slices inside worker goroutines | low | accept | Each worker processes its own entry's own independent slice with no shared indexing; the existing range-only defensive convention (T-04-01, ASVS V5) is preserved verbatim because the closure body is a direct translation of the sequential loop body. |
| T-11-SC | Tampering | package-manager installs | low | accept | No package-manager install occurs in this plan. 11-RESEARCH.md's Package Legitimacy Audit records the phase adds no new external package; `golang.org/x/sync` is a first-party `golang.org/x/*` module already present in `go.sum` and is not imported by this plan. |
</threat_model>
