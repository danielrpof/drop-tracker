<objective>
Close PERF-04's lost-update race by replacing the deluxe-change baseline's check-then-act read/write with one atomic database statement, and re-derive the detection branching from that single statement's result without changing any observable detection outcome.

This is the phase's highest-correctness-risk work. The race is not a Go data race — both existing statements are individually safe — it is a logical lost update across two round trips, invisible to `go test -race` and only provable by asserting final stored state after a deliberate race.

Purpose: PERF-04, and ROADMAP criterion 4's requirement that a test race two artists sharing a release group and assert the final baseline is correct.
Output: `AdvanceGroupTrackCountBaseline`, `Detector.advanceGroupBaseline`, the re-derived `detectDeluxeChanges` branching, and the race test that proves the window is closed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| concurrent poller workers → shared `events.track_count` row | two workers polling different artists that credit the same release group now mutate one row concurrently |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-11-12 | Tampering (data integrity) | `events.track_count` deluxe-change baseline under concurrent callers | high | mitigate | The time-of-check-to-time-of-use window between the former read and write is closed by a single statement whose CTE takes a `FOR UPDATE` row lock, so a second caller racing the same `external_id` blocks and then re-evaluates against the committed value.
