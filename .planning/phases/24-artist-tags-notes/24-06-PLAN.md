<objective>
Add the global tag-management surface: a Manage tags dialog from the Watchlist header that lists the vocabulary with
watched-only counts and lets the user delete, rename, and — after an explicit confirmation — merge tags, with the cards
updating in place. The tracer is delete end to end (the smallest full path through dialog -> confirm -> API -> cards);
Task 2 adds rename; Task 3 adds the collision -> merge flow and the nested-dialog focus guarantees.

Purpose: TAG-05 and TAG-06 in the UI, plus the reusable ConfirmDialog Phase 26 will reuse (D-16).
Output: vendored `dialog` / `alert-dialog`, `ConfirmDialog.tsx`, `ManageTagsDialog.tsx`, `renameTag` / `mergeTag` / `deleteTag`,
`ApiError.body`, and the route's tag-wide card updaters.

Integration decision (flagged in PATTERNS.md): `apiFetch` today keeps only the `error` message of a non-2xx body. Task 2
adds an optional `body` field to `ApiError`, filled with the parsed JSON on any non-2xx, so `renameTag` can read the 409's
`target` and `carrier_count_after_merge` while every call still goes through the one `apiFetch` path.
</objective>
