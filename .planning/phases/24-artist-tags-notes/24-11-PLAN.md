Close the re-verification WARNING gap 2 (TAG-06, code review WR-06). `loadVocabulary` in `web/app/routes/watchlist.tsx` writes
its `listTags()` result unconditionally when the request settles. Suppose the "+ tag" vocabulary request is still in flight
when the user opens Manage tags and deletes a tag. The late response then overwrites the filtered vocabulary with a list
that still holds the deleted tag, and sets the status to `loaded`, so nothing refetches. Picking that suggestion silently
re-creates the tag. The same overwrite can also undo a rename or a merge. The fix is a generation ref: any fresher local
vocabulary change makes an in-flight response stale, and a stale response is dropped. A route test drives the exact race
with a deferred `listTags` promise.
