<objective>
Close the one open UAT gap, G-24-5. At a 375px viewport, the merge ConfirmDialog title `Merge “{32-char}” into “{32-char}”?`
overflows sideways (UAT test 5, "the text overflows sideways"). The diagnosed root cause: ConfirmDialog renders
`AlertDialogTitle` and `AlertDialogDescription` with no overflow-wrap rule. A 32-character tag name with no spaces is
one unbreakable token, wider than the roughly 272px of dialog content at 375px.

The fix follows the gap's `missing` list:
- `wrap-anywhere` on the title and description in ConfirmDialog, the shared component behind the merge and delete confirms (D-16).
- A unit test pinning the class on both elements.

The vendored `ui/alert-dialog.tsx` stays untouched.

`wrap-anywhere` is required, not just preferred. `AlertDialogHeader` is a `place-items-center` grid, so the title sizes to
fit-content, and fit-content can never go below the title's min-content width. Only `overflow-wrap: anywhere` counts its
break points toward min-content. With the `break-word` value, the heading would still size itself to the 32-character token and overflow.

The tracer pins the class in ConfirmDialog and drives the UAT scenario through ManageTagsDialog's real collision path,
with two 32-character names. Task 2 rebuilds the embedded SPA, proves the built CSS carries the rule, and runs the phase gate.

G-24-4 is resolved (a retest showed it is not a defect) and is out of scope.

Wave 1, with no dependencies: 24-01..24-12 are complete. Nothing here touches the backend, the route, or the vendored ui layer.

Purpose: the merge and delete confirms show both full tag names at any viewport width, so the user always sees what they are
confirming (D-09 "naming both tags").
Output: two `className` props in ConfirmDialog, one ConfirmDialog test, one ManageTagsDialog merge test, the refreshed
embedded bundle, and a green whole-phase gate.
</objective>
