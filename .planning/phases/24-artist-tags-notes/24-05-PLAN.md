<objective>
Let the user type a tag on a card, pick an existing one from autocomplete or create a new one, and see it as a chip.
The tracer is one pick end to end: `+ tag` -> combobox -> Enter -> pending chip -> POST /watchlist/{id}/tags -> confirmed chip.
Task 2 pins the suggestion rules in a pure, unit-tested helper; Task 3 adds the cap hint, counter, error mapping,
focus table, and announcements.

Purpose: TAG-01 (autocomplete + create on the fly), TAG-03 (no near-duplicates from the UI), and TAG-04's UI half.
Output: vendored `combobox` / `input-group` / `textarea`, `TagCombobox.tsx`, `lib/tags.ts`, `attachTag` / `listTags`, and the
route's lazily loaded vocabulary.

Deviation notes:
- UI-SPEC's vendoring command is `npx shadcn@latest add ...`; this plan runs the repo's pinned local CLI
  (`corepack pnpm --dir web exec shadcn add ...`, shadcn 4.16.2 from `web/package.json`) so no unpinned package is fetched.
- UI-SPEC says a pending chip's × is `disabled`. A natively disabled button cannot take focus, which breaks the same spec's
  "the pick that reaches 10 focuses the new chip's ×". The pending × therefore uses `aria-disabled="true"` with its click
  handler inert until the request settles — same "cannot remove before it exists" guarantee, still focusable.
</objective>
