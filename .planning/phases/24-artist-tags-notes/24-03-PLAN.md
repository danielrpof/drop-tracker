<objective>
Give each watchlist entry its plain-text note on the server: a dedicated PUT endpoint (D-25), an optional note on
POST so the SPA's Undo can restore it (D-27), and one shared projection so POST and PATCH answer with the same
`tags` + `note` shape GET does (D-26). The note PUT is the tracer; the POST/PATCH projection and the re-add
guarantees follow.

Purpose: NOTE-01 on the server, and D-26/D-27's accuracy guarantees that plans 24-04 and 24-07 rely on.
Output: `GetWatchlistEntry` / `UpdateWatchlistNote` queries, `NormalizeNote`, `Service.UpdateNote`, `PUT /watchlist/{id}/note`,
and POST/PATCH responses on the shared projection.

Context-drift note: CONTEXT.md's code-context line says `WatchlistEntry` gains "notes"; D-28 and the UI-SPEC data
contract fix the field as singular `note`. This plan uses `note` everywhere.
</objective>
