## Accomplishments

- `TestRunCycle_CounterInvariant` (`internal/poller/poller_test.go`, +134 lines): two sub-tests over a shared 20-entry synthetic table with `M`, `K`, `P`, `S`, `E` as named local constants.
  - **MusicBrainz leg:** `WithMusicBrainzWorkers(8)`, a `fakeReleaseGroupSource` whose hook switches on the MBID to return a sentinel error for `mbid-1..3` (K=3) and `panic` for `mbid-4..5` (P=2), succeeding for the rest; a `fakeEventRecorder` returning `E=2` events per success. Each of 1000 iterations builds a fresh `Poller` through `New(...)` with a fresh `fakeRunRecorder` capturing the `RunResult`, then asserts with `==`: `ArtistsChecked == 20`, `ArtistsErrored == 5`, `ArtistsChecked - ArtistsErrored == 15`, `EventsRecorded == 30`, `ArtistsSkipped == 0`, `Outcome == OutcomeOK`, and `RunMusicBrainzCycle` returned `nil` (a panicking artist is an errored artist, not a failed cycle).
  - **Deezer leg:** `WithDeezerWorkers(8)`, the same table with its last 4 entries carrying a nil `DeezerID`. Each iteration asserts `ArtistsSkipped == 4`, `ArtistsChecked == 16`, `ArtistsChecked + ArtistsSkipped == 20`, `Outcome == OutcomeOK`.
  - After each loop, asserts the overlap guard (`mbRunning` / `dzRunning`) reads `false`.
  - No inequality operator (`>=` / `<=`) anywhere in the test body — a shared-counter regression manifests as an occasional undercount an inequality would hide.
  - Passes under `-count=3` in ~0.5s per run.
