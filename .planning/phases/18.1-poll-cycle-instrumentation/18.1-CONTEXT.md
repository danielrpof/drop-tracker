# Phase 18.1: Poll-Cycle Instrumentation - Context

**Gathered:** 2026-09-09 (created by the design grilling that split Phase 18)
**Status:** Ready for planning — **after Phase 18 lands**

<domain>
## Phase Boundary

The one risky change v1.4 was split to isolate: make `runCycle` record a run
entry through the `RunRecorder` seam Phase 18 built, with counts that are
correct under the worker fan-out, without regressing `runCycle`'s
ctx-cancellation or per-worker panic isolation.

Deliverables:

1. **Widen `EventRecorder`** — `DetectMusicBrainz` / `DetectDeezer` return
   `(int, error)` (the count of events recorded that cycle). Threads through
   `internal/detection` + both `fetchAndRecord` closures + ~6 test call
   sites. Mechanical.
2. **`runCycle` counter aggregation** — a per-cycle result channel sized to
   the dispatched count; each worker emits exactly one result (success /
   errored / panicked / ctx-bailed); the parent folds single-threaded after
   `wg.Wait()`. **Channel fold, not shared ints / atomics** — `go test
   -race` is unavailable locally and absent from CI, so correctness is by
   construction.
3. **`RecordRun` call** — `defer`-registered after the CAS succeeds, so it
   fires on the `ok` / `error` / `cancelled` exit paths, **never** the
   pre-CAS skip return. Log-and-swallow the error exactly like
   `NotifyPending`. No `context.WithoutCancel` (the store append is
   synchronous).
4. **`RecordSkip` call** — at the `!running.CompareAndSwap` branch, before
   returning `ErrCycleInProgress`.
5. **Concurrency-correctness section** in the plan + a looped (~1000×)
   exact-equality invariant test with erroring *and* panicking fake artists.
   Required deliverable.

Requirements: RUN-01, RUN-02 (the `cancelled` run entry — the skip *signal*
is Phase 18), RUN-03.

**Not in this phase:** the `pollruns.Store`, the `RunRecorder` interface, the
`RunResult` struct, `/ready`, `/status`, app version — all Phase 18. The SPA
— Phase 19.

</domain>

<decisions>
## Implementation Decisions

The ROADMAP.md "Phase 18.1" → "Notes for the phase planner" block is the
primary brief. Load-bearing points:

- **D-14 (the reason for the split): channel fold, not atomics.** Each
  worker path emits exactly one value on a buffer sized to the dispatched
  count (no worker blocks on send); the fold is single-threaded. The
  `recover()` path (`poller.go:337`) must emit an **errored** result — a
  panicked artist is a failed artist — which means restructuring the worker
  body so the recover returns a value rather than acting only through a bare
  `defer`.

- **`artists_checked` = entries dispatched to a worker** (post
  `shouldDispatch`). MB dispatches every entry → `artists_skipped` always 0.
  Deezer skips nil-`deezer_id` entries before the semaphore → those are
  `artists_skipped`, never `artists_checked`. `checked + skipped + (errored
  overlap)` must reconcile against watchlist size for the operator.

- **`outcome` ∈ `{ok, error, cancelled}`** — no `partial`. A cycle that
  finished with some artists errored is `ok` with `artists_errored > 0`;
  Phase 19 derives a "degraded" label. `error` = cycle machinery failed
  (e.g. watchlist `List` errored — `poller.go:289`). `cancelled` = `cycleErr`
  is `context.Canceled` / `DeadlineExceeded`.

- **`duration_ms` / `finished_at`** measured at the existing "poll cycle
  complete" log point (after `wg.Wait()`, before `NotifyPending`) —
  consistent with the current log line; notifier delivery excluded.

- **`RecordRun` failure is logged and swallowed** — `logger.Error("record
  poll run failed", …)`, never returned. An observability write must never
  turn a green detection cycle red or wedge the overlap guard's
  `defer running.Store(false)`.

- **`RecordSkip`** bumps the store's per-source `consecutiveSkips` +
  `lastSkippedAt`; the next successful `RecordRun` resets `consecutiveSkips`
  to 0 (that reset can live in the store's `RecordRun`, not `runCycle`).

- **Minimal diff.** Do not restructure the semaphore/`select`-on-`ctx.Done()`
  dispatch, `wg.Wait()` reachability, or the double `ctx.Err()` check
  (`poller.go:293-377`). The only signature change is `fetchAndRecord`
  gaining an `(int, error)` return.

</decisions>

<code_context>
## Existing Code Insights

- The worker `recover()` currently only logs. It must also feed an errored
  result into the fold. Simplest: the goroutine body is
  `resultCh <- runOneArtist(...)` where `runOneArtist` has its own
  `defer/recover` returning an errored result value.
- `cycleErr` is already computed (context cancellation, two check points).
  The `outcome` switch keys off it: `Canceled`/`DeadlineExceeded` →
  `cancelled`, other non-nil → `error`, nil → `ok`.
- `p.runs` (the `RunRecorder`) is already a non-nil field with a no-op
  default after Phase 18 — `runCycle` calls it unconditionally, no nil check.
- The skipped path (`!running.CompareAndSwap`) returns *before* `cycleID` /
  `cycleStart` exist — `RecordSkip(source)` only needs the source string.

</code_context>

<specifics>
## Specific Ideas

- Invariant test: fake source, M artists, K return an error, P panic; assert
  every iteration `checked == M - skipped`, `errored == K + P`,
  `checked == errored + succeeded`; loop ~1000×.
- Also test: recorder returns an error → `runCycle` still returns `nil` and
  logs; a skipped tick → no run entry, `consecutiveSkips` incremented; a
  ctx-cancelled cycle → one entry, `outcome == "cancelled"`, recorded even
  though `ctx` is done.

</specifics>
