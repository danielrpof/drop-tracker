<objective>
Close bug #1 (History cards show no release date) and bug #2 (guest-feature cards show no album art) end-to-end: source a release date and a release-group MBID for each newly-detected guest feature from a new MusicBrainz recording lookup, store them on the event row through the existing write-once display-snapshot fields, and render a release date on both the guest-feature and deluxe-change History cards.

Purpose: `guest_feature` rows have carried neither `release_date` nor `cover_art_url` since Phase 4 because `RecordingsByArtist`'s browse response has no release linkage to source them from; `deluxe_change` rows have carried `release_date` since Phase 4 but never rendered it. Both gaps are user-visible on the History tab today.

Output: a new `internal/musicbrainz` lookup method with its `[ASSUMED]`-tagged response types, a widened `detection.RecordingSource`, guest-feature insert wiring, and date rendering on two `EventCard.tsx` bodies — all covered by httptest, real-Postgres, and React Testing Library tests.
