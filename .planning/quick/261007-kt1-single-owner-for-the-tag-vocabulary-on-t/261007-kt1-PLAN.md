<objective>
Give the web tag vocabulary one owner. Today the Watchlist route and ManageTagsDialog each keep their own copy of GET /tags. Each has its own stale-response counter, each applies rename/merge/delete to its own list, and four callbacks keep the two copies in sync by hand. That split caused WR-06, WR-08, 24-11 and 24-12, and it still contains a live bug: remembering a newly created tag does not supersede an in-flight GET /tags, so the stale response can drop the new tag.

Purpose: one module and one stale-response rule replace the two copies, and the remember bug is fixed by that same rule, not by a fifth patch.
Output: `web/app/lib/useTagVocabulary.tsx` (provider and hook) with its own test file. The route, ManageTagsDialog and TagChips move onto it, the embedded SPA is rebuilt, and Phase 25's plan text is pointed at the new seam.

Plan shape: no tracer. Two owners cannot be cut over halfway: a partial migration leaves three owners and breaks the existing cross-surface tests in between. So Task 1 builds the module, proven by its own tests and touching no consumer. Task 2 is the single cut-over, and it starts with a regression test that is red against the current route.

Row-rewrite placement (decided): the module emits one discriminated `onChange(change: TagChange)` callback, which the route registers. The route's single `applyTagChange` maps the module's exported pure `rewriteTags` over `entries`. Why this split:
- Rows are route state, and Phase 25 adds sticky ids and URL filter writes on these same events. The module must not reach into `entries`.
- The meaning of each change is defined once, next to the vocabulary semantics, and unit-tested without rendering the route.
- One callback replaces four props, which gives Phase 25-07 a single switch to hook.
</objective>

```ts
export type TagChange =
  | { kind: "renamed"; tag: TagRef }
  | { kind: "merged"; sourceId: number; target: TagSummary }
  | { kind: "deleted"; tagId: number }

export type VocabularyStatus = "idle" | "loading" | "loaded" | "error"

export interface TagVocabulary {
  vocabulary: TagSummary[] | null // sorted: name (localeCompare, sensitivity "base"), then id; null until a load lands
  status: VocabularyStatus
  ensureLoaded(): void // fetches only from idle/error (D-30)
  reload(): void // always fetches (Manage tags open, Retry)
  remember(tag: TagRef): void // the tag an attach returned
  rename(id: number, name: string): Promise<RenameTagResult>
  merge(sourceId: number, targetId: number): Promise<TagSummary>
  remove(id: number): Promise<{ carrier_count: number }>
}

export function TagVocabularyProvider(props: {
  onChange?: (change: TagChange) => void
  children: React.ReactNode
}): React.JSX.Element
export function useTagVocabulary(): TagVocabulary // outside a provider throws Error("useTagVocabulary must be used inside TagVocabularyProvider")
export function rewriteTags(tags: TagRef[], change: TagChange): TagRef[]
```

The one generation rule (it replaces both existing counters):
- `fetch()`: increment the generation, mark "a request for the current generation is in flight", set status `loading`, call `listTags()`.
  - A settle whose generation is no longer current is ignored entirely: no state change, and the in-flight flag is not touched.
  - A current settle clears the in-flight flag. On success it stores the sorted list with status `loaded`. On failure it sets status `error` and keeps any previous list.
- `supersede()`: increment the generation, then call `fetch()` if a current-generation request was in flight. Without the refetch, the surface would be stuck on loading after its response was dropped (WR-08).
- Every applied local change calls `supersede()` exactly once. That covers remember, rename, merge and delete.
- `ensureLoaded()` and the in-flight check read refs, never render-closure state.
