<objective>
Make the tag and note error contract single-sourced (Phase 24 architecture-review candidates 2 and 3):

1. The tags/watchlist domain services are the only validation point. HTTP handlers stop pre-normalizing tag names and notes and map domain errors through one table per handler file. The response body echoes the sentinel's own user-safe text, plus a new machine-readable `code`.
2. Limits come from one place. In Go that means exported constants that build the sentinel texts. In the SPA it is one `lib/limits.ts` module plus code-point counting helpers. The client then never rejects input the server accepts, and the SPA branches on `code`, never on message text.

Purpose: today the same rule is checked in 2-3 places with hand-retyped strings, and the client counts UTF-16 units while the server counts code points. Any drift is a user-visible bug.
Output: refactored Go handlers and services with a coded error envelope, a web limits module with code-point counting, updated tests, and a rebuilt embedded SPA.

Shape note: this is a quick task, split the way the orchestrator asked: Go contract, then web, then rebuild and gates. Task 1 fixes the wire contract (interface-first) that Task 2 consumes. It is a refactor of an existing, already-proven path, so a leading tracer slice would add no information.
</objective>
