# Phase quick-260824-23o Plan 01: Factor shared runCycle out of RunMusicBrainzCycle/RunDeezerCycle Summary

Consolidated the ~150-line bounded-fan-out-with-overlap-guard pattern duplicated between `RunMusicBrainzCycle` and `RunDeezerCycle` into one private `runCycle` method, parameterized over a CAS guard pointer, source name, worker count, and a `shouldDispatch`/`fetchAndRecord` closure pair.

## What Was Built

`internal/poller/poller.go` gained a new private method:

```go
func (p *Poller) runCycle(ctx context.Context, running *atomic.Bool, source string, workers int, shouldDispatch func(entry watchlist.Entry, logger *slog.Logger) bool, fetchAndRecord func(ctx context.Context, logger *slog.Logger, entry watchlist.Entry)) error
```

`runCycle` carries the CAS overlap guard, per-cycle `cycleID`/logger construction, `p.store.List(ctx)` call, the semaphore-bounded worker-pool dispatch loop (with cancellation handling and panic recovery), the post-`wg.Wait()` re-check, cycle-complete logging, and the inline `NotifyPending` call at the end -- exactly the logic both cycle methods previously duplicated byte-for-byte.

`RunMusicBrainzCycle` and `RunDeezerCycle` are now each reduced to building a local `shouldDispatch` closure (MusicBrainz: unconditional `true`; Deezer: the pre-existing nil-`DeezerID` skip, unchanged in behavior and log message) and a local `fetchAndRecord` closure (their respective fetch call, result log, and `EventRecorder` call), then delegating with `return p.runCycle(ctx, &p.mbRunning/&p.dzRunning, sourceMusicBrainz/sourceDeezer, p.mbWorkers/p.dzWorkers, shouldDispatch, fetchAndRecord)`.

Net effect: `internal/poller/poller.go` shrank from 551 to 504 lines. Neither public method declares its own `sem`, `wg`, `cycleErr`, `cycleID`, or per-cycle `logger` anymore -- confirmed by reading back through the file after Task 2.
