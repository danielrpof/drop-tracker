Extract the rate-limited HTTP request logic that `internal/musicbrainz/client.go` and `internal/deezer/client.go` each independently implement (`doRequest`'s timeout-wrap + `limiter.Wait` + cancel-on-error + cancel-on-close body wrapping, plus the `cancelReadCloser` type) into a new shared `internal/httpclient` package, then update both clients' `doRequest` to delegate to it.

Output: A new `internal/httpclient` package with its own test suite, plus both existing clients' `doRequest` shrunk to header-setting + a call into the shared helper. No public API changes anywhere; all pre-existing tests keep passing unchanged.

<planning_findings>
Verified during planning by reading both files directly -- the executor should act on these, not re-derive them:

- **The two `doRequest` methods are byte-identical in structure**, differing only in the error-message prefix (`"musicbrainz: ..."` vs `"deezer: ..."`) and in which header(s) they set afterward (`musicbrainz` sets `User-Agent` + `Accept`; `deezer` sets only `Accept`). Both: build a no-op `cancel := func() {}`; if `httpClient.Timeout > 0`, wrap `ctx` via `context.WithTimeout(ctx, httpClient.Timeout)` and keep the real cancel func (a zero `Timeout` means "unbounded" in `net/http`'s own convention -- wrapping it unconditionally would treat a zero duration as already-expired); reassign `req = req.WithContext(ctx)`; call `limiter.Wait(ctx)`, and on error call `cancel()` then return a wrapped error; otherwise call `httpClient.Do(req)`, and on error call `cancel()` then return a wrapped error; on success, wrap `resp.Body` in a `cancelReadCloser{ReadCloser: resp.Body, cancel: cancel}` so the derived timeout keeps bounding the caller's body read until `Close()` releases it, then return `resp, nil`.
- **`cancelReadCloser` is byte-identical in both files**: an unexported `io.ReadCloser`-embedding struct whose `Close()` calls the embedded `Close()` then the stored `cancel` func.
- **`clampLimit` is functionally identical in both files** (non-positive -> `defaultLimit`, above `maxLimit` -> `maxLimit`) but its constants are semantically independent: `musicbrainz`'s `maxLimit`/`defaultLimit` are MusicBrainz's own documented "limit" ceiling/default (`maxLimit` is also reused directly as `recordingPageSize`, `releasePageSize`, and `releaseGroupPageSize` in three other files in that package), and `deezer`'s are Deezer's own documented ceiling/default. Both happen to be `100`/`25` today by coincidence, not by a shared contract. **Decision: do not extract `clampLimit`** -- sharing it would wrongly couple two independently-documented external API limits for an 8-line function, and would require touching three additional MusicBrainz files that reference `maxLimit` directly for no behavioral benefit. `clampLimit` stays duplicated in each package, untouched by this plan.
- **No test file in either package references `doRequest`, `cancelReadCloser`, or `clampLimit` directly.** All four `musicbrainz` test files and both `deezer` test files are whitebox (`package musicbrainz` / `package deezer`, not `_test`-suffixed) and call these only indirectly through the package's exported methods -- confirmed by reading `search_test.go` in both packages. Two tests do reach into unexported `Client` fields directly (`c.baseURL`, `c.httpClient`) but never the removed helpers, so no test file needs editing.
- **`internal/discord/client.go` has no rate limiter and is explicitly out of scope** -- it already diverges from the musicbrainz/deezer shape deliberately (see its own package doc comment) and is not touched by this plan.
- Module path is `github.com/danielrpof/drop-tracker`; the new package's full import path is `github.com/danielrpof/drop-tracker/internal/httpclient`. `golang.org/x/time v0.15.0` (which provides `golang.org/x/time/rate`) is already a direct `go.mod` dependency -- no `go.mod` changes are needed.

  <behavior>
    - Success: given an unlimited limiter (`rate.NewLimiter(rate.Inf, 1)`) and an httptest.Server returning 200, `Do` returns a non-nil response with a nil error and a readable body.
    - Limiter-wait error: given a context that is already canceled before `Do` is called, `Do` returns a non-nil error wrapping `context.Canceled`, a nil response, and the underlying test server records zero received requests.
    - Timeout: given `httpClient.Timeout` set to a short positive duration (e.g. 200ms) and a handler that never responds within the test's lifetime, `Do` returns a non-nil error wrapping `context.DeadlineExceeded`, returning promptly rather than hanging.
    - Close cancels the derived context: given `httpClient.Timeout` positive and a successful response, a `RoundTripper` wrapper that captures the actual `*http.Request`'s `Context()` shows `Err() == nil` immediately after `Do` returns, and `Err() == context.Canceled` only after the returned response's `Body.Close()` is called.
  </behavior>
  <action>
Create `internal/httpclient/httpclient.go` with a package doc comment explaining this package's purpose (the shared rate-limited request seam extracted from `internal/musicbrainz` and `internal/deezer`'s formerly-duplicated `doRequest` helpers). Export `func Do(ctx context.Context, req *http.Request, limiter *rate.Limiter, httpClient *http.Client, component string) (*http.Response, error)` implementing exactly the logic recorded in `<planning_findings>` above: conditional timeout wrap, `req.WithContext`, `limiter.Wait`, `httpClient.Do`, and success-path body wrapping. On the limiter-wait failure, return `fmt.Errorf("%s: rate limiter wait: %w", component, err)`; on the `httpClient.Do` failure, return `fmt.Errorf("%s: do request: %w", component, err)` -- the `component` parameter lets each caller keep naming itself in wrapped errors exactly as it does today (`"musicbrainz: ..."`, `"deezer: ..."`) without this shared package hardcoding either name. Do not set any HTTP headers inside `Do` -- header construction stays each caller's responsibility, applied to `req` before it calls `Do` (`Request.WithContext`'s shallow copy shares the same `Header` map, so headers set beforehand survive). Add the unexported response-body wrapper type recorded in `<planning_findings>` (an `io.ReadCloser`-embedding struct whose `Close()` calls the embedded close then the stored cancel func) so the derived timeout keeps bounding the caller's body read until the caller closes it.

Write `internal/httpclient/httpclient_test.go` covering all four `<behavior>` cases as separate test functions, mirroring the existing style in `internal/musicbrainz/search_test.go` (`httptest.NewServer`, a `rate.NewLimiter(rate.Inf, 1)` helper for non-limiter-focused cases, `errors.Is` assertions, a mutex-guarded request counter for the zero-requests assertion).
