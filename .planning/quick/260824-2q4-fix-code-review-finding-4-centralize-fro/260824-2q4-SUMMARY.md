# Quick Task 260824-2q4: Centralize frontend source-identity business rule Summary

**Extracted the "only MusicBrainz results are addable" / "mbid vs deezer_id identity field" rule, previously duplicated across three call sites, into a single pure helper module `web/app/lib/sources.ts`.**

## Performance

- **Duration:** ~15 min
- **Tasks:** 2 completed
- **Files modified:** 3 (1 created, 2 modified)

## Accomplishments
- Created `web/app/lib/sources.ts` exporting `isAddableSource(sourceName)` and `identityField(sourceName)` as the single source of truth for both business rules.
- Wired `SearchResultsColumns.tsx`'s `alreadyWatching` cross-reference and `canAdd` flag to call the shared helper instead of inline `sourceName === "musicbrainz"` / `sourceName === "deezer"` comparisons.
- Wired `watchlist.tsx`'s `handleAddSearchResult` guard to call `isAddableSource` instead of its own inline comparison.
- Confirmed zero behavior change: all 56 existing frontend tests pass unchanged, `npm run typecheck` passes with zero errors, and a repo-wide grep confirms no duplicate inline comparison remains outside `sources.ts` and the unrelated `EventCard.tsx`.

## Files Created/Modified
- `web/app/lib/sources.ts` - New pure module: `isAddableSource(sourceName): boolean`, `identityField(sourceName): "mbid" | "deezer_id"`
- `web/app/components/watchlist/SearchResultsColumns.tsx` - `alreadyWatching` now computes `identityField(sourceName)` once and indexes `entry[field]`; `canAdd` now calls `isAddableSource(sourceName)`
- `web/app/routes/watchlist.tsx` - `handleAddSearchResult`'s guard now calls `isAddableSource(sourceName)` instead of `sourceName !== "musicbrainz"`
