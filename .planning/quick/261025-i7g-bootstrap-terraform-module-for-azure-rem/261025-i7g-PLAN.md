# Terraform bootstrap module (infra/bootstrap)

Remote-state storage + GitHub OIDC identity, applied once locally and never destroyed.
Source: ROADMAP Phase 999.1 slice (a); notes `2026-10-17-terraform-azure-ephemeral-deploy.md`.

## Constraints

- Region `eastus2` (policy allows only southcentralus, canadacentral, mexicocentral, eastus2, brazilsouth).
- Verified 2026-10-25: tenant allows app registrations; user is subscription Owner.
- Providers `Microsoft.Storage` and others may need `az provider register` first.
- Learning mode: Claude writes boilerplate; the user writes the core resources and predicts `terraform plan` output before each run.
- Commits on a feature branch (not main), per Definition of Done; no AI attribution.

## Division of labor

| File | Author | Concept taught |
|---|---|---|
| `versions.tf`, `providers.tf`, `variables.tf`, `outputs.tf`, `infra/.gitignore` | Claude | providers vs state, lock file |
| `main.tf` (resource group, storage account, container) | User | resources, references, plan output |
| `github_oidc.tf` (app, service principal, federated credential, role) | User, guided | OIDC, why no stored secrets |
| backend migration (`backend "azurerm"` + `init -migrate-state`) | User | state migration, bootstrap's own state |

## Tasks

1. **Scaffold (Claude):** boilerplate files above; `terraform fmt` + `validate`. Grill: providers vs state.
2. **State storage (User):** write `main.tf`; predict plan (resource count, which attributes are "known after apply"); apply.
3. **OIDC identity (User, guided):** write `github_oidc.tf`; predict plan; apply. Grill: why federated credentials beat secrets.
4. **Migrate state (User):** add backend block, `init -migrate-state`, confirm blob exists. Grill: what if bootstrap state is lost.
5. **Wrap-up:** README note, DoD gates for any non-infra files touched, commit on branch.

## Done when

- `terraform plan` on `infra/bootstrap` reports no changes after apply.
- State blob exists in the new storage container; local `terraform.tfstate` is not committed.
- Storage account has versioning enabled and public blob access disabled.
- Federated credential subject matches this repo.
