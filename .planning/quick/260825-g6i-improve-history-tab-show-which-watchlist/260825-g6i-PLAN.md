<objective>
Two independent, already-root-caused History-tab fixes, each landing as its own commit-able slice:

1. **Featured-artist gap.** `guest_feature` rows persist the recording's *primary credited* artist in `artist_name` (`displayArtistName(rec, entry.Name)`), so the History card never tells you which watchlisted artist actually triggered the event. Add a write-once `watched_artist_name` snapshot column populated at all four detection call sites with `entry.Name`, thread it through every layer, and surface it on the guest-feature card.

2. **Ordering bug.** `ListEvents` orders by `id DESC` (detection order). A newly-watched artist's seed-mode back-catalogue therefore lands with fresh ids on old releases and interleaves with genuinely new drops. Re-order by real release chronology (`release_date DESC NULLS LAST, id DESC`) and replace the single-`bigint` keyset cursor with a correct composite `(release_date, id)` cursor carried as one opaque token.

Purpose: make the History feed both attributable (whose watchlist entry is this?) and chronologically honest (what actually dropped most recently?).
Output: one migration pair, regenerated sqlc code, an `events.Cursor` codec, updated Go detection/service/HTTP layers, updated TS API client and EventCard, and updated tests at every layer.
</objective>

**Chosen cursor wire design (decided during planning — implement this, do not re-litigate):**

An **opaque single-value token**, not two raw query params. Rationale: the existing HTTP param (`cursor`), the response field (`next_cursor`), and the `history.tsx` `nextCursor` state all already treat the cursor as one atomic nullable value; two raw params would spread one invariant across two independently-nullable fields that a client could desynchronise. Encoding is base64url-no-padding over compact JSON `{"d":"<release_date or omitted>","i":<id>}`.

**Layer split (load-bearing):** the *typed domain value* crosses the domain boundary; only the *HTTP boundary* speaks the encoded string.

- `events.ListParams.Cursor` is `*events.Cursor` (typed)
- `events.Page.NextCursor` is `*events.Cursor` (typed)
- `events.EncodeCursor` / `events.DecodeCursor` live in `internal/events/cursor.go` but are **called from `internal/httpserver/events.go`**, matching how `events.MaxPageSize` is defined in `events` while the parse lives in `httpserver`
- `eventsResponse.NextCursor` is `*string` (the encoded token)

This keeps every existing Go test's `cursor = page.NextCursor` round-trip loop compiling untouched.
