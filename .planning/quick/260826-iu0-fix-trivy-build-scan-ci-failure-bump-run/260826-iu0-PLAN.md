<objective>
Clear the two HIGH-severity `libssl3`/`libcrypto3` findings (CVE-2026-14456) failing CI's `build-scan` Trivy gate, by patching the runtime stage's Alpine packages at build time from Alpine's live package index — without unpinning the base image.

Purpose: CI's `build-scan` job is red on main and blocking the pipeline. Trivy reports:

```
drop-tracker:scan (alpine 3.24.1)
Total: 2 (HIGH: 2, CRITICAL: 0)
libcrypto3 / libssl3  CVE-2026-14456  HIGH  fixed  installed 3.5.7-r0  fixed 3.5.8-r0
```

The obvious fix — repin `alpine:3.24` to a newer digest — is **not available**. This was already checked directly against the registry: `docker pull alpine:3.24` still resolves to the exact digest currently pinned (`sha256:28bd5fe8b56d1bd048e5babf5b10710ebe0bae67db86916198a6eec434943f8b`). The base image has not been rebuilt with the fix yet. However, `apk upgrade` inside that same image DOES pull `libssl3-3.5.8-r0` and `libcrypto3-3.5.8-r0` — the patched packages are already published in Alpine 3.24's repository index, they are simply not baked into the image layer.

That gap is the general case, not a one-off: a digest pin buys reproducibility by freezing a layer, and a frozen layer cannot receive security patches that the distro publishes afterwards. The durable fix is to let the build pull the current patched packages at build time while keeping the digest pin as the trust root.

Output: a one-line change to the runtime stage of `Dockerfile` (plus its explanatory comment), verified by a real local `docker build` and a real Trivy scan under CI's exact gate.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-IU0-01 | Tampering | Runtime-stage `apk upgrade` pulling from Alpine's live mirror | medium | accept | `apk` verifies every package's signature against the Alpine signing keys already present in `/etc/apk/keys` of the digest-pinned base layer, so the trust root remains the pinned image, not the mirror. A malicious mirror cannot serve an unsigned or resigned package. Accepted rationale: the alternative — knowingly shipping a fixed HIGH CVE because a frozen layer cannot be patched — is strictly worse, and this is the standard, documented Alpine container hardening pattern. |
| T-IU0-02 | Denial of Service | Image reproducibility / build determinism | low | accept | The exact package set is no longer identical across build dates. Accepted deliberately: the digest pins for all three stages are retained, so the *base* is still fixed; only security-patched package versions float forward.
