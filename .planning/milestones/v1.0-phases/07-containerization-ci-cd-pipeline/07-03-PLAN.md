> Every push is automatically linted, tested, and security-scanned, and every merge to main produces a versioned, non-root, single-image build published to a container registry — with the full stack (API, scheduler, notifier, embedded SPA) also runnable locally via docker-compose.

<objective>
Create the Full Pipeline workflow: source-level gates (vet, lint, test, gitleaks, PR-title) that must all pass before a job builds the multi-stage image and scans it with Trivy.

Purpose: this is the enforcement half of the phase. Plan 07-01 proved the image builds; plan 07-02 proved the repo lints clean. This plan makes those facts non-optional on every push, and adds the vulnerability gate that must be green before anything can ever be published. It deliberately stops short of pushing: on a pull request the image is built and scanned and thrown away (D-09), which is what makes plan 07-04's publish path safe to add on top.

Output: `.github/workflows/full-pipeline.yml`, and `.trivyignore` only if a real unfixable finding forces it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull-request author -> CI runner | PR-authored code executes on the runner; the token that job holds is the blast radius |
| third-party GitHub Action -> workflow execution | An action runs arbitrary code with the job's token; a re-pointed mutable tag is a silent code substitution |
| upstream base image / Go module -> built image | Transitive OS and language-level packages enter the artifact without review |
| source tree -> public repository | A committed secret in a public repo is disclosed the moment it is pushed |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-11 | Tampering | third-party GitHub Actions | high | mitigate | Every third-party `uses:` pinned to the 40-hex commit SHA from 07-RESEARCH.md's `git ls-remote`-verified table, re-verified against the live remote at implementation time (CICD-08); enforced by the TOTAL-equals-PINNED gate in every task's verify |
| T-07-12 | Elevation of Privilege | PR-triggered jobs | high | mitigate | Plain `pull_request` trigger only; workflow-level `permissions: contents: read`; `build-scan` re-declares `contents: read` at job level; the only job with any elevation is `pr-title`, scoped to `pull-requests: read`, which checks out nothing |
| T-07-13 | Tampering | vulnerable base image or transitive dependency | high | mitigate | Trivy `severity: CRITICAL,HIGH`, `exit-code: '1'` against the locally-loaded image, gated by `needs:` on all four source jobs so a finding blocks before anything can be published (D-07, D-09) |
| T-07-14 | Information Disclosure | committed secret reaching a public repo | high | mitigate | gitleaks-action v3 as its own required check on every push, with `fetch-depth: 0` so the full pushed commit range is scanned rather than the final diff |
