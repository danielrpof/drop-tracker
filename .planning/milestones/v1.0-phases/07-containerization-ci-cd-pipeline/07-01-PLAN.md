**Note (MVP_MODE):** the ROADMAP `**Goal:**` line for Phase 7 is not in `As a / I want to / so that` user-story form, so no story is invented here. The ROADMAP goal is carried verbatim:

> Every push is automatically linted, tested, and security-scanned, and every merge to main produces a versioned, non-root, single-image build published to a container registry — with the full stack (API, scheduler, notifier, embedded SPA) also runnable locally via docker-compose.

Run `/gsd mvp-phase 07` if a user-story-framed goal is wanted before execution.

<objective>
Make the whole application runnable as a single non-root container image, and make that image the local dev loop via `docker-compose up`.

Purpose: this is the phase's tracer slice. Everything downstream (CI build, Trivy scan, ghcr.io push, SBOM) builds on the exact same `Dockerfile`. Proving the image builds and serves real traffic end-to-end *before* any pipeline YAML exists means an architectural dead-end in the build (go:embed ordering, musl native deps, missing CA trust store, non-root file permissions) surfaces after one commit instead of after the whole pipeline is wired.

Output: `Dockerfile`, `.dockerignore`, and an `app:` service in `docker-compose.yml`.
</objective>

  </read_first>
  <files>Dockerfile, .dockerignore</files>
  <action>
    Create `.dockerignore` first, then `Dockerfile`, at the repo root.

    `.dockerignore` mirrors `.gitignore`'s section groupings adapted to build-context semantics, and MUST exclude at minimum: `.git/`, `.env`, `.env.*`, `node_modules/`, `web/node_modules/`, `web/build/`, `web/.react-router/`, `bin/`, `.planning/`, `.vscode/`, `.idea/`, `*.exe`, `*.test`, `coverage.out`, `coverage.html`, and `internal/webassets/build/client/`. Excluding the committed webassets tree is deliberate: the image builds the SPA itself per D-10's rationale, and excluding it makes a broken Node stage fail loudly at `go build` rather than silently embedding a stale committed tree. Do NOT exclude `web/` itself, `go.mod`, `go.sum`, or `internal/` — all are build inputs. Follow this repo's comment-heavy config convention (see `docker-compose.yml` lines 9-16 and `Makefile` lines 58-66): a `#` comment above each grouping explaining why, and specifically an explicit note above the `.env` lines that a secret must never enter a build context or an image layer.

    `Dockerfile` has exactly three stages:

    Stage 1, named `web-build`, `FROM node:26-alpine3.24`. Node 26 no longer bundles corepack, so install pnpm explicitly with `npm install -g pnpm@11.8.0` (that exact version is what this repo's `lockfileVersion: '9.0'` lock file is verified against) — do not use `corepack enable`. Set the working directory to the web source dir, copy `web/package.json`, `web/pnpm-lock.yaml` and `web/pnpm-workspace.yaml`, run `pnpm install --frozen-lockfile`, then copy the rest of `web/` and run `pnpm run build`. The build output lands at `web/build/client`. If a native optional dependency (esbuild, lightningcss) has no musl binary and the install or build fails on alpine, switch this throwaway build stage's base to `node:26-bookworm-slim` and keep everything else identical — D-01 constrains the final runtime stage only, and the stage layout is Claude's discretion per CONTEXT.md.

    Stage 2, named `go-build`, `FROM golang:1.26.5-alpine3.24` (matches `go.mod`'s `go 1.26` directive and the pinned local toolchain `go1.26.5`). Copy `go.mod` and `go.sum` first and run `go mod download` so the module layer caches independently of source changes. Then copy the rest of the repo. Then `rm -rf ./internal/webassets/build/client` and `mkdir -p ./internal/webassets/build` (mirroring the Makefile `web` target's own rm/mkdir, so no stale hashed asset filenames survive), and `COPY --from=web-build` the SPA output into `./internal/webassets/build/client`. This ordering is load-bearing: `//go:embed all:build/client` resolves at compile time, so the SPA files must exist before `go build`. Build with `CGO_ENABLED=0 GOOS=linux go build -trimpath -ldflags="-w -s" -o /out/server ./cmd/server` — `./cmd/server` is the same entrypoint the Makefile `build` target uses; do not invent a different one.

    Stage 3, `FROM alpine:3.24` (D-01). Install the CA trust store with `apk add --no-cache ca-certificates` — this is mandatory, not optional: the `CGO_ENABLED=0` binary reads the system certificate pool, and plain alpine ships none, so without it every outbound HTTPS call to MusicBrainz, Deezer and the Discord webhook fails the TLS handshake at runtime while `/health` still reports healthy. Never work around a certificate failure by disabling TLS verification. Create the user with the fixed numeric ids from D-02 using the busybox applets `addgroup -g 10001 app` and `adduser -D -u 10001 -G app app`. Copy the binary from `go-build` to `/usr/local/bin/server`. Set `USER 10001:10001`, `EXPOSE 8080`, and a `HEALTHCHECK --interval=10s --timeout=3s --start-period=15s --retries=3` whose CMD is the shell form `wget -qO- "http://127.0.0.1:${HTTP_PORT:-8080}/health" || exit 1` (D-03 — shell form so the container's shell expands `HTTP_PORT` at runtime; busybox wget exits non-zero on the handler's 503, which is exactly what makes container health track real database health). Entrypoint is the exec form `["/usr/local/bin/server"]`.

    No `ENV` or `ARG` instruction anywhere in this Dockerfile may carry a configuration value — `internal/config/config.go` documents the process environment as the single source of truth, and a baked value would both break that invariant and risk a secret in a committed layer.
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| repo working tree -> Docker build context | Untrusted-for-secrets: anything not excluded by `.dockerignore` becomes an image layer |
| container process -> host kernel | A compromised in-container process must not hold host-equivalent privileges |
| container process -> public internet (MusicBrainz, Deezer, Discord) | Outbound TLS; certificate validation is the only integrity control |
| host developer -> committed compose values | Anything written into `docker-compose.yml` is public in a public repo |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-01 | Information Disclosure | Docker build context / image layers | high | mitigate | `.dockerignore` excludes `.env`, `.env.*`, `.git/` and `.planning/`; no `ENV`/`ARG` in the Dockerfile carries a configuration value; asserted by the `^ENV ` count gate and the `.dockerignore` greps in Task 1 |
| T-07-02 | Elevation of Privilege | container runtime process | high | mitigate | Fixed non-root `USER 10001:10001` created with explicit `addgroup -g 10001` / `adduser -D -u 10001` (D-02); asserted by `docker exec dt-tracer id -u` = 10001 and the image config `User` field |
| T-07-03 | Tampering | outbound HTTPS to MusicBrainz / Deezer / Discord | high | mitigate | `apk add --no-cache ca-certificates` in the final stage so the `CGO_ENABLED=0` binary can validate chains; asserted by the `/etc/ssl/certs/ca-certificates.crt` existence check. Disabling TLS verification is explicitly forbidden as a workaround |
| T-07-04 | Tampering | base image drift | medium | mitigate | All three stages pin exact patch tags (`node:26-alpine3.24`, `golang:1.26.5-alpine3.24`, `alpine:3.24`) rather than floating `latest`, so a rebuild is reproducible and Trivy's verdict in 07-03 stays meaningful |
| T-07-05 | Information Disclosure | committed docker-compose values | medium | accept | The `drop_tracker:drop_tracker` DSN in D-12's override is a dev-only credential already present verbatim in the existing `postgres:` service block; it grants access only to a local throwaway container. Real secrets remain in the gitignored `.env` loaded via `env_file` |
| T-07-06 | Denial of Service | container health reporting | low | accept | HEALTHCHECK intervals (10s/3s/3 retries) are a local-dev signal only; no external monitor depends on them in this phase |
</threat_model>
