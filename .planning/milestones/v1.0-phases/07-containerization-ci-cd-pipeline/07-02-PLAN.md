<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer working tree -> git commit object | The pre-commit hook is the last point at which a secret or a lint regression can be stopped before it becomes history |
| pre-commit hook auto-fix -> committed code | `--fix` rewrites source; the rewrite must be visible to the developer, not applied invisibly |
| local lint config -> CI lint config | A version or config skew makes a locally-green commit fail CI (or worse, the reverse) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-07 | Tampering | golangci-lint pre-commit `--fix` pass | medium | accept | Upstream's `golangci-lint` hook id applies `--fix` by design; rewrites land in the working tree where the developer re-stages them, and the `git diff --exit-code` acceptance gate proves no silent rewrite occurred during verification. Documented in a `#` comment above the entry rather than suppressed |
| T-07-08 | Repudiation | lint suppression | medium | mitigate | Every `//nolint` introduced must name its linter and carry a same-line reason; narrowing `.golangci.yml`'s enabled set to reach green is forbidden and gated by the `default: standard` grep |
| T-07-09 | Tampering | pre-commit hook supply chain | medium | mitigate | Both hook repos pin an exact released tag (`v8.30.1`, `v2.12.2`); pre-commit builds the pinned source itself rather than pulling a floating binary |
| T-07-10 | Elevation of Privilege | local hook bypass (`--no-verify`) | low | accept | `--no-verify` is a git-level escape a local hook cannot close; the CI gitleaks job (CICD-02, plan 07-03) is the non-bypassable backstop, which is exactly why CICD-02 and CICD-10 are two enforcement points for the same tool |
</threat_model>
