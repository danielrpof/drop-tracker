# Phase 06 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (user-confirmed; preset locked below, **not yet run in-repo** — see Registry Safety note) |
| Preset | `bdKQpIA4` (template: `react-router`) |
| Init command | `pnpm dlx shadcn@latest init --preset bdKQpIA4 --template react-router` — run inside the new top-level frontend directory (e.g. `web/`) as the first implementation task; this repo is genuinely greenfield for frontend (no `package.json`, no `web/`/`frontend/`/`ui/` dir, confirmed via scan) |
| Component library | radix (shadcn's underlying primitive layer) |
| Icon library | lucide-react (shadcn's default icon set — ships with the preset) |
| Font | System UI sans-serif stack (Tailwind's default `font-sans`) — no custom font import, per D-13's "don't over-invest in UI craft" |
| Routing | React Router (locked by the user-selected `--template react-router` preset) — resolves CONTEXT.md's "routing library choice" discretion item: D-01's two tabs are implemented as two real routes (`/watchlist`, `/history`), styled as a tab bar |
| Data fetching | Plain `fetch` + component state (no TanStack Query) — CONTEXT.md defaults to manual refresh, no polling; a data-fetching library adds no value without background refetch/cache-invalidation needs |

**Why shadcn fits D-15's "no heavier component library" constraint:** shadcn is not an npm runtime dependency like Mantine/Chakra — its CLI copies owned Tailwind+Radix component source directly into the repo, which the project can edit/trim freely. This is consistent with D-15's intent (Tailwind utility classes, no framework lock-in) while saving real time on Tabs/Switch/Toast/Skeleton primitives this phase needs.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, checkbox/label inline padding |
| sm | 8px | Compact element spacing (badge padding, toggle row gaps) |
| md | 16px | Default element spacing (card padding, list row padding) |
| lg | 24px | Section padding (tab content top padding, card internal sections) |
| xl | 32px | Layout gaps (gap between search box and results, gap between watchlist rows and page edge) |
| 2xl | 48px | Major section breaks (gap between the search block and the watchlist list) |
| 3xl | 64px | Page-level spacing (top-level page margin on wide viewports) |

Exceptions:
- Icon-only interactive targets (remove button, toggle switches, load-more spinner) get a minimum 44px hit area even where the visible icon is smaller, for touch/click accessibility — the 44px itself is not on the 8-point scale but is layered as padding around an on-scale icon size.

## Typography

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px | 400 (regular) | 1.5 |
| Label | 14px | 400 (regular) | 1.5 |
| Heading | 20px | 600 (semibold) | 1.2 |
| Display | 28px | 600 (semibold) | 1.2 |

Usage mapping:
- Display (28/600) — page-level titles: "Watchlist", "History" tab headers
- Heading (20/600) — artist name in a watchlist row, event card title
- Body (16/400) — event card detail text, form inputs, button labels
- Label (14/400) — disambiguation text, event dates, filter chip text, empty/error state secondary copy

Exactly 2 weights (400/600) and 4 sizes declared — no third weight, no fifth size.

## Color

Three layered semantic systems exist in this phase — call this out explicitly so the checker and executor don't collapse them into one:

1. **Neutral surfaces (60/30)** — the dark theme background/card system.
2. **UI accent (10%, indigo)** — reserved strictly for navigation/actions, below.
3. **Event-type badge colors** — reused verbatim from Phase 5's Discord embed colors (D-08: "mirror the same story Discord notifications already tell"). These are a locked, pre-existing semantic system and are **never** used for buttons, nav, or focus rings — only for the small color chip/badge on each History event card and its matching emoji, exactly as Discord renders them.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#09090B` (Tailwind `zinc-950`, shadcn dark `--background`) | Page background |
| Secondary (30%) | `#18181B` / `#27272A` (Tailwind `zinc-900`/`zinc-800`, shadcn `--card`/`--secondary`) | Watchlist rows, event cards, tab bar surface |
| Accent (10%) | `#6366F1` (Tailwind `indigo-500`) — user-confirmed | Primary CTA buttons ("Add to Watchlist", "Load more"), active tab underline/indicator, focus rings on inputs and controls |
| Destructive | shadcn default `--destructive` (Tailwind `red-600`, `#DC2626`) | Remove-artist icon/hover state, PATCH/DELETE failure toast border |
| Event: new_release | `#57F287` (green, Discord D-01, reused verbatim) | Cover-art badge chip + 🆕 emoji on `new_release` event cards only |
| Event: guest_feature | `#FEE75C` (yellow, Discord D-01, reused verbatim) | Badge chip + 🎤 emoji on `guest_feature` event cards only |
| Event: deluxe_change | `#EB459E` (fuchsia, Discord D-01, reused verbatim) | Badge chip + 💿 emoji on `deluxe_change` event cards only |

Accent reserved for: primary buttons (Add to Watchlist, Load more, Undo), the active Watchlist/History tab indicator, and focus-visible rings. Never used for event-type badges, links inside body text, or decorative elements.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (search result) | "Add to Watchlist" |
| Primary CTA (feed pagination) | "Load more" |
| Empty state — Watchlist (heading) | "No artists yet" |
| Empty state — Watchlist (body) | "Search above to add one." (verbatim per CONTEXT.md D-16 example) |
| Empty state — History, no events at all (heading) | "No release activity yet" |
| Empty state — History, no events at all (body) | "Add an artist to your watchlist to start tracking new releases, features, and deluxe editions." |
| Empty state — History, filtered to zero results (heading) | "No matching events" |
| Empty state — History, filtered to zero results (body) | "Try a different artist or event type." |
| Empty state — search column, zero matches (per source) | "No matches for \"{query}\"" |
| Error — watchlist list fetch fails | "Couldn't load your watchlist." + Retry button |
| Error — history feed fetch fails | "Couldn't load release history." + Retry button |
| Error — one search source down (D-03 partial failure) | "MusicBrainz is unavailable right now — showing Deezer results only." (rendered inline in that column only; the other column stays fully populated) |
| Error — add-artist fails | "Couldn't add this artist. Try again in a moment." (toast) |
| Error — preference toggle PATCH fails | "Couldn't update preferences — try again." (toast; toggle visually reverts to its prior state, optimistic-update rollback) |
| Error — remove fails | "Couldn't remove {artist name} — it may already be gone." (toast; row re-fetched from server) |
| Destructive confirmation — Remove artist | No blocking confirmation dialog. DELETE fires instantly on click; toast reads "Removed {artist name} from your watchlist." with an "Undo" action, auto-dismissing after 5s. Undo re-adds the artist via `POST /watchlist` with default preferences — **known limitation, document for the user**: Undo does not restore the artist's prior custom release-type/mute preferences, only re-adds with defaults, since the DELETE is a real hard delete (D-10) and preferences aren't cached client-side across the toast window. |
| "Already watching" state (search result) | "Already watching" (disabled button label, no action — D-11's client-side prevention; the 409 from `POST /watchlist` is a defensive backstop never surfaced as user-facing copy) |

## UI Considerations

Applicable state considerations resolved: 20 covered, 5 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | Watchlist list (list-collection) | ✅ covered | Renders the locked "No artists yet — search above to add one" copy (Copywriting Contract row) |
| empty | History feed (list-collection) | ✅ covered | Renders "No release activity yet…" (global) or "No matching events…" (filtered) per Copywriting Contract |
| empty | Search result columns (list-collection) | ✅ covered | Each source column independently renders "No matches for \"{query}\"" — a zero-result column stays visible with its label, never collapses (preserves D-09's side-by-side layout even at zero) |
| loading | Watchlist list (list-collection) | 🧪 backstop | Skeleton row placeholders (3 rows) render while `GET /watchlist` is in flight |
| loading | History feed (list-collection, media) | 🧪 backstop | Skeleton cards (hero-art block + text bars) render on initial load and on "Load more" append |
| loading | Search results (list-collection) | 🧪 backstop | Debounced search-as-you-type shows a small inline spinner in the search box while a request is in flight; no skeleton needed given the fixed 10-result-per-source cap |
| loading | Preference toggle (interactive-control) | ✅ covered | Toggle enters a brief disabled/dimmed state between click and `PATCH` response (optimistic UI, matches D-12's "changes immediately") |
| loading | Load-more control (interactive-control) | ✅ covered | Button label replaced by an inline spinner while the next page fetches; disabled during fetch to prevent duplicate requests |
| error | Watchlist list (list-collection) | ✅ covered | "Couldn't load your watchlist." + Retry button replaces the list area |
| error | History feed (list-collection) | ✅ covered | "Couldn't load release history." + Retry button |
| error | Search results (list-collection) | ✅ covered | Per-source partial-failure banner mirrors `GET /search`'s `sourceResult.Status: "error"` contract (D-03) — one source's failure never blocks the other column |
| error | Preference toggle (interactive-control) | ✅ covered | PATCH failure reverts the toggle and shows the toast in Copywriting Contract |
| error | Add-artist action (interactive-control) | ✅ covered | Generic failure toast; the preventable 409 case is blocked client-side before it can occur (D-11) |
| error | Remove action (interactive-control) | ✅ covered | DELETE failure (e.g. entry already gone) shows the toast in Copywriting Contract and re-fetches the row's true state |
| populated | Watchlist list (list-collection) | ✅ covered | Each row: artist image/avatar, name, disambiguation (if present), release-type checkboxes, mute checkboxes, remove control (D-12) |
| populated | History feed (list-collection, media) | ✅ covered | Type-specific cards per D-08: `new_release` (cover art + release type + date), `guest_feature` (recording title + link), `deluxe_change` (track-count delta, e.g. "12 → 18 tracks") |
| partial | Watchlist row (list-collection) | ✅ covered | `image_url` null → fallback placeholder avatar (generic music-note icon, per D-14's "graceful fallback for null art"); `disambiguation` null → field omitted entirely, no empty parentheses artifact |
| partial | History event card (list-collection, media) | ✅ covered | `cover_art_url` null → same fallback placeholder; `release_date` null → "Release date unknown" label instead of a blank; `previous_track_count` null on a `deluxe_change` row (defensive only, D-04 should always populate it) → render current `track_count` alone with no delta arrow |
| overflow | Search result columns (list-collection) | ✅ covered | Fixed 10-result cap per source (existing `searchResultLimit` API contract) — no client pagination; column scrolls internally if content exceeds viewport height |
| overflow | History feed (list-collection) | ✅ covered | Infinite scroll / "Load more" per D-07, bounded page size of 24 events per fetch |
| overflow | Watchlist row artist name (list-collection) | 🧪 backstop | Long names truncate with ellipsis within the row's fixed-width name column; full name available via a title/hover tooltip |
| zero-one-many | Watchlist list (list-collection) | ✅ covered | 0 → empty state; 1 → single row, no pluralization copy involved; many → list scrolls, no virtualization needed at expected single-operator scale |
| zero-one-many | History feed (list-collection) | ✅ covered | 0 → empty state; 1 → single card; many → infinite scroll per D-07 |
| long-text | Event card title / recording title (static-content) | 🧪 backstop | Titles beyond ~2 lines truncate with ellipsis inside the card; full title available via hover tooltip |
| long-text | Search result disambiguation (static-content) | ✅ covered | Truncates to one line within the result row's fixed width |

Note: the Watchlist/History tab nav (nav element) was evaluated against loading/error/overflow/long-text and dismissed for all four — it is a static two-route control with fixed, short, non-user-generated labels ("Watchlist", "History") that cannot overflow and has no async load or failure mode of its own.
