<objective>
Close gap G-02-2b: `Service.UpdatePreferences` reads the current row with a plain unlocked
`SELECT` and then writes it back with a separate `UPDATE`, as two non-transactional statements.
Two failure modes follow. If the row is deleted between the two, the `UPDATE`'s `pgx.ErrNoRows`
is wrapped as a plain error that never satisfies `errors.Is(err, ErrNotFound)`, so the handler
answers 500 where it should answer 404. And because both axes are read once and written back in
full, two concurrent PATCH calls touching different axes each write back the other's pre-update
value for the axis they never intended to touch — whichever lands second silently reverts the
first. The developer's UAT disposition on test 2 was "fix both WRs".

Purpose: this is the last mutation path in the phase that is not honest under concurrency —
`DELETE` already is, via `:execrows` (T-02-15). Phase 4's detection engine will write to
`watchlist`-adjacent tables on a poll schedule while a user is editing preferences through the UI,
so "two writers touching one row" stops being hypothetical the moment Phase 4 ships.

Output: `UpdateWatchlistPreferences` rewritten as a single data-modifying CTE that resolves each
axis under its own row lock and returns the artist-joined row, a one-round-trip
`UpdatePreferences` that maps a zero-row result to `ErrNotFound`, and four tests — two
deterministic held-lock tests at the service layer, two end-to-end concurrency tests at the
handler layer.
</objective>

**Query (`queries/watchlist.sql`).** Replace the `UpdateWatchlistPreferences` body with a single
data-modifying CTE. The update sets each axis from a `CASE` whose `WHEN` tests an explicit boolean
parameter and whose `ELSE` names the column itself; the outer `SELECT` joins `artists` and aliases
every column exactly the way `ListWatchlist` does, so the generated row struct carries both `id`
and `artist_id` rather than collapsing them:

```sql
WITH updated AS (
    UPDATE watchlist
    SET release_types = CASE
            WHEN @set_release_types::boolean THEN @release_types::text[]
            ELSE release_types
        END,
        muted_event_types = CASE
            WHEN @set_muted_event_types::boolean THEN @muted_event_types::text[]
            ELSE muted_event_types
        END,
        updated_at = now()
    WHERE id = @id
    RETURNING id, artist_id, release_types, muted_event_types, created_at, updated_at
)
SELECT u.id AS id, a.id AS artist_id, a.mbid, a.name, a.deezer_id,
       a.disambiguation, a.image_url,
       u.release_types, u.muted_event_types, u.created_at, u.updated_at
FROM updated u
JOIN artists a ON a.id = u.artist_id;
```

List the `RETURNING` columns explicitly rather than using `*`, so sqlc resolves the CTE's output
types without depending on star-expansion inside a data-modifying CTE. If `sqlc generate` still
cannot infer the two `CASE` result types, wrap each whole expression in a redundant cast —
`(CASE ... END)::text[]` — and note that in the summary; do not fall back to a second statement.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → `handleUpdateWatchlist` | Untrusted preference arrays and an attacker-controlled `{id}` path segment |
| concurrent client → concurrent client | Two requests mutating one watchlist row with no coordination between them — the boundary this plan exists to make safe |
| `internal/watchlist` → Postgres | Preference arrays cross into CHECK-constrained columns; the row lock taken by the update is the serialisation point |
