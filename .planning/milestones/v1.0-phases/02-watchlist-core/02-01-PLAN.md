<objective>
Prove the entire watchlist stack end-to-end with the thinnest real path: a client POSTs
`{"mbid": ..., "name": ...}` to `/watchlist`, a row lands in Postgres, and the created entry
comes back as JSON with its D-08 default preferences.

**Phase goal (ROADMAP.md, verbatim):** "Users can fully manage their watchlist — add, remove,
list, and configure per-artist alert preferences — through a tested API service layer."

Purpose: this phase introduces the first domain schema, the first service package, and a
breaking change to `httpserver.New`. Proving one path through every one of those layers on a
fresh context window means an architectural dead end surfaces after one commit rather than
after four. Every later plan in this phase expands outward from the slice this plan lands.

Output: a migrated `artists` + `watchlist` schema, regenerated sqlc code including a `Querier`
interface, an `internal/watchlist` package exposing the full `Store` contract, a
`POST /watchlist` handler, and a widened `httpserver.New` with all eight call sites updated in
the same commit.

```go
// internal/watchlist/service.go
package watchlist

type Entry struct {
	ID              int64     `json:"id"`
	ArtistID        int64     `json:"artist_id"`
	MBID            string    `json:"mbid"`
	Name            string    `json:"name"`
	DeezerID        *string   `json:"deezer_id"`
	Disambiguation  *string   `json:"disambiguation"`
	ImageURL        *string   `json:"image_url"`
	ReleaseTypes    []string  `json:"release_types"`
	MutedEventTypes []string  `json:"muted_event_types"`
	CreatedAt       time.Time `json:"created_at"`
	UpdatedAt       time.Time `json:"updated_at"`
}

type AddParams struct {
	MBID            string
	Name            string
	DeezerID        *string
	Disambiguation  *string
	ImageURL        *string
	ReleaseTypes    []string // nil means "apply the D-08 defaults"
	MutedEventTypes []string // nil means "apply the D-08 defaults"
}

type PreferencesParams struct {
	ReleaseTypes    *[]string // nil means "leave this axis untouched"
	MutedEventTypes *[]string // nil means "leave this axis untouched"
}

type Store interface {
	Add(ctx context.Context, p AddParams) (Entry, error)
	List(ctx context.Context) ([]Entry, error)
	UpdatePreferences(ctx context.Context, id int64, p PreferencesParams) (Entry, error)
	Remove(ctx context.Context, id int64) error
}
```

**Schema (`internal/db/migrations/000002_watchlist.up.sql`).** Copy the DDL verbatim from

NULL`, `disambiguation TEXT`, `image_url TEXT`, `created_at`/`updated_at TIMESTAMPTZ NOT NULL
DEFAULT now()`) and `watchlist` (`id BIGSERIAL PRIMARY KEY`, `artist_id BIGINT NOT NULL
REFERENCES artists(id) ON DELETE CASCADE`, `release_types TEXT[] NOT NULL DEFAULT
ARRAY['album','single','ep','deluxe']::text[]`, `muted_event_types TEXT[] NOT NULL DEFAULT
'{}'::text[]`, timestamps, plus the three named constraints `watchlist_artist_id_key`,
`watchlist_release_types_valid` and `watchlist_muted_event_types_valid`). Use `TEXT[]` with
`CHECK (col <@ ARRAY[...]::text[])`, never a native Postgres enum — Pitfall 1 explains why.

`album/single/ep/deluxe` and `new_release/guest_feature/deluxe_change` are this phase's working

deterministic edge probe could not classify WLST-02 into any of its eight edge categories, so
no acceptance criterion was auto-derived for it and it is recorded here rather than silently
dropped. The concrete open question it maps onto: **how strictly should `mbid` be validated?**

This plan validates only that `mbid` is non-blank after trimming. It deliberately does NOT
enforce UUID syntax, even though every real MusicBrainz MBID is a UUID, because Phase 3 is what
actually produces MBIDs from search results and no source artifact locks the format. Plan 02-02
adds a 36-character length cap as a denial-of-service bound (T-02-05), which is a length
constraint, not a format constraint.

Consequence if the assumption is wrong: a client can persist a syntactically invalid `mbid`,
and Phase 3's poller will query MusicBrainz for it forever and get nothing back. Surface this
to the developer during phase verification; the fix, if wanted, is a `uuid.Parse`-equivalent
check in `handleAddWatchlist` plus a `CHECK (mbid ~* '^[0-9a-f-]{36}$')` constraint — both
additive, neither requiring a schema rewrite.
</flagged_assumptions>
