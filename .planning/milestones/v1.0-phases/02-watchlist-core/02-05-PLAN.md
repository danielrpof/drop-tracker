<objective>
Close gap G-02-2a: `UpsertArtist`'s `ON CONFLICT (mbid) DO UPDATE` clause refreshes `name` and
`deezer_id` but omits `disambiguation` and `image_url` entirely, so every re-add after the first
insert silently discards those two caller-supplied values — and the `Entry` echoed back in the
response carries the stale ones. The developer's UAT disposition on test 2 was "fix both WRs",
so this is a fast-follow correctness fix, not an accepted risk.

Purpose: Phase 3 (MusicBrainz/Deezer clients) and Phase 6 (the React UI) will both legitimately
re-submit refreshed artist metadata for an mbid that already exists. Landing this before either
phase starts writing to `artists` means neither has to work around a table that quietly refuses
half its own updates.

Output: A widened `ON CONFLICT` SET list, its regenerated sqlc output, and two real-Postgres
tests pinning both halves of the `COALESCE` semantics — a supplied value refreshes, an omitted
value preserves.
</objective>

**Query (`queries/artists.sql`).** Extend the `ON CONFLICT (mbid) DO UPDATE` SET list to:

- `name = EXCLUDED.name` — unchanged. `name` is `NOT NULL` and required on every add (D-04), so
  there is no "omitted" case to guard and no reason to wrap it.
- `deezer_id = COALESCE(EXCLUDED.deezer_id, artists.deezer_id)` — unchanged.
- `disambiguation = COALESCE(EXCLUDED.disambiguation, artists.disambiguation)` — new.
- `image_url = COALESCE(EXCLUDED.image_url, artists.image_url)` — new.
- `updated_at = now()` — unchanged.

Keep `RETURNING *`. The two new lines deliberately mirror `deezer_id`'s existing treatment rather
than assigning `EXCLUDED` unconditionally: these are the three nullable metadata columns, and for
all three "the caller did not send this field" must mean "leave what is stored alone", never
"blank it". Task 2 pins that half of the behaviour.

Update the query's leading comment to record why the SET list is exhaustive: a column absent from
it is a column the table silently refuses to ever update again, and because `Service.Add` builds
the response `Entry` from this query's returned row, the caller is handed back the stale value
with a 201 as though the write succeeded. That combination — accepted, discarded, and echoed back
wrong — is what made WR-01 worth a fast-follow rather than a v2 note.

**Regenerate.** Run `make sqlc` (which enforces the pinned `v1.31.1` via `sqlc-version-check`
before generating) and commit the regenerated `internal/db/sqlc/artists.sql.go` in the same commit
as the `.sql` edit — the two must never be committed apart, which is exactly what `make
sqlc-check` gates.

**Do not touch** `internal/watchlist/service.go`, `internal/httpserver/watchlist.go`, or `go.mod`.
`AddParams` already carries `Disambiguation` and `ImageURL` all the way through to
`UpsertArtistParams`; the values were reaching the query and being dropped by it. No Go plumbing
is missing and no new module is needed — the entire production change is five lines of SQL plus
its codegen.
