<objective>
Prove and complete the two operator-facing behaviours the tracer established: `/health`
tells the truth in both directions, and every response carries a correlation id an operator
can use to find that request's log lines.

Purpose: OPS-01 is only half satisfied by a passing health check — the degraded path is the
one that matters during an incident, and it is the path least likely to be exercised by
accident. OPS-02 is unobservable to an operator until the id that appears in the log also
appears on the response they are holding.

Output: an `X-Request-Id` response header, and the `internal/httpserver` test suite covering
both health branches, concurrency, id distinctness, and DSN redaction.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → HTTP API | Unauthenticated clients reach `GET /health` and now also receive an `X-Request-Id` header. Only the fixed two-field JSON body plus that id may cross back. |
| process → logs | Every served request writes structured log lines. The DSN and any pgx error embedding it must not cross into that sink. |
| client → correlation id | An inbound `X-Request-Id` supplied by a caller is propagated by chi into logs. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-02 | Information Disclosure | `internal/httpserver/health.go` response body | medium | mitigate | `TestHealth_Down` asserts the 503 body contains neither the underlying error text, nor `postgres://`, nor `password`. The fixed `{status, db}` shape (D-03) is the control. |
| T-01-01 | Information Disclosure | structured log sink | medium | mitigate | `TestNoDSNInLogs` asserts the captured JSON log output for a served request contains neither the DSN `user:password` pair nor the `postgres://` scheme prefix. |
| T-01-03 | Denial of Service | `internal/httpserver/health.go` | medium | mitigate | `TestHealth_Concurrent` exercises 20 simultaneous polls race-clean against the single shared pool; `TestHealth_DownOnTimeout` proves the 3s Ping bound converts a hung database into a fast 503 rather than a held goroutine. |
| T-01-06 | Spoofing | inbound `X-Request-Id` header | low | accept | chi propagates a caller-supplied `X-Request-Id` into logs, so a caller can choose their own correlation id and could collide with another caller's. Accepted: the id is a debugging correlation aid on a single-operator deployment, is never used for authorization, authentication, or as a database key, and `/health` carries no per-caller state to confuse. Revisit if a correlation id is ever persisted or trusted for access control. |
| T-01-07 | Repudiation | structured log sink | low | accept | A caller-supplied id means a log line's correlation id is not proof of origin. Accepted at ASVS L1: PROJECT.md scopes v1 to a single operator with no auth surface and no audit requirement; logs are operational, not evidentiary. |
</threat_model>
