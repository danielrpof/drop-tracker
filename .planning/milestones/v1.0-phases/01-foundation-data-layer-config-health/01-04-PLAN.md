<objective>
Wire sqlc end to end — configuration, a real query source, committed generated output, a
test that executes the generated code against Postgres, and the drift check that keeps the
three in sync — and put the phase's recurring commands behind `make` targets.

Purpose: D-02 is explicit that sqlc is wired now rather than retrofitted in Phase 2, and that
the drift check lands now rather than being invented alongside the CI pipeline in Phase 7.
RESEARCH.md's Pitfall 4 is the reason: `sqlc generate` is a manual step with no build-time
enforcement, so committed generated code silently diverges from its SQL source until
something checks.

Output: `sqlc.yaml`, `queries/health.sql`, the committed `internal/db/sqlc` package, an
integration test executing the generated query, and a `Makefile` whose `sqlc-check` target
Phase 7's CI job invokes verbatim.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SQL source → generated Go | `queries/*.sql` and `internal/db/migrations/*.sql` are compiled by sqlc into Go that ships in the binary. Drift between source and committed output means the shipped code is not the reviewed code. |
| sqlc CLI → build | A developer-tool binary installed outside `go.mod` participates in producing shipped source. |
| process → Postgres | The generated queries execute over the same DSN-carrying pool as the rest of the service. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-12 | Tampering | committed `internal/db/sqlc/` versus `queries/*.sql` | medium | mitigate | `make sqlc-check` regenerates and fails on any working-tree difference, so reviewed SQL and shipped Go cannot diverge. Proven by the acceptance criterion that edits a query without regenerating and asserts a non-zero exit. Phase 7's CI job (CICD-01) runs the same target on every push. |
| T-01-13 | Tampering | `sqlc` CLI supply chain | medium | mitigate | The CLI is pinned to v1.31.1, whose release was verified directly against the GitHub Releases API in RESEARCH.md's Package Legitimacy Audit (verdict OK, no `[SUS]`/`[ASSUMED]`/`[SLOP]`). The task precondition asserts `sqlc version` reports that exact tag before generation. It stays out of `go.mod` because it is a build-time tool, not a runtime dependency of the shipped binary. |
| T-01-14 | Information Disclosure | `Makefile` recipes | low | mitigate | No recipe hardcodes a DSN into a build or run command; `run` takes `DATABASE_URL` from the environment and the integration DSN is an overridable variable defaulting to the throwaway compose credentials. Asserted by a negative source check on the recipe lines. |
| T-01-15 | Injection (Tampering) | generated query surface | low | accept | sqlc emits parameterised queries and the only query in this phase takes no parameters, so there is no string-concatenated SQL surface to attack. Accepted for this phase; Phase 2 introduces the first parameterised domain queries and inherits sqlc's parameterisation by construction. SQL injection is canon OWASP territory covered by `/gsd-secure-phase` — recorded here as a trust-boundary note, not minted as a project-specific prohibition. |
</threat_model>
