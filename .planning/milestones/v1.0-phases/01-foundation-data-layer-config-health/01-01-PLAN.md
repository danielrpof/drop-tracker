## Phase Goal

**Goal (verbatim from ROADMAP.md Phase 1):** The service boots reliably from environment
configuration, persists to a migrated Postgres schema, and reports its own health — the
foundation every later phase is built on.

> **MVP_MODE note — surfaced, not invented.** `MVP_MODE=true` asks the planner to frame this
> goal as an "As a / I want to / so that" user story sourced from the ROADMAP `**Goal:**` line.
> That line is not in user-story format, and the planner does not invent one. Run
> `/gsd mvp-phase 01` if you want the ROADMAP goal rewritten as a user story; the plans below
> are unaffected either way.

<objective>
Stand up the walking skeleton: one Go binary that reads its configuration from the
environment, builds a structured logger, connects to Postgres, applies its embedded
migrations, and serves `GET /health` reporting real database connectivity — proven
end-to-end against a real Postgres before any other plan in this phase runs.

Purpose: this is the tracer slice. Every later plan in Phase 1 and every phase after it
builds on the package layout, the wiring order, and the seams established here. Proving the
whole path works now means an architectural dead end costs one commit instead of ten.

Output: a buildable Go module with a single `cmd/server` entrypoint, `internal/{config,
logging,db,httpserver,testutil}` packages, an embedded no-op initial migration, a local
Postgres compose service, and an integration test that boots the real stack and asserts the
`/health` contract.
</objective>

`internal/db/pool.go` — export `NewPool(ctx context.Context, dsn string) (*pgxpool.Pool, error)`.
`pgxpool.New` is lazy and returns a usable pool even when Postgres is unreachable
(RESEARCH.md Pitfall 2), so follow construction with an eager `Ping` under a
`context.WithTimeout` of 5 seconds and close the pool before returning any error. When
wrapping a connection failure, wrap a redacted description — the host and database name
parsed from the DSN — and never the DSN itself, because pgx connection errors and the DSN
both carry the password (Pitfall 3).

`internal/db/migrate.go` — per RESEARCH.md Pattern 3. Declare `//go:embed migrations/*.sql`
over an `embed.FS`, build the source with `iofs.New(fs, "migrations")`, and export
`RunMigrations(ctx context.Context, dsn string, logger *slog.Logger, opts ...RetryOption) error`
together with an exported `RetryOption` type. Implement the full bounded retry loop now:
6 attempts, 500ms base delay doubling to an 8s cap, `select` on `time.After` versus
`ctx.Done()`, returning a wrapped error after the final attempt. Treat
`errors.Is(err, migrate.ErrNoChange)` as success — without this every restart after the
first fails (Pitfall 1). Log each failed attempt at Warn with the attempt number and delay,
never with the DSN. Plan 05 makes the three retry constants injectable through
`RetryOption` and adds the behavioural tests; the variadic signature exists now so that
refactor does not touch this file's call site.

`internal/db/migrations/000001_init.up.sql` and `000001_init.down.sql` — the up file is a
comment stating that Phase 1 creates no domain tables (D-01 assigns the watchlist schema to
Phase 2) followed by the single statement `SELECT 1;`; the down file mirrors it. This
resolves RESEARCH.md assumption A2 on a hard technical constraint rather than a preference:
Go's embed directive fails to compile when its pattern matches zero files, so an empty
migrations directory cannot build. One no-op migration satisfies D-01 (no domain tables) and
proves the embed to iofs to `schema_migrations` pipeline works end-to-end.

`internal/httpserver/server.go` — declare `type Pinger interface { Ping(ctx context.Context) error }`
(`*pgxpool.Pool` satisfies it) and export `New(db Pinger, logger *slog.Logger) *Server` plus
`func (s *Server) Router() http.Handler`. Defining the seam now means plan 02 tests the
database-down branch without a live database and without changing this signature. Build the
chi router with the middleware order from RESEARCH.md Pattern 2: `middleware.RequestID`
first so the correlation ID exists in context, then `httplog.RequestLogger(logger, ...)`,
then `middleware.Recoverer`. Register `GET /health`.

`internal/httpserver/health.go` — per RESEARCH.md Pattern 4. Response struct with json tags
`status` and `db`. Derive a `context.WithTimeout(r.Context(), 3*time.Second)` and call
`Ping` on it; the bound is mandatory because a hung network path to Postgres would otherwise
hang the health request itself and accumulate blocked goroutines under a monitor polling
every few seconds. On success write 200 with status `ok` and db `up`; on any Ping error
write 503 with status `degraded` and db `down` (D-03/D-04). The response body carries only
those two fields — attach the underlying error to the request's log entry via
`httplog.LogEntrySetField`, never to the response, so database host and credential detail
cannot cross the client boundary. Set `Content-Type: application/json` before writing the
status code.

`cmd/server/main.go` — keep `main()` thin: call `run() error`, and on a non-nil return print
the error to stderr and `os.Exit(1)`. `run()` sequences exactly as PATTERNS.md's wiring

then `db.NewPool(...)`, then `httpserver.New(pool, logger)`, then `http.ListenAndServe` on

before listening returns an error and the process exits non-zero — the service never reaches
a running-but-broken state.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment → process | Operator-supplied environment variables (`DATABASE_URL`, `HTTP_PORT`, `LOG_LEVEL`, `LOG_FORMAT`) cross into the process at boot. Malformed or empty values must fail the boot; the DSN credential must never cross back out into logs. |
| client → HTTP API | Unauthenticated network clients reach `GET /health`. Only the fixed two-field JSON body may cross back. |
| process → Postgres | The DSN, which embeds the password, crosses here. Connection errors returned across this boundary frequently embed the DSN. |
