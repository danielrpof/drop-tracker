<objective>
Turn the two fetch paths into the scheduled polling CLNT-01 and CLNT-02 actually require: two
independent `robfig/cron` jobs running on `Config.PollInterval`, each iterating the live watchlist
sequentially through its own rate limiter, each guarded against overlapping ticks, each logging one
structured line per artist and writing nothing (D-04).

This is the phase's second architectural axis — the search tracer proved the client and handler
layers, this plan proves the scheduler layer and the shutdown ordering that goes with it. Phase 4
replaces the log statement with real diff logic against the "seen" store and inherits the overlap
guard (DTCT-05) rather than retrofitting it.

Purpose: complete CLNT-01 and CLNT-02, and de-risk cron plumbing, rate-limiting-under-real-schedule
behaviour and graceful shutdown before the diff engine is built on top.
Output: `internal/poller`, and a `cmd/server/main.go` that starts and drains it.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cron scheduler → poll cycle | an unattended, self-triggering execution path with no human in the loop and no inbound request to bound it |
| Postgres `watchlist`/`artists` → poll cycle | stored, user-supplied artist identifiers (`mbid`, nullable `deezer_id`) drive outbound requests |
| poll cycle → musicbrainz.org / api.deezer.com | outbound volume now scales with watchlist size, on a schedule, forever |
| process shutdown → in-flight cycle | a cycle mid-request races the database pool being closed |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Denial of Service | overlapping cron ticks per source | high | mitigate | A cycle that runs longer than `PollInterval` would otherwise have a second cycle start on top of it, compounding goroutines and doubling outbound rate every tick. Per-source `atomic.Bool` `CompareAndSwap` guard skips the tick and logs a warning; released via `defer` so an error return or a panic cannot wedge the source. Asserted by a blocked-cycle test and by grep gates on the CAS/defer pair. |
| T-03-17 | Denial of Service | outbound rate as watchlist size grows | high | mitigate | Cycles iterate sequentially with no worker pool, semaphore or goroutine, and every request passes through the one process-wide limiter per source that `/search` also shares. Watchlist growth therefore lengthens a cycle rather than raising instantaneous rate. Asserted by an in-flight counter that must never exceed 1 and by a grep gate proving no concurrency primitive is used in the cycle path. |
| T-03-18 | Tampering | stored `deezer_id` reaching URL construction | medium | mitigate | Nil `deezer_id` is skipped in Go before any call (D-06); a non-nil value is rejected when empty and `url.PathEscape`d by `deezer.ArtistAlbums` (plan 03-02, T-03-10). The poller never builds a URL itself. |
| T-03-19 | Denial of Service / Repudiation | shutdown ordering | medium | mitigate | `pollr.Stop` is deferred *after* `defer pool.Close()` so LIFO ordering drains the cycle first, and the drain is bounded by `pollDrainTimeout` so a hung upstream cannot make the process unkillable. Without the drain, a cycle mid-request sees a closed pool and produces an error that looks like data corruption rather than a shutdown race (Pitfall 4). |
| T-03-20 | Information Disclosure | poll-cycle log lines | medium | mitigate | The poller logs artist identity, source, item count, cycle id and error strings — never a DSN, never a config value, never an upstream response body. Upstream errors reaching the log are already status-only strings (plans 03-01/03-02/03-03 never include response bodies in error text). |
| T-03-21 | Repudiation | silently skipped artists | low | mitigate | Every skip (nil `deezer_id`) and every per-artist failure emits its own structured log record with the artist's identity, so a poll cycle that quietly covered fewer artists than the watchlist holds is visible rather than inferred. |
| T-03-SC | Tampering | `go get github.com/robfig/cron/v3` module install | high | mitigate | 03-RESEARCH.md's Package Legitimacy Audit verified `github.com/robfig/cron/v3` against the authoritative Go module proxy (`go list -m -versions` → `v3.0.1`); verdict OK / Approved, de facto standard Go cron library already locked in CLAUDE.md, no `[ASSUMED]`/`[SUS]`/`[SLOP]` entries — so no blocking human legitimacy checkpoint is required. Version pinned in `go.mod`, checksum-pinned in `go.sum`. |
