## The `GET /search` contract (established here, extended by 03-02)

```
GET /search?q=<query>

200 OK
{
  "query": "drake",
  "sources": {
    "musicbrainz": {
      "status": "ok",
      "artists": [
        { "source": "musicbrainz",
          "id": "9fff2f8a-21e6-47de-a2b8-7f449929d43f",
          "name": "Drake",
          "disambiguation": "Canadian rapper",
          "type": "Person",
          "image_url": null }
      ]
    }
  }
}

200 OK  (degraded source, D-03)
{ "query": "drake",
  "sources": { "musicbrainz": { "status": "error", "error": "source unavailable", "artists": [] } } }

400 Bad Request  { "error": "q is required" }    // empty or whitespace-only q
400 Bad Request  { "error": "q is too long" }    // more than 512 runes
```

`sources` is a map keyed by source name, so plan 03-02 adds `"deezer"` as a new key with zero
change to the envelope. `status` is `ok` or `error`. `error` is the fixed operator-authored string
`source unavailable` and is never raw upstream text. `artists` is always present and never `null`.
