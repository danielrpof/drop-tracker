<user_story>
**As a** drop-tracker operator, **I want to** be told when an artist I watch turns up as a guest
on someone else's track, **so that** I do not miss features that never appear in their own
discography.
</user_story>

<objective>
Deliver the guest-feature slice end-to-end: the MusicBrainz poll cycle browses every recording
the watched artist is credited on, keeps only the ones where they are not the primary credit,
and records each as a `guest_feature` event in the same seen store.

Purpose: DTCT-03 is the one detection type with no existing fetch path — this slice adds the
recording browse and the positional credit rule together, so the new client method never exists
without a consumer.
Output: `internal/musicbrainz/recordings.go`, the `detection.RecordingSource` seam, guest-feature
detection inside `DetectMusicBrainz`, and fixture-driven plus real-Postgres tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MusicBrainz `/ws/2/recording` -> `internal/musicbrainz` | A never-before-called endpoint whose response shape is assumed, not verified; arrays are decoded and then indexed |
| `internal/musicbrainz` -> MusicBrainz | Outbound request volume against a free, volunteer-run community API that throttles by User-Agent |
| `internal/detection` -> Postgres | Recording titles and credited artist names from community-editable data cross into persisted rows |
