<objective>
Deliver the complete Discord delivery path end-to-end, thinnest possible slice: a real
`events` row with `notified_at IS NULL` becomes a real HTTP POST to a webhook endpoint and
gets acknowledged in the database — wired into the live poll cycles and the process
entrypoint, not just unit-tested in isolation.

Purpose: this phase's entire architectural risk lives in the seam chain
`poll cycle -> notifier -> discord client -> Postgres ack`. Proving that chain once, on one
event, before building out per-event-type formatting, means an architectural dead end
surfaces after one commit instead of after every layer is already committed.

Output: migration 000004 + the `MarkNotified` query + regenerated sqlc, the new
`internal/discord` and `internal/notifier` packages, the `poller.Notifier` seam wired into
both cycles, and D-10's disabled-path wiring in `cmd/server/main.go`.

**Tracer scope note.** Everything architectural is in the tracer: the CAS guard (D-06), the
inter-send spacing (D-07), the 429/`Retry-After` retry (D-08), the leave-NULL failure
contract (D-09), and the no-op selection (D-10). Retrofitting any of these later would
change `NotifyPending`'s or `Send`'s shape. What is deliberately left thin is the
*formatting richness* — a functionality gap, fillable in plan 05-03 without touching a
single seam.
</objective>
