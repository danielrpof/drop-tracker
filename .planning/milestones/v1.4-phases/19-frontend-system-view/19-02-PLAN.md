Create `web/app/lib/format.ts` following the `sources.ts` module shape: a header comment
enumerating the six formatters and naming where each is consumed, then one small exported pure
function per rule, no React import, no third-party import. This plan adds four of the six.

`formatRelativeTime(iso: string | null, now?: Date): string` — returns the em dash for null.
Computes the delta from `now` (defaulting to the current time) and clamps any negative delta to
`"just now"` before the ladder runs, so a client clock behind the server can never produce a
future-tense phrase. Then walks the grammar ladder from the RESEARCH table, pluralizing each
unit correctly.

`formatAbsoluteTime(iso: string | null, now?: Date): string` — returns the em dash for null and
for a value that does not parse to a valid date, so a malformed wire value degrades to the same
neutral placeholder rather than leaking the runtime's own error rendering (D-09). When the
timestamp falls on the same local calendar day as `now`, renders 24-hour `HH:MM:SS`; otherwise
renders `MMM D, HH:MM`. Build both with `Intl.DateTimeFormat` — native only, zero dependencies,
since CONTEXT locks this phase to no new packages.

`formatIsoTitle(iso: string): string` — the value for a `title` attribute: the full local
timestamp including its UTC offset, so hovering a row resolves both the exact instant and the
zone it is being read in.

`formatClock(d: Date): string` — 24-hour `HH:MM:SS` for the injected Date; this is the D-13
freshness stamp, deliberately taken from the client clock at fetch resolution rather than from
any payload field.

Every function takes its clock as a parameter defaulting to the current time so tests are
deterministic without mocking globals — the same discipline that keeps `history.test.tsx`
deterministic by controlling inputs.

Create `web/app/lib/format.test.ts` as a table-driven unit file: one `describe` per formatter,
`it.each` over the boundary rows, no router harness and no module mocking. Cover every boundary
named in the behavior block, including both sides of each ladder threshold and the same-day
versus earlier-day split.

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-05 | Information disclosure | `formatAbsoluteTime` / `formatRelativeTime` malformed-input path | low | mitigate | An unparseable or null timestamp returns the fixed em dash placeholder instead of the runtime's own invalid-date rendering, so no engine-internal text ever reaches the operator's screen. Asserted by a dedicated test case. |
| T-19-06 | Tampering (XSS) | formatter return values | low | mitigate | Every formatter returns a plain string composed from numbers and compile-time literals via `Intl` — no HTML, no markup, no interpolated payload text. Callers render the result as a JSX text node or a `title` attribute value, both escaped by React. |
| T-19-07 | Denial of service | `formatDuration` / `formatPollInterval` with an extreme integer | low | accept | Both are constant-time arithmetic over a bounded int the backend composes itself (`duration_ms` from a wall-clock delta, `poll_interval_seconds` from operator config). No loop, no allocation proportional to the input. A nonsensical value renders a nonsensical but harmless string. |
| T-19-SC | Tampering | npm/pnpm installs | low | accept | This plan runs no package install. `formatAbsoluteTime` deliberately uses native `Intl` rather than a date library precisely because CONTEXT locks the phase to zero new dependencies; `web/package.json` and `web/pnpm-lock.yaml` are untouched. |

**No threat in this plan reaches the configured `high` block-on severity.** These are six pure
string functions with no I/O, no network, no storage, and no DOM access.
