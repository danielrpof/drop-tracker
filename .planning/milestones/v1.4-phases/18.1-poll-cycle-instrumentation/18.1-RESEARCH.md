## User Constraints (from CONTEXT.md)

### Locked Decisions

The ROADMAP.md "Phase 18.1" → "Notes for the phase planner" block is the primary brief. Load-bearing points (verbatim from `18.1-CONTEXT.md` `<decisions>`):

- **D-14 (the reason for the split): channel fold, not atomics.** Each worker path emits exactly one value on a buffer sized to the dispatched count (no worker blocks on send); the fold is single-threaded. The `recover()` path must emit an **errored** result — a panicked artist is a failed artist — which means restructuring the worker body so the recover returns a value rather than acting only through a bare `defer`.
- **`artists_checked` = entries dispatched to a worker** (post `shouldDispatch`). MB dispatches every entry → `artists_skipped` always 0. Deezer skips nil-`deezer_id` entries before the semaphore → those are `artists_skipped`, never `artists_checked`. `checked + skipped + (errored overlap)` must reconcile against watchlist size for the operator.
- **`outcome` ∈ `{ok, error, cancelled}`** — no `partial`. A cycle that finished with some artists errored is `ok` with `artists_errored > 0`; Phase 19 derives a "degraded" label. `error` = cycle machinery failed (e.g. watchlist `List` errored). `cancelled` = `cycleErr` is `context.Canceled` / `DeadlineExceeded`.
- **`duration_ms` / `finished_at`** measured at the existing "poll cycle complete" log point (after `wg.Wait()`, before `NotifyPending`) — notifier delivery excluded.
- **`RecordRun` failure is logged and swallowed** — `logger.Error("record poll run failed", …)`, never returned. An observability write must never turn a green detection cycle red or wedge the overlap guard's `defer running.Store(false)`.
- **`RecordSkip`** bumps the store's per-source `consecutiveSkips` + `lastSkippedAt`; the next successful `RecordRun` resets `consecutiveSkips` to 0 (that reset already lives in the store's `RecordRun` — see Verified section — not `runCycle`).
- **Minimal diff.** Do not restructure the semaphore/`select`-on-`ctx.Done()` dispatch, `wg.Wait()` reachability, or the double `ctx.Err()` check. The only signature change is `fetchAndRecord` gaining an `(int, error)` return.
- **No `context.WithoutCancel`** — the in-memory ring-buffer append is synchronous and returns in microseconds even during shutdown (ADR-0001). `pollruns.Store.RecordRun` literally ignores its `ctx` argument.

## Summary

Phase 18 shipped the entire storage and read side of poll-run history: `internal/pollruns.Store` (a mutex-guarded per-source ring of the last `N=50` `RunResult` values), the `poller.RunRecorder` seam interface, a no-op default, the `WithRunRecorder` option, and one shared `*pollruns.Store` wired at the composition root as **both** the poller's recorder and the `/status` handler's reader. `runCycle` was left byte-for-byte untouched — the seam is inert, pinned by `TestRunRecorderInertThisPhase`.

Phase 18.1 is the single `runCycle` edit that fills that seam. The work is: (1) widen `EventRecorder.DetectMusicBrainz` / `DetectDeezer` to return `(int, error)`; (2) give `runCycle`'s `fetchAndRecord` parameter an `(int, error)` return; (3) restructure the worker goroutine body into a `runOneArtist` helper that returns a result value (so the `recover()` path emits an **errored** result instead of only logging); (4) fold the per-worker results single-threaded on a buffered channel after `wg.Wait()`; (5) add a `defer`-registered `p.runs.RecordRun(...)` after the CAS succeeds; (6) add `p.runs.RecordSkip(source)` at the `!CompareAndSwap` branch. The `go test -race` detector is unavailable on this box and absent from CI, so correctness is by construction (channel fold, not shared ints) plus a looped ~1000× exact-equality invariant test — the project's stated substitute.

**Primary recommendation:** Extract `runOneArtist(ctx, logger, entry, fetchAndRecord) artistResult` with its own `defer/recover`; the goroutine body becomes `resultCh <- runOneArtist(...)`. Buffer `resultCh` to `len(entries)` (safe upper bound → no worker ever blocks on send → `wg.Wait()` always reached). Count `artists_skipped` in the dispatch loop (single-threaded, never via the channel). Capture `finishedAt`/`durationMS` into function-scoped vars at the existing "poll cycle complete" log point and have the `RecordRun` defer read those captured values, never a fresh `time.Now()` (the defer fires after `NotifyPending`). Pass the live `ctx` straight to `RecordRun` — it is ignored by the store.

### System flow (the edit, end to end)

```
cron tick ──> RunMusicBrainzCycle / RunDeezerCycle
                 │  (builds shouldDispatch + fetchAndRecord closures)
                 ▼
              runCycle(ctx, &running, source, workers, shouldDispatch, fetchAndRecord)
                 │
         ┌───────┴─ CAS: running.CompareAndSwap(false,true) ?
         │  false ─> logger.Warn(skip) ─> p.runs.RecordSkip(source) ─> return ErrCycleInProgress   [NO run entry]  ★NEW
         │  true  ─> defer running.Store(false)
         │           defer RecordRun(...)   ── reads finishedAt / counts / outcome captured below  ★NEW
         ▼
       cycleID, logger, cycleStart := ...
       entries, err := p.store.List(ctx)
         err != nil ─> cycleErr = wrap(err); return cycleErr        [outcome=error, zero counts]  ★NEW (assign cycleErr)
         ▼
       resultCh := make(chan artistResult, len(entries))            ★NEW
       dispatch loop:
         !shouldDispatch(entry) ─> artistsSkipped++ ; continue      ★NEW (skipped counter, single-threaded)
         select { sem<-{} ; <-ctx.Done() -> cycleErr=ctx.Err(); break dispatch }
         wg.Add(1); go func(entry){ defer wg.Done(); defer func(){<-sem}();
                                     resultCh <- runOneArtist(ctx, logger, entry, fetchAndRecord) }(entry)  ★CHANGED
         ▼
       wg.Wait()
       close(resultCh)                                              ★NEW
       for r := range resultCh { fold: checked/errored/succeeded/events }   ★NEW (single-threaded)
       if cycleErr == nil { cycleErr = ctx.Err() }                  (unchanged re-check)
       finishedAt := time.Now(); durationMS := finishedAt.Sub(cycleStart).Milliseconds()   ★NEW capture

       p.notifier.NotifyPending(ctx, logger)                        (unchanged)
       return nil                                                   [defer records outcome=ok]
```

### Pattern 1: `runOneArtist` helper returns a value; the goroutine only sends it

**What:** Move the worker's body — the in-flight `ctx.Err()` check, the `fetchAndRecord` call, and the `recover()` — into a named function that returns an `artistResult`. The recover sets the **named return** to an errored result.

**Why:** D-14 requires the panic path to feed the fold, not just log. A bare `defer func(){ recover() }()` cannot contribute a value; a helper with a named return can.

**Recommended shape:**

```go
// artistResult is one worker's contribution to the cycle fold. Exactly one
// is produced per dispatched entry (success, error, panic, or ctx-bail).
type artistResult struct {
	checked bool // false only when the worker bailed on ctx.Err() before fetching
	errored bool // fetchAndRecord returned non-nil, OR the worker panicked
	events  int  // events recorded for this artist (0 on error / panic / bail)
}

// runOneArtist runs one dispatched entry's fetch+record under its own
// recover, so a panicking artist yields an errored result instead of
// crashing the process (panics do not cross goroutine boundaries). Mirrors
// the old inline worker body; the only new behaviour is returning a value.
func runOneArtist(
	ctx context.Context,
	logger *slog.Logger,
	entry watchlist.Entry,
	fetchAndRecord func(context.Context, *slog.Logger, watchlist.Entry) (int, error),
) (res artistResult) {
	defer func() {
		if r := recover(); r != nil {
			logger.Error("poll worker panicked",
				slog.String("artist_mbid", entry.MBID),
				slog.String("artist_name", entry.Name),
				slog.Any("panic_value", r),
			)
			res = artistResult{checked: true, errored: true}
		}
	}()

	// Mirrors the sequential loop's per-iteration ctx.Err() check: a worker
	// whose slot was acquired before cancellation must still not fetch.
	if err := ctx.Err(); err != nil {
		return artistResult{} // not checked, not errored — a ctx-bail
	}

	events, err := fetchAndRecord(ctx, logger, entry)
	if err != nil {
		return artistResult{checked: true, errored: true}
	}
	return artistResult{checked: true, events: events}
}
```

Goroutine body (the only change to the dispatch loop):

```go
wg.Add(1)
go func(entry watchlist.Entry) {
	defer wg.Done()
	defer func() { <-sem }()
	resultCh <- runOneArtist(ctx, logger, entry, fetchAndRecord)
}(entry)
```

The `defer wg.Done()` / `defer func(){ <-sem }()` order and registration stay exactly as today (LIFO: `<-sem` then `wg.Done()`). The panic recover moved *inside* `runOneArtist`, so no panic can escape the goroutine — same guarantee as today, expressed one call frame deeper.

**Panic-value decision:** the recovered result is `{checked:true, errored:true}`. A panicked artist *was* dispatched (slot acquired, `runOneArtist` entered) so it counts as checked; it failed, so it counts as errored. This keeps `checked == errored + succeeded` exact.

### Pattern 2: Buffered result channel sized to `len(entries)`, folded after `wg.Wait()`

```go
resultCh := make(chan artistResult, len(entries))
// ... dispatch loop sends exactly one per dispatched entry ...
wg.Wait()
close(resultCh)

var artistsChecked, artistsErrored, eventsRecorded int
for r := range resultCh {
	if !r.checked {
		continue // ctx-bail: dispatched but never fetched
	}
	artistsChecked++
	if r.errored {
		artistsErrored++
	}
	eventsRecorded += r.events
}
```

**Why `len(entries)` and not the precise dispatch count:** the channel must be created before the dispatch loop, and dispatched ≤ `len(entries)` always (each entry is dispatched at most once or skipped). An over-allocated buffer wastes a few `artistResult` structs (~24 bytes each; watchlists are tens of entries). The load-bearing property is **buffer capacity ≥ number of senders**, which `len(entries)` guarantees unconditionally — so no worker ever blocks on `resultCh <-`, so every worker reaches `wg.Done()`, so `wg.Wait()` always returns. An undersized buffer would deadlock `wg.Wait()` forever. This invariant must be stated explicitly in the concurrency-correctness section (there is no `-race` to catch a regression).

**`artists_skipped` is NOT folded from the channel.** It is incremented in the dispatch loop's `if !shouldDispatch(entry, logger) { artistsSkipped++; continue }` — that loop is single-threaded, so a plain `int++` is correct there. MB's `shouldDispatch` always returns `true` → `artistsSkipped` stays 0. Deezer's returns `false` for nil `DeezerID` → those are counted skipped and never enter `resultCh`.

### Pattern 3: `defer`-registered `RecordRun` after the CAS, reading captured end-of-cycle state

```go
if !running.CompareAndSwap(false, true) {
	p.logger.Warn("skipping poll cycle: previous cycle still in progress", slog.String("source", source))
	p.runs.RecordSkip(source)          // ★ RUN-02 skip signal
	return ErrCycleInProgress           // returns BEFORE any defer is registered — no run entry
}
defer running.Store(false)

cycleID := fmt.Sprintf("%s-%d", source, nextCycleID.Add(1))
logger := p.logger.With(slog.String("source", source), slog.String("cycle_id", cycleID))
cycleStart := time.Now()

var (
	artistsChecked, artistsSkipped, artistsErrored, eventsRecorded int
	runFinishedAt time.Time
	runDurationMS int64
)
defer func() {
	if runFinishedAt.IsZero() { // e.g. the store.List error path returned before the capture below
		runFinishedAt = time.Now()
		runDurationMS = runFinishedAt.Sub(cycleStart).Milliseconds()
	}
	outcome := pollruns.OutcomeOK
	switch {
	case errors.Is(cycleErr, context.Canceled), errors.Is(cycleErr, context.DeadlineExceeded):
		outcome = pollruns.OutcomeCancelled
	case cycleErr != nil:
		outcome = pollruns.OutcomeError
	}
	if err := p.runs.RecordRun(ctx, pollruns.RunResult{
		Source:         source,
		CycleID:        cycleID,
		StartedAt:      cycleStart,
		FinishedAt:     runFinishedAt,
		DurationMS:     runDurationMS,
		ArtistsChecked: artistsChecked,
		ArtistsSkipped: artistsSkipped,
		ArtistsErrored: artistsErrored,
		EventsRecorded: eventsRecorded,
		Outcome:        outcome,
		// Summary intentionally not set — RecordRun composes it from the counts + outcome.
	}); err != nil {
		logger.Error("record poll run failed", slog.String("run_recorder_error", err.Error()))
	}
}()
```

Notes:
- **`cycleErr` already exists** as a function-scoped `var cycleErr error` (current `poller.go` line 343). The defer closes over it. The only new assignment is on the `store.List` error path: `cycleErr = fmt.Errorf("poller: list watchlist: %w", err); return cycleErr`.
- **Defer ordering:** `defer running.Store(false)` is registered first, the `RecordRun` defer second → LIFO → `RecordRun` runs *first* (guard still held), then `running.Store(false)`. Since `RecordRun` is a microsecond mutex append that cannot block, holding the guard across it is harmless and it sidesteps any theoretical concurrent same-source `RecordRun`. Either order satisfies the requirements; this one is simplest to reason about.
- **`ctx` is passed straight through.** `pollruns.Store.RecordRun(_ context.Context, r RunResult)` ignores it (verified below). A shutdown-cancelled cycle still records — no `context.WithoutCancel`, no timeout, no new const. This is the ADR-0001 simplification.
- **`finished_at` / `duration_ms` capture:** set `runFinishedAt` / `runDurationMS` at the existing "poll cycle complete" log point (after the post-join `ctx.Err()` re-check, before the `if cycleErr != nil` return) and reuse the same value in the log line. The defer must **not** call `time.Now()` on the happy path — it runs after `NotifyPending`, and CONTEXT excludes notifier delivery time.

### Pattern 4: `fetchAndRecord` and `EventRecorder` widening

`runCycle`'s parameter signature — one change:

```
BEFORE: fetchAndRecord func(ctx context.Context, logger *slog.Logger, entry watchlist.Entry)
AFTER:  fetchAndRecord func(ctx context.Context, logger *slog.Logger, entry watchlist.Entry) (int, error)
```

Both closures (`RunMusicBrainzCycle` ~line 453, `RunDeezerCycle` ~line 512) change from bare `return` after a logged error to `return 0, err`, and gain a trailing `return count, nil` (or `return count, err` — see below). The `p.events.DetectMusicBrainz(...)` / `DetectDeezer(...)` calls become `count, err := p.events.Detect...(...)`.

`EventRecorder` interface (`poller.go` lines 87-90):

```go
type EventRecorder interface {
	DetectMusicBrainz(ctx context.Context, logger *slog.Logger, entry watchlist.Entry, groups []musicbrainz.ReleaseGroup) (int, error)
	DetectDeezer(ctx context.Context, logger *slog.Logger, entry watchlist.Entry, albums []deezer.Album) (int, error)
}
```

**`events` return on a `fetchAndRecord` error:** recommend `return 0, err` for a *fetch* failure (no detection ran) and `return count, err` for a *detection* failure (rows may have been inserted before the error). The fold adds `r.events` regardless of `r.errored`, so a partially-successful detection still contributes its real count. This is a judgement call — the alternative (always `return 0` on any error) is also defensible since `events_recorded` is observability-only. Either way, in the **looped invariant test** the erroring/panicking fake artists fail at the *fetch* stage (`ReleaseGroupsByArtist` returns `(nil, err)` / panics), so they contribute `events == 0` cleanly.

### Anti-Patterns to Avoid

- **`atomic.Int64` counters incremented inside the workers.** Compiles, passes every existing test, passes a naive new test — and is a data race with no `-race` net. D-14 forbids it explicitly. Use the channel fold. (The `sync/atomic` import stays, but only for `nextCycleID` / `atomic.Bool` as today.)
- **A shared `[]string` / `map` appended to inside `fetchAndRecord`.** Same race class. The run entry carries counts + an outcome enum only — never per-artist detail.
- **Restructuring the semaphore `select`, the `dispatch:` label/`break`, `wg.Add`/`wg.Wait`, or the two `ctx.Err()` checks.** The brief and `ARCHITECTURE.md` Anti-Pattern 5 both prohibit this. The extraction of `runOneArtist` is the *only* sanctioned worker-body change.
- **Recording a run entry for an overlap-skipped tick.** The `!CompareAndSwap` branch returns before `cycleID`/`cycleStart`/the defers exist. Only `RecordSkip(source)` goes there.
- **Calling `RecordRun` with a fresh `time.Now()` inside the defer.** Captures `NotifyPending` latency into `duration_ms`. Capture at the log point.
- **Propagating the `RecordRun` error.** Turns a green cycle red. Log and swallow, exactly like `NotifyPending` (`poller.go` line 430-432).
- **Widening `DetectMusicBrainz` to `(int, error)` but forgetting the guest-feature / deluxe-change insert counts.** `events_recorded` would silently under-report. Widen `detectGuestFeatures` and `detectDeluxeChanges` too (both unexported, both called only from `musicbrainz.go`), or accept `new_release`-only and document it.

## Don't Hand-Roll

| Problem | Don't build | Use instead | Why |
|---------|-------------|-------------|-----|
| Per-source run history storage | A `poll_runs` table + prune SQL + migration | `internal/pollruns.Store` (shipped) | ADR-0001 designed the table out — prune races, cross-source deadlock, migration surface all gone. |
| The recorder seam / no-op default / option | A new interface | `poller.RunRecorder` + `noopRunRecorder` + `WithRunRecorder` (shipped Phase 18) | Already wired at the composition root as the same instance `/status` reads. |
| Summary string composition | Formatting a summary in `runCycle` | `pollruns.Store.RecordRun` composes it from counts + outcome and **discards** any caller-supplied `Summary` | Structural leak-prevention (D-09) — verified below. |
| `consecutiveSkips` reset | Resetting it in `runCycle` after a successful cycle | `RecordRun` already sets `st.consecutiveSkips = 0` | Verified below (`pollruns.go` line 91). |
| Cross-goroutine counter aggregation | `atomic.Int64` / mutex / shared slice | Buffered channel + single-threaded fold | Correct by construction without `-race`. |
| Shutdown-surviving recorder write | `context.WithoutCancel` + timeout + a new const | Pass `ctx` straight through | The ring append is synchronous and ignores `ctx` (ADR-0001). |

**Key insight:** Phase 18 did the hard design work. Phase 18.1 is deliberately small; the risk is entirely in *not* disturbing `runCycle`'s existing concurrency reasoning while threading four counters through it.

## Common Pitfalls

### Pitfall 1: The counter data race with no `-race` backstop
**What goes wrong:** `errored++` inside `fetchAndRecord` (or a shared slice append) from N worker goroutines — undefined behaviour, corrupted counts that usually look plausible.
**Why it happens:** it is the obvious implementation, compiles, and passes a naive non-race test because the window is tiny.
**How to avoid:** channel fold (Pattern 2). Each worker emits exactly one `artistResult`; the parent folds after `wg.Wait()`, single-threaded. `sync/atomic` stays reserved for `nextCycleID`/`atomic.Bool`.
**Warning signs in review:** any `+=`/`++` on a shared variable inside the `go func`; `>=`/`<=` (not `==`) assertions on counts in a test; flaky count values between runs.

### Pitfall 2: `wg.Wait()` deadlock from an undersized result channel
**What goes wrong:** buffer `resultCh` to the wrong size (e.g. `workers` instead of `len(entries)`) → workers block on `resultCh <-` → never call `wg.Done()` → `wg.Wait()` hangs forever → the cron goroutine and eventually shutdown wedge.
**Why it happens:** "size it to the worker count" is a plausible misreading of "sized to the dispatched count."
**How to avoid:** `make(chan artistResult, len(entries))`. Capacity ≥ senders is the invariant. State it in the concurrency-correctness section.
**Warning signs:** a test that hangs; `resultCh` capacity that is not `len(entries)` or a precisely-tracked dispatch count.

### Pitfall 3: The panic path drops out of the fold
**What goes wrong:** the `recover()` only logs (as today), so a panicking artist increments nothing → `checked != errored + succeeded` whenever a worker panics.
**How to avoid:** `runOneArtist`'s deferred recover sets the **named return** `res = artistResult{checked:true, errored:true}`. The `resultCh <- runOneArtist(...)` still fires because the function returns normally after recovering.
**Warning signs:** a panic test that asserts only "process didn't crash" and not "`artists_errored` went up by 1."

### Pitfall 4: `duration_ms` includes `NotifyPending`
**What goes wrong:** the `RecordRun` defer runs at function return — *after* `NotifyPending`. A `time.Now()` there inflates `duration_ms` by notifier delivery time, contradicting CONTEXT and the existing "poll cycle complete" log.
**How to avoid:** capture `runFinishedAt`/`runDurationMS` at the log point; the defer reads the captured values (with a zero-check fallback for the early `store.List` error return).

### Pitfall 5: Recording a run entry for an overlap-skipped tick
**What goes wrong:** if the `RecordRun` call is placed in `RunMusicBrainzCycle`/the cron closure instead of *inside* `runCycle` after the CAS, every `ErrCycleInProgress` return writes a junk entry (zero everything) and — because the ring is only 50 deep — a burst of skips during one slow cycle evicts real history.
**How to avoid:** the `RecordRun` defer is registered *after* the successful CAS, so the pre-CAS `return ErrCycleInProgress` never triggers it. Only `RecordSkip(source)` goes on that branch.

### Pitfall 6: `outcome` never becomes `error` on `store.List` failure
**What goes wrong:** the current `store.List` error path does `return fmt.Errorf(...)` without touching `cycleErr`, so the `RecordRun` defer would see `cycleErr == nil` and record `ok` for a cycle that never ran.
**How to avoid:** `cycleErr = fmt.Errorf("poller: list watchlist: %w", err); return cycleErr`.

### Pitfall 7: `events_recorded` under-reports (MB guest-feature / deluxe passes)
**What goes wrong:** widening only `DetectMusicBrainz`'s outermost `new_release` count omits the `detectGuestFeatures` and `detectDeluxeChanges` inserts.
**How to avoid:** widen both unexported helpers to `(int, error)` and sum; or consciously ship `new_release`-only and note it in the plan + a code comment. (Recommend summing — criterion 5 says "`events_recorded` is real … never hard-coded to 0 while displayed.")

### Pitfall 8: Forgetting to invert `TestRunRecorderInertThisPhase`
**What goes wrong:** `internal/poller/poller_test.go:92-115` asserts `rec.runCalls == 0` and `rec.skipCalls == 0` after a full cycle — it will fail the moment the wiring lands, and a reader could misread it as a regression.
**How to avoid:** the plan must rewrite it (rename to e.g. `TestRunRecorder_RecordsOneRunPerCycle`) asserting `runCalls == 1` per `RunMusicBrainzCycle`/`RunDeezerCycle` and `skipCalls == 1` on an overlap. Both 18-02-SUMMARY and 18-04-SUMMARY explicitly flag this as required.

## Code Examples

### The full `runCycle` edit (assembled)

```go
func (p *Poller) runCycle(ctx context.Context, running *atomic.Bool, source string, workers int,
	shouldDispatch func(entry watchlist.Entry, logger *slog.Logger) bool,
	fetchAndRecord func(ctx context.Context, logger *slog.Logger, entry watchlist.Entry) (int, error), // ★ +(int, error)
) error {
	if !running.CompareAndSwap(false, true) {
		p.logger.Warn("skipping poll cycle: previous cycle still in progress", slog.String("source", source))
		p.runs.RecordSkip(source) // ★
		return ErrCycleInProgress
	}
	defer running.Store(false)

	cycleID := fmt.Sprintf("%s-%d", source, nextCycleID.Add(1))
	logger := p.logger.With(slog.String("source", source), slog.String("cycle_id", cycleID))
	cycleStart := time.Now()

	var (
		artistsChecked, artistsSkipped, artistsErrored, eventsRecorded int
		cycleErr                                                       error
		runFinishedAt                                                  time.Time
		runDurationMS                                                  int64
	)
	defer func() { // ★ RUN-01/02/03
		if runFinishedAt.IsZero() {
			runFinishedAt = time.Now()
			runDurationMS = runFinishedAt.Sub(cycleStart).Milliseconds()
		}
		outcome := pollruns.OutcomeOK
		switch {
		case errors.Is(cycleErr, context.Canceled), errors.Is(cycleErr, context.DeadlineExceeded):
			outcome = pollruns.OutcomeCancelled
		case cycleErr != nil:
			outcome = pollruns.OutcomeError
		}
		if err := p.runs.RecordRun(ctx, pollruns.RunResult{
			Source: source, CycleID: cycleID,
			StartedAt: cycleStart, FinishedAt: runFinishedAt, DurationMS: runDurationMS,
			ArtistsChecked: artistsChecked, ArtistsSkipped: artistsSkipped,
			ArtistsErrored: artistsErrored, EventsRecorded: eventsRecorded,
			Outcome: outcome,
		}); err != nil {
			logger.Error("record poll run failed", slog.String("run_recorder_error", err.Error()))
		}
	}()

	entries, err := p.store.List(ctx)
	if err != nil {
		cycleErr = fmt.Errorf("poller: list watchlist: %w", err) // ★ so outcome=error
		return cycleErr
	}

	sem := make(chan struct{}, workers)
	resultCh := make(chan artistResult, len(entries)) // ★ capacity >= senders
	var wg sync.WaitGroup

dispatch:
	for _, entry := range entries {
		if !shouldDispatch(entry, logger) {
			artistsSkipped++ // ★ single-threaded, dispatch loop only
			continue
		}
		select {
		case sem <- struct{}{}:
		case <-ctx.Done():
			cycleErr = ctx.Err()
			break dispatch
		}
		wg.Add(1)
		go func(entry watchlist.Entry) {
			defer wg.Done()
			defer func() { <-sem }()
			resultCh <- runOneArtist(ctx, logger, entry, fetchAndRecord) // ★
		}(entry)
	}
	wg.Wait()
	close(resultCh) // ★

	for r := range resultCh { // ★ single-threaded fold
		if !r.checked {
			continue
		}
		artistsChecked++
		if r.errored {
			artistsErrored++
		}
		eventsRecorded += r.events
	}

	if cycleErr == nil {
		cycleErr = ctx.Err()
	}

	runFinishedAt = time.Now() // ★ capture BEFORE NotifyPending
	runDurationMS = runFinishedAt.Sub(cycleStart).Milliseconds()
	logger.Info("poll cycle complete",
		slog.Int("artist_count", len(entries)),
		slog.Int64("duration_ms", runDurationMS),
	)

	if cycleErr != nil {
		return cycleErr
	}

	if err := p.notifier.NotifyPending(ctx, logger); err != nil {
		logger.Error("notify pending failed", slog.String("notifier_error", err.Error()))
	}
	return nil
}
```

### Concurrency-Correctness Section (required plan deliverable — the `-race` substitute)

The plan must spell out, in prose:
1. **No shared mutable counter.** `artists_checked/errored`, `events_recorded` are derived by a single-threaded `for r := range resultCh` fold that runs only after `wg.Wait()`. `artists_skipped` is incremented only in the single-threaded dispatch loop.
2. **Exactly one result per dispatched worker.** Every path through `runOneArtist` returns an `artistResult`; the goroutine body is `resultCh <- runOneArtist(...)` with no early return. The panic path returns via the deferred recover setting the named return.
3. **No worker blocks on send.** `cap(resultCh) == len(entries) >= (dispatched count)`, so every `resultCh <-` succeeds immediately, every worker reaches `wg.Done()`, `wg.Wait()` always returns, the fold always runs.
4. **`sem` and `wg` semantics unchanged.** The `select { sem<-{} ; <-ctx.Done() }` dispatch, the `dispatch:` label/`break`, `wg.Add(1)` before `go`, the deferred `<-sem` and `wg.Done()` — byte-identical to today.
5. **The looped invariant test** (`-count=1000` internal loop, run also with `-count=3`) with erroring *and* panicking fake artists is the compensating control for the absent race detector.
