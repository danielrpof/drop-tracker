<concurrency_correctness_reference>
The five-point concurrency-correctness argument this test is the fifth point of lives
in `18.1-01-PLAN.md` under `<concurrency_correctness>`. Read it before writing the
test — the assertions here exist to falsify exactly the failure modes that argument
claims are impossible:

1. no shared mutable counter → a race would show as a *low* `artists_checked` on some
   iterations, which exact equality catches and an inequality would not
2. exactly one result per dispatched worker → a dropped panic result shows as
   `artists_errored < K + P`
3. no worker blocks on send → an undersized buffer shows as a hung test, which is why
   every verify below carries an explicit `-timeout`
4. `sem`/`wg` semantics unchanged → a broken `wg.Wait()` shows as a *low* checked count
5. this test
</concurrency_correctness_reference>

      iteration: `ArtistsSkipped == 4`, `ArtistsChecked == 16`,
      `ArtistsChecked + ArtistsSkipped == 20`.
    - A panicking worker never crashes the test process and never leaves the overlap
      guard held: after the loop, `p.mbRunning.Load()` is `false`.
    - The whole test completes inside a 120-second `go test -timeout`.
  </behavior>

  <action>
Write `TestRunCycle_CounterInvariant` as two sub-tests sharing a table of synthetic
entries. Build the entries with a helper local to the test — do not reuse
`threeEntries()`, which is three entries with a fixed nil-`DeezerID` shape; this test
needs M, K, P and S as named constants at the top of the test so the assertions read as
the invariant they encode.

For each iteration, construct a fresh `Poller` through `New(...)` with a `stubStore`
returning the M entries, a `fakeReleaseGroupSource` whose hook switches on the mbid to
return a sentinel error for the K designated artists and to panic for the P designated
ones, a `fakeEventRecorder` whose hook returns the fixed per-artist count E and a nil

so the fan-out is genuinely concurrent rather than serialised. Use a discarding logger
rather than `newTestLogger`, because ~1000 iterations of panic logging into a
`bytes.Buffer` would dominate the runtime and prove nothing.

After each `RunMusicBrainzCycle`, assert the six equalities from the behavior block with
`==` and fail with `t.Fatalf` including the iteration index, so a single bad iteration
stops the run and names itself. Never use an inequality comparison, a tolerance, or an
"at least" phrasing anywhere in this test — a shared-counter regression manifests as an
*occasional* undercount, and an inequality would swallow exactly the signal this test
exists to produce. Also assert `RunMusicBrainzCycle` returned `nil` on every iteration:
a panicking artist is an errored artist, not a failed cycle.

The Deezer sub-test mirrors it with `WithDeezerWorkers(8)`, a `fakeAlbumSource`, and S
of the M entries carrying a nil `DeezerID`, asserting the skipped/checked split.

After the loops, assert both overlap guards read `false`.

Keep the test's doc comment to the project's 1-3 line discipline: what invariant it
pins and one reference to D-14. Do not restate the concurrency argument in the source —
