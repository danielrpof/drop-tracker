# Phase 18.1 Plan 01: Widen the EventRecorder seam and record one real run entry end-to-end Summary

**`EventRecorder` widened to `(int, error)` across every layer and call site; `runCycle` now folds per-worker `artistResult` values single-threaded off a `len(entries)`-buffered channel and writes exactly one `pollruns.RunResult` per completed cycle through a `defer`-registered `RecordRun`.**

## Accomplishments

- `DetectMusicBrainz`, `DetectDeezer`, and the two unexported MusicBrainz helpers (`detectGuestFeatures`, `detectDeluxeChanges`) return the count of event rows they inserted; `DetectMusicBrainz` sums all three passes via a function-scoped `newRelease` counter.
- `runCycle` extracts the worker body into `runOneArtist` (its own `defer/recover`, named return), sends one `artistResult` per dispatched entry on a `make(chan artistResult, len(entries))` buffer, and folds `artists_checked / artists_errored / events_recorded` single-threaded after `wg.Wait()` — no counter is written from inside a worker (D-14). `artists_skipped` is bumped only in the single-threaded dispatch loop.
- A `defer`-registered `p.runs.RecordRun(...)` writes exactly one entry per post-CAS cycle: `source`, `cycle_id`, `started_at`, `finished_at`/`duration_ms` captured at the "poll cycle complete" log point (notifier delivery excluded), the four counters, and an `outcome` derived from the existing `cycleErr` (`ok` / `error` / `cancelled`). `Summary` is left unset — the store composes it from counts + outcome (ASVS V7). A recorder error is logged and swallowed, mirroring `NotifyPending`.
- `RecordSkip(source)` fires on the pre-CAS overlap-skipped tick; the `store.List` error path now assigns `cycleErr` so that invocation records `outcome=error` with zero counts.
- The Phase 18 inert-seam pin `TestRunRecorderInertThisPhase` is inverted to `TestRunRecorder_RecordsOneRunPerCycle`, which asserts one `RecordRun` per cycle, zero `RecordSkip` without overlap, and a real `pollruns.NewStore()` holding the entry with `EventsRecorded == 9` (3 entries × 3 events) that came out of the widened seam.
- `events_recorded` is pinned to reality at both ends of the seam: four detection cases bind and assert the returned count against rows they already prove landed (including a guest-feature case where a count of 1 can only come from the summed pass), and both poller real-Postgres integration tests assert `LastRun.EventsRecorded` equals the inserted row count.

## Concurrency-Correctness Section (the `-race` substitute — required deliverable)

`go test -race` fails on this dev box (ThreadSanitizer allocation failure under WSL2) and is absent from CI. Correctness of the new counters is established **by construction**, not by detector. Five load-bearing points (verbatim from the plan):

1. **No shared mutable counter.** `artists_checked`, `artists_errored` and `events_recorded` are derived exclusively by the single-threaded `for r := range resultCh` fold, which runs only after `wg.Wait()` has joined every worker. `artists_skipped` is incremented only inside the dispatch loop, which is itself single-threaded. No worker goroutine writes any variable the parent reads. (D-14 forbids the `sync/atomic` alternative explicitly; the existing `sync/atomic` import stays reserved for `nextCycleID` and the `atomic.Bool` overlap guards.)

2. **Exactly one result per dispatched worker.** Every path through `runOneArtist` returns an `artistResult`: success, fetch/detect error, ctx-bail, and — via the deferred `recover()` assigning the *named* return — panic. The goroutine body is a single unconditional send of that value; it contains no early `return`, so dispatched-count and sent-count are equal by inspection.

3. **No worker ever blocks on send.** `cap(resultCh) == len(entries)`, and the number of senders is the dispatched count, which is `<= len(entries)` because each entry is dispatched at most once. Capacity `>=` senders means every send completes immediately, so every worker reaches its deferred `wg.Done()`, so `wg.Wait()` always returns and the fold always runs. Sizing the buffer to `workers` instead would deadlock `wg.Wait()` forever.

4. **`sem` and `wg` semantics are unchanged.** The `select` on `sem <- struct{}{}` versus `<-ctx.Done()`, the `dispatch:` label and `break dispatch`, the `wg.Add(1)` before `go`, the deferred `<-sem` and `wg.Done()` and their LIFO order, and both `ctx.Err()` checks (the in-flight one now inside `runOneArtist`, the post-join re-check) are byte-identical in behaviour to today. The only sanctioned change to the worker body is the extraction into `runOneArtist`.

5. **The compensating control** is `TestRunCycle_CounterInvariant` (`18.1-03-PLAN.md`): ~1000 internal iterations over a fake source with K erroring and P panicking artists, asserting `checked == errored + succeeded`, `errored == K + P` and `checked == M - skipped` with **exact equality** on every iteration, run additionally with `-count=3`. A Broken Windows Ledger `deviation` entry records the `-race` waiver, matching entries 9 and 10 (recorded here as entry 12).
