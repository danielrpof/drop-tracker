# Phase 18.1 Plan 02: The remaining exit paths — skip, list-failure, cancellation, misbehaving recorder Summary

**Four new `internal/poller` unit tests pin every non-happy `runCycle` exit: an overlap-skipped tick that writes a skip signal and no history entry, a watchlist `List` failure recorded as `outcome=error` with zero counters and no leaked driver text, a shutdown-cancelled cycle (mid-flight and pre-dispatch) recorded as `outcome=cancelled`, and a recorder that errors or stalls without ever failing, retrying, or wedging the cycle.**

## Performance

- **Duration:** 22 min
- **Started:** 2026-09-10
- **Completed:** 2026-09-10
- **Tasks:** 3 (all `tdd="true"`, executed test-only — see Deviations)
- **Files modified:** 1

## Accomplishments

- `TestRunRecorder_SkipRecordsNoEntry` — two subtests over one blocked-cycle helper: a `fakeRunRecorder` sees exactly one `RecordSkip` and zero `RecordRun` during the skipped tick; a real `pollruns.NewStore()` shows history length unchanged (0) across the skip and `ConsecutiveSkips` moving 0 → 1 → 0 once the held cycle's `RecordRun` completes. This is the direct assertion for threat T-18.1-08 (a skip-storm must not evict real history).
- `TestRunRecorder_RecordsErrorOutcomeOnListFailure` — a `stubStore` whose `listFunc` returns a sentinel error: `RunMusicBrainzCycle` returns non-nil, the store holds exactly one entry with `Outcome == pollruns.OutcomeError`, all four counters 0, and a composed summary (`"error — 0 checked, 0 errored, 0 events"`) that contains no part of the sentinel text (threat T-18.1-07).
- `TestRunRecorder_RecordsCancelledOutcome` — subtest 1 mirrors `TestMusicBrainzCycle_ContextCancelledStopsIteration` (`WithMusicBrainzWorkers(1)`, `cancel()` from inside the fake source on `mbid-1`): the cycle returns a context error and the store holds exactly one entry with `Outcome == pollruns.OutcomeCancelled` and `ArtistsChecked == ArtistsErrored + <fake-served>`. Subtest 2 cancels before the call: one entry, cancelled outcome, all four counters 0, zero source calls (every dispatched worker `ctx`-bails in `runOneArtist` before fetching).
- `TestRunRecorder_ErrorSwallowed` — subtest 1: a `fakeRunRecorder` whose `runFn` errors leaves `RunMusicBrainzCycle` returning `nil`, emits both a `poll cycle complete` and a `record poll run failed` (carrying a `run_recorder_error` attribute) log record, calls `RecordRun` exactly once, and leaves `mbRunning` false. Subtest 2: a `runFn` that sleeps 50 ms still returns `nil` within a bounded wait with the guard released.
- `TestPoller_RunDeezerCycle_SkipsNilDeezerID` rebuilt on `New(..., WithRunRecorder(pollruns.NewStore()))`: every prior assertion kept, plus `ArtistsSkipped == 1` / `ArtistsChecked == 2` read off the real store's `LastRun`.
- `TestPoller_RunMusicBrainzCycle_EmptyWatchlist` extended with a real store: one `ok` entry, four counters 0, `FinishedAt` not before `StartedAt` — the zero-length-input edge.
- `ArtistsSkipped == 0` assertion added to the MusicBrainz leg of `TestRunRecorder_RecordsOneRunPerCycle`.
