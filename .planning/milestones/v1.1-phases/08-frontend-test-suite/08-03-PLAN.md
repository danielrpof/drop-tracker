<objective>
Cover the search surface and close the folded AbortController bug so the component's own documented
supersession guarantee is true at the request level, not only at the callback level.

Purpose: ROADMAP success criterion 2 names search as one of four surfaces needing a passing behavior
test, and CONTEXT.md folds in the AbortController bug precisely because the search test's strongest
claim — a superseded search never affects a newer one — is only half true today. `SearchBox.runSearch`
creates a fresh `AbortController` per debounced search and aborts the prior one, but never hands the
signal to `searchArtists`, so the superseded request still runs to completion against the live Go API
(and transitively against MusicBrainz and Deezer); only its resolved value is discarded.

Per D-07 the fix lands as a RED-then-GREEN pair: a test commit that fails against current source,
then a minimal fix commit that makes it pass. The RED commit intentionally leaves the suite red for
one commit; the GREEN commit restores it. This mirrors the repo's established convention (Phase 02-03
and 03-03 both landed RED test commits ahead of separate GREEN feat commits).

Output: `web/app/components/watchlist/SearchBox.test.tsx`, plus a widened `searchArtists` signature in
`web/app/lib/api.ts` and its call site in `web/app/components/watchlist/SearchBox.tsx`.
</objective>
