<objective>
Build and prove the backend coverage measurement-and-gate mechanism end to end, then measure and
record the backend starting baseline before any threshold is enforced anywhere.

Purpose: this is the phase's tracer slice. Every later plan depends on two facts this plan
establishes — that the measure→parse→compare→exit chain actually works with the right measurement
scope, and what the real backend number is. `-coverpkg` scope correctness is the single largest
technical risk on the backend side (09-RESEARCH.md Pitfall 1: omitting `-coverpkg` silently drops
`cmd/server` from the profile entirely and inflates the aggregate), so it is proven first, against a
real Postgres-backed run, before any gap-closing test is written against a number that might be a
measurement artifact. Recording the baseline before enforcement is ROADMAP success criterion 4.

Output: an instrumented `Makefile` with a `coverage-gate` target pinned at 80, and
`.planning/phases/09-ci-coverage-gates/09-BASELINE-BACKEND.md` holding the measured starting number.
</objective>

       requirement id CICD-11 and state that 80 is the required floor, not a tunable.

    4. Extend the `test-integration` recipe: keep `db-up` as its prerequisite, keep the
       `TEST_DATABASE_URL=$(TEST_DATABASE_URL)` prefix, keep `-race -count=1 -p 1` and the entire

       immediately after `test-integration` without re-running the suite), written in the
       `sqlc-version-check` idiom. Its recipe must, in order:
       - Fail with a message naming `coverage.out` and telling the reader to run `make
         test-integration` first, unless `coverage.out` exists and is non-empty. Use the shell's
         file-size test for this.
       - Extract the aggregate percentage by piping `go tool cover -func=coverage.out` into a grep
         anchored on the total line at the start of the line, then an `awk` that takes the third
         whitespace field and strips its trailing percent sign with `substr`.
       - Fail with a parse-error message if the extracted value is the empty string.
       - Echo one line reporting the measured percentage and the required minimum. This echo plus the
         pass/fail line below is the entire report surface — do not write an HTML report, do not
         upload an artifact (D-03: log-only).
       - Compare with `awk`, never with the shell's `[` / `test`: pass `cov` and `thresh` in as `-v`
         variables and let the `BEGIN` block decide, because `go tool cover -func` reports one decimal
         place and POSIX `test` is integer-only. On the failing side echo a message to stderr that
         names both the measured value and the required minimum, then `exit 1`; on the passing side
         echo a pass line. Do not write to a `/dev/stderr` path from inside awk — do the comparison in
         awk and do the reporting in the surrounding shell `if`, so the recipe stays portable to a
         Windows msys shell as well as an ubuntu runner.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Developer/CI push → pipeline gating decision | The coverage gate is the only thing standing between an under-tested commit and the build/scan/publish chain; a gate that fails open is indistinguishable from no gate |
| `coverage.out` on disk → gate verdict | An untrusted, absent, truncated, or stale profile file is the gate's sole input |
