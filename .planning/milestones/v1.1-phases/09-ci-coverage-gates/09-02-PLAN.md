<objective>
Install the frontend coverage provider and configure an honest measurement denominator, then measure
and record the frontend starting baseline before any threshold is enforced.

Purpose: this is the frontend half of the phase's measurement layer, and it carries the phase's
single highest-risk gotcha. Vitest 4 removed the option that used to force every matched file into
the coverage report; the current default measures only files a test actually imported. With
`coverage.include` left unset, `app/routes/history.tsx` (no test file) and `app/lib/api.ts` (mocked
out of every existing test by TEST-02's own design) would simply never appear — producing a
technically-passing 70% gate measuring almost nothing (09-RESEARCH.md Pitfall 3). Getting the
denominator right is therefore the work; the threshold itself is one config key added later.

Output: `@vitest/coverage-v8@4.1.10` in `web/package.json`, a `coverage` block in
`web/vitest.config.ts` that measures all first-party `app/**` source, and
`.planning/phases/09-ci-coverage-gates/09-BASELINE-FRONTEND.md` holding the measured starting number.
</objective>
