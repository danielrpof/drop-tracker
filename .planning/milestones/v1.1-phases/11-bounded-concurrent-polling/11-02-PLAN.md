<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Deezer API → worker closure | externally-supplied album slices are processed inside concurrent goroutines |
| poller worker → shared `*rate.Limiter` | many goroutines now queue on one token bucket that previously saw one caller at a time |
| cron tick → cycle-overlap guard | a second tick can arrive while N workers are in flight, not just while one fetch is in flight |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-06 | Denial of Service | outbound request rate to MusicBrainz / Deezer under concurrent workers | high | mitigate | The shared `*rate.Limiter` is documented safe for concurrent callers and is left completely unwrapped; Task 2 proves the ceiling empirically with real captured request timing rather than trusting the documented guarantee (11-RESEARCH.md Pitfall 5). Exceeding a third party's published rate is the one externally-visible abuse this phase could cause. |
| T-11-07 | Denial of Service (self-inflicted) | `RunDeezerCycle` worker closure | medium | mitigate | Buffered-channel semaphore with no shared error or cancellation object; the x/sync group constructor that derives a cancellable context is prohibited and grep-gated in Task 1's acceptance criteria; Task 3 proves simultaneous failures do not abort the cycle. |
| T-11-08 | Denial of Service | cycle-overlap guard under concurrency | medium | mitigate | `dzRunning`/`mbRunning` are released by `defer` after the worker join, never before; Task 2 proves a second cycle is rejected while workers are in flight and that the two sources' guards remain independent. |
| T-11-09 | Denial of Service | goroutine lifetime on context cancellation in `RunDeezerCycle` | medium | mitigate | Semaphore acquisition selects on `ctx.Done()`; the dispatch loop breaks rather than returning mid-flight, so `wg.Wait()` is always reached. |
| T-11-10 | Repudiation | per-artist log attribution under interleaved concurrent output | low | mitigate | D-07 accepts interleaving but requires full labelling; `TestMusicBrainzCycle_ConcurrentLogLinesAreFullyLabelled` pins `cycle_id`/`source`/`artist_mbid`/`artist_name` on every per-artist record so an incident is still reconstructible from an aggregator. |
| T-11-11 | Tampering | Deezer album slices inside worker goroutines | low | accept | Each worker processes its own entry's own independent slice with no shared indexing; the existing range-only defensive convention is preserved because the closure body is a direct translation of the sequential loop body. |
| T-11-SC | Tampering | package-manager installs | low | accept | No package-manager install occurs in this plan; `golang.org/x/time/rate` is already a direct dependency and `golang.org/x/*` is a first-party Go team module namespace. |
</threat_model>
