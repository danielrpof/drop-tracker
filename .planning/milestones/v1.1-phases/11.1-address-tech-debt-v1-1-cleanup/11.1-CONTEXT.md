### Working-tree state: Postgres port
- **D-01:** Keep the already-uncommitted `docker-compose.yml`/`Makefile` change reverting the published Postgres port from `5433` back to `5432:5432`. This was **not** an accident — the user confirmed the stray container that originally squatted on port 5432 (the root cause documented in `.planning/debug/resolved/notify-pass-hangs-forever.md` and referenced in PROJECT.md/comments) has since been shut down, so the original mapping is safe to keep permanently. — **Reversibility:** reversible — plain config value, easy to flip back if another collision recurs.
- **D-02:** Update the stale rationale comments in `docker-compose.yml` and `Makefile` (currently the diff already dropped the "why 5433" explanation) to instead explain *why 5432 was chosen and later reverted from 5433*, so a future reader has the full history rather than a silently vanished comment. Also update PROJECT.md's Phase 05 UAT key-decision entry / Context section if it references the 5433 port number directly, so the documented state matches reality.

### Phase 8 frontend-test debt
- **D-03:** Fix `SearchBox.test.tsx`'s stale comment (WR-01, 08-REVIEW.md) claiming both tests fail against current source — no longer true since fix `14003dd` landed. Doc-only.
- **D-04:** Fix `EventCard.tsx`'s single-quote string literals to conform to `.prettierrc`'s `singleQuote:false` (IN-01), **and** add a `prettier --check` step to `.github/workflows/full-pipeline.yml` so this class of formatting drift is caught by CI going forward, not just fixed once. — **Reversibility:** reversible — a new independent CI step, easy to remove if it proves noisy.
- **D-05:** Add real test coverage for both flagged gaps: `watchlist.test.tsx`'s remove action gets a failure-path/post-remove UI assertion (WR-02), and `HistoryFilters.test.tsx` gets a test exercising the `eventType` filter axis, not just `artistId` (IN-02). Both were explicitly chosen over "skip, roadmap floor already met."

### Phase 9 CI/coverage debt
- **D-06:** Fix `main_test.go`'s `TestRun_BootServesHealthThenGracefulShutdownOnCancel` (WR-01) so it selects on `run()`'s error channel instead of polling `/health` in a loop — an early boot failure should surface as the real error, not a generic timeout.
- **D-07:** Fix the `Makefile`'s `COVER_PKGS` unanchored `grep -v` substring match (WR-02) against `internal/db/sqlc` so a future package merely containing that substring isn't silently excluded too.
- **D-08:** Correct `.planning/v1.1-MILESTONE-AUDIT.md`'s stale claim that Phase 9's live-CI backstop verification is still outstanding — STATE.md already records it closed 2026-08-13 (three real GitHub Actions runs on scratch branch `test/coverage-gate-ci-check`, branch deleted). Add an amendment/correction note to the audit doc pointing at that closure record, rather than silently editing history.

Note for planning/execution: this is an orchestration action (a GSD command invocation), not a source-code change — plan it as its own task/step rather than folding it into a code-editing plan.

### Phase 11 concurrency debt
- **D-10:** Fix `detectDeluxeChanges`'s doc comment (WR-01, 11-REVIEW.md, `internal/detection/musicbrainz.go:278-294`) to explicitly state that an `InsertEvent` failure also skips any remaining groups in that artist's `freshGroups` slice for the rest of the current cycle (delayed to next cycle, not lost) — not just the one group whose insert failed.
- **D-11:** Fix `PoolConfig`'s two internal parse failures (IN-01, `internal/db/pool.go:160-186`) sharing identical wrapped error text — differentiate per the review's suggested diff (e.g. `"parse pool_max_conns override for %s: %w"` for the second, defensive parse call) so a production log line can tell which parser actually failed.
- **D-12:** For WR-02 (the `advanceGroupBaseline`-then-`InsertEvent` notification-loss window): add a distinguishable log/metric signal when this specific window is hit, beyond the existing generic `Warn` line — so an operator can observe how often it actually occurs in production. Explicitly **not** wrapping in a transaction (would require giving `Detector` a transaction-capable seam first — bigger scope, its own phase) and explicitly **not** leaving as documented-risk-only (the reviewer's two suggested follow-ups were "transaction" or "log signal"; log signal was chosen as the right-sized fix for a cleanup phase). — **Reversibility:** reversible — additive logging only, no behavior change.
