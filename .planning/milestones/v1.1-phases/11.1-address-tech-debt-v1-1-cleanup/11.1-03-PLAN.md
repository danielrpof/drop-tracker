**Edit A — D-10, doc comment.** The "Known, accepted edge" paragraph currently describes the loss window for exactly ONE group: the baseline advances, the insert fails, that group's notification is permanently lost. It never says what happens to the OTHER groups. Extend the paragraph (keep the existing text; add to it) to state the second, distinct consequence, which the reader currently has to derive from the control flow:

- The insert failure's `return fmt.Errorf(...)` propagates out of the `for _, g := range freshGroups` loop, so every group after the failing one in that artist's `freshGroups` slice is skipped for the rest of the current cycle.
- Those skipped groups are NOT lost the way the failing group is: their baselines were never advanced, so the next cycle recomputes them from scratch and they are simply delayed by one poll interval.
- Make the asymmetry explicit, because it is the load-bearing distinction: the failing group's notification is permanently lost; the groups behind it in the slice are merely delayed.

Note this failure mode is a pre-existing pattern shared with the sibling detection passes, not something Phase 11 introduced — 11-REVIEW.md says so and the comment should not imply otherwise. Exact wording is this phase's discretion (CONTEXT.md Claude's Discretion).
