<objective>
Build the single artist-art matching function both of bug #3's call sites will share, the read/write queries the backfill sweep needs, and the small concurrency primitive (D-10) that keeps the sweep from contending with interactive adds for the same rate-limited budget.

Purpose: every `artists.image_url` in this database is NULL and always has been — MusicBrainz has no artist images, and adds only ever flow from a MusicBrainz search result. Deezer has artist pictures but no MusicBrainz id, and this project has deliberately never had cross-source identity resolution. D-08 defines the narrow, fail-closed resolution rule that makes Deezer's pictures usable without ever attaching a wrong artist's photo. A `/grill-with-docs` challenge pass against the original three-plan design (see 13-CONTEXT.md's "grilling round" decisions D-10–D-13) found this plan's original scope insufficient on four points, now folded in here: diacritic folding for actual match yield (D-08 amendment, Q3), a substring-aware tie-break for the same reason (D-08 amendment, Q6), a cooldown so the backfill doesn't re-attempt the same fail-closed artists on every restart (D-12, Q4), and a shared activity signal so the backfill can yield to interactive adds (D-10, Q1).

Output: a new `internal/artistart` package containing the match rule, its narrow upstream seams, and the `ActivityGate` primitive, fully unit-tested against stubs with no real HTTP; a new migration adding `artists.art_match_attempted_at`; and two sqlc queries (a widened `ListArtistsMissingImage`, and a new `RecordArtMatchAttempt`) the backfill sweep needs.
</objective>
