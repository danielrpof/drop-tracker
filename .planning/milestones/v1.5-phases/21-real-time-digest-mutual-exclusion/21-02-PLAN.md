<objective>
Expand the proven gate from plan 21-01 in three directions: re-read the mode before every
Discord send so a mid-pass toggle stops the pass, log one line only when the observed mode
actually changes, and anchor stale-release suppression to each event's own `created_at` so
time spent pending never ages an event out of delivery.

Purpose: 21-01 closes the pass-level window; this plan closes the send-level one, which is
the window an operator actually hits (they toggle while a backlog is draining). The
`created_at` anchor is what stops DGST-14 and Phase 22's weekly cadence from quietly dropping
releases that waited in the outbox, and the transition logging is what makes the standdown
visible in production without a line per poll cycle.

Output: a notify pass whose every send is gated, whose mode changes are legible in the logs,
and whose freshness window travels with the event instead of with the clock.

**Release-sequencing note (locked 2026-09-11, ROADMAP "Deploy sequencing").** Phase 21 is not
merged to `main` until Phase 22 is also ready. Commit to the phase branch only.
</objective>
