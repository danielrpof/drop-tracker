<objective>
Put the digest-mode gate into the real-time notify pass and wire it end to end: a
`SettingsReader` seam declared in `internal/notifier`, made a required constructor
argument of `New`/`Select`, read under `dbOpTimeout` immediately after the `notifying`
CAS succeeds and before `listUnnotified`, failing closed on error — with the composition
root passing the same `settings.Service` the SPA writes through, and every existing call
site updated so the module compiles.

Purpose: this is the milestone's riskiest behavioral change, and it is the slice every
other plan in this phase expands out from. If the seam shape, the read placement, or the
failure posture is wrong, that is a one-commit correction here instead of a three-plan
unwind. It also fixes the constructor signature that plan 21-02 and all of Phase 22 build on.

Output: with digest mode on, a notify pass sends nothing and leaves every pending row
pending; with it off, the pass behaves exactly as v1.4 shipped.

**Release-sequencing note (locked 2026-09-11, ROADMAP "Deploy sequencing").** Phase 21 is
not merged to `main` until Phase 22 is also ready — landing the gate alone would put an
operator-visible standdown into production with no digest sender behind it. Commit to the
phase branch; do not open or merge a PR to `main` from this phase.
</objective>

<assumption_delta_decision>
**Primary noun:** the sender that drains the one outbox.
**Transition observed:** the `assumption-delta` probe returned `detected: true` with
`pluralization` signals on "un-gated real-time drain **alongside** digest", "do not add a
**second** digest queue table", and "this **also** means the digest window is defined by
outbox state".
**Decision:** `promote`.
**Rationale:** the transition is real and already adjudicated upstream. The `notifying`
`atomic.Bool` stops being "the real-time pass's re-entrancy guard" and becomes *the one
sender lock every outbox send serializes on* — real-time now, Phase 22's digest send later,
as a method on `Notifier` rather than an independent goroutine with its own guard. That is
D-04 and `docs/adr/0002-one-outbox-one-sender-lock.md` (status: accepted). The rejected
alternative — a second guard per sender — is recorded there with its failure mode: each guard
only stops its own sender overlapping itself, so a real-time pass and a digest send could
still list and send the same rows. The second signal is a *prohibition* on a plural (exactly
one outbox), not the arrival of one. Recorded for audit; non-blocking, not re-litigated here.
</assumption_delta_decision>
