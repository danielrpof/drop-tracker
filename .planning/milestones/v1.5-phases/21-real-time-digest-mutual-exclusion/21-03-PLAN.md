<objective>
Add the operator-facing explanation of the digest standdown to the `/system` Digest
notifications card: always-visible helper text under the Digest mode row reading exactly
"While on, new events wait for the next digest; switching back off delivers them
individually." — then refresh the committed SPA bundle so the embedded UI matches source.

Purpose: plans 21-01 and 21-02 make real-time notifications go quiet when the toggle is on.
Without this sentence the operator's only evidence of that is silence, which is
indistinguishable from a broken notifier. This one line is the difference between a designed
standdown and an apparent outage — and it is the only place in the product that states the
toggle-off flush behavior (DGST-14) to a human.

Output: one static sentence in an existing component, one test pinning it, and a bundle
refresh.

merged to `main` until Phase 22 is also ready. Commit to the phase branch only.

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-21-11 | Tampering | helper text rendering | low | mitigate | The copy is a static JSX text child. React escapes text children by default, and the plan forbids `dangerouslySetInnerHTML` and any interpolation of settings values into the sentence, so there is no injection path even if `notification_settings` were ever attacker-controlled. Pinned by the acceptance criterion that the component gains no new `~/lib/api` import and no new state. |
| T-21-12 | Tampering | committed `internal/webassets/build/client/` tree | medium | mitigate | A committed build artifact is a place where content could diverge from source unnoticed. Mitigated three ways: the tree is only ever produced by `make web` (never hand-edited, asserted); the task verifies the new copy is actually present in the regenerated bundle rather than trusting the command's exit code; and Phase 7's Docker image rebuilds the SPA in its own Node stage from source, so the shipped container never trusts this tree. |
| T-21-13 | Spoofing | dependency resolution during the refresh | medium | mitigate | `make web` uses `pnpm install --frozen-lockfile`, which refuses to resolve a version other than what `pnpm-lock.yaml` pins, so the refresh cannot silently pull a substituted or newly-published package into the embedded bundle. Enforced by the gate `git diff --exit-code -- web/pnpm-lock.yaml web/package.json`. |
| T-21-14 | Information Disclosure | helper text content | low | accept | The sentence describes a product behavior already visible in the UI's toggle. It names no host, credential, schedule, or identifier. |
| T-21-SC | Tampering | npm/pip/cargo installs | high | mitigate | No package is installed in this plan — the change is plain text in an existing component. `pnpm install --frozen-lockfile` plus the `git diff --exit-code -- web/pnpm-lock.yaml web/package.json` gate in both tasks means a new or substituted package cannot enter unreviewed, so no package-legitimacy audit is required and no `[ASSUMED]`/`[SUS]` package can reach the bundle. |

No threat is dispositioned `mitigate` at severity `high` or above without a concrete in-plan
mitigation, satisfying `security_block_on: high` at ASVS L1.
