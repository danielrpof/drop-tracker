<objective>
Make "rate-limited after the one permitted retry was already spent" a distinguishable
outcome in `internal/discord`, instead of a generic unexpected-status error
indistinguishable in shape from a 500.

Purpose: under plan 23-04's burst pacing a digest sends up to 20 messages through one
webhook in quick succession, which makes rate-limiting the single most likely cause of
a partial digest (D-28). Today that cause is invisible in the logs. Output: an exported
sentinel error in `internal/discord` and the test proving each status maps to the right
error identity. Plan 23-04 consumes it at the notifier's chunk-failure log site.

This plan is deliberately isolated to `internal/discord` so it runs in parallel with
plan 23-01's notifier work — the two share no file.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Discord webhook API -> drop-tracker process | Response status codes, headers, and bodies are attacker-influenceable by anything on that network path, including a misbehaving proxy or CDN error page. |
| drop-tracker process -> structured logs | An error value returned from this package is logged by `internal/notifier`; anything embedded in it lands in log storage. The webhook URL's path is a live credential. |
