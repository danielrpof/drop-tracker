<objective>
Expand plan 23-01's legal-but-greedy splitter into the shape the requirement actually
asks for: group-preferred boundaries so Phase 22's grouping survives the split by
construction, continuation markers on the rare group that genuinely must be cut, and
the `(N/Total)` position indicator on every message — with the whole chunker pinned by
the three property-style invariants 23-CONTEXT.md names as the definition of "provably
correct under a synthetic large digest".

Purpose: success criterion 2 requires grouping preserved across the split and no
content truncated away without a visible marker. Group-preferred filling makes the
common case correct by construction and demotes the continuation machinery to a rare
path (D-06), which is the cheapest way to make that criterion true. Output: a chunker
whose output is fully determined by its input and provably within Discord's ceiling.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Postgres `events` rows -> rendered chunk description | Community-editable artist names and titles flow through `digestLine` into chunk text that this plan rearranges across message boundaries. |
| Chunk composition -> Discord's 4096-rune Description ceiling | An over-budget Description is rejected with a 400, never acked, and retried forever with each attempt larger — a self-amplifying wedge, not a one-off failure. |
