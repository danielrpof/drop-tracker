<objective>
Build `cmd/coverage-report/`: a small, unit-tested Go `main` package that parses a Go coverage
profile and a Vitest coverage summary, reads cached baseline metric sidecars, computes signed
deltas, and renders the single markdown table the PR comment and the job summary both display.
It also exposes the `--mode=total` number `make coverage-gate` consumes in plan 15-02 (D-17)
and the `--mode=sidecar` writer the baseline-publish steps call in plan 15-03 (D-02).

Purpose: after D-17 this package is the one place a coverage percentage is computed in this
repo. The PR comment, the job summary, the 80% gate, and the published baseline all read its
output, which is why the comment and the gate cannot disagree.

Output: `cmd/coverage-report/main.go`, `cmd/coverage-report/main_test.go`, a committed
`testdata/` fixture set with golden markdown, and the `.golangci.yml` gosec carve-out that
lets the package be committed at all.
</objective>

<assumption_delta_decision>
**Primary noun:** the backend coverage total, computed once by `cmd/coverage-report`.
**Decision:** promote.
**Rationale:** D-17 makes the tool the single source of truth for the backend coverage number
and refactors `make coverage-gate` (plan 15-02) to consume it, rather than standing a second
independent measurement up alongside the existing gate. One parse, one rounding rule, so the
comment and the gate cannot disagree.
</assumption_delta_decision>

<planner_resolutions>
Open questions RESEARCH left to the planner, resolved here and binding on the executor:

1. **Two per-language sidecars** (RESEARCH Open Question 1) — `baseline-metrics-backend.json`
   and `baseline-metrics-frontend.json`, each cached alongside its own language's profile,
   each carrying the identical flat key set `pct` / `sha` / `generated_at`. D-13 forbids a
   dedicated baseline job, so a single merged sidecar would need a cross-job write. The tool
   reads whichever files are present; a missing one means that row's delta is the em-dash.
2. **The Go tool owns the step-summary write** (RESEARCH Open Question 4) — in comment mode it
   writes the body to `--out` and, when the `GITHUB_STEP_SUMMARY` environment variable names a
   path, appends the identical body there. One renderer, one format, and the summary is
   populated even when the sticky-comment step is skipped on a fork.
3. **Fixture file extensions** — the repo `.gitignore` excludes `*.out` and `coverage.out`, so
   a fixture named `sample.out` would silently never be committed. Go coverage-profile
   fixtures therefore use a `.txt` extension. `.gitignore` is not modified by this phase.
</planner_resolutions>

  <behavior>
    - Total mode against a valid profile writes exactly one line to stdout: the 2-decimal number and a newline, nothing else.
    - Total mode against a missing or malformed profile writes nothing to stdout, writes a diagnostic to stderr, and returns a non-nil error so the process exits non-zero.
    - Sidecar mode writes a JSON object with exactly the keys pct, sha and generated_at; pct equals the number total mode prints for the same profile; generated_at is an RFC3339 UTC timestamp.
    - Sidecar mode rejects a sha argument that is not 7 to 40 lowercase hex characters, returning an error rather than writing the file.
    - Comment mode with a head-sha argument that is not 7 to 40 lowercase hex characters omits the head SHA from the footer instead of echoing the argument.
    - Comment mode fed a profile whose file-path fields contain markdown and HTML metacharacters renders a body containing none of those metacharacter sequences.
    - A sidecar file whose sha field is not 7 to 40 lowercase hex characters yields a body with no provenance short SHA, and the run still exits 0.
  </behavior>
  <action>
    Wire the remaining two dispatch arms. Total mode reads `--profile`, runs the same backend
    parse and rounding helpers Task 1 built, and writes the formatted number plus a newline to
    the `stdout` writer `run` was handed — nothing else ever goes to that writer in this mode.
    Every diagnostic goes to `os.Stderr`. On any read or parse failure return a wrapped error so
    `main` exits 1 with an empty stdout; this is the condition the Makefile empty-output guard
    depends on in plan 15-02.

    Sidecar mode reads `--profile`, `--sha` and `--out`, computes the same rounded percentage,
    and marshals a flat object with the keys pct, sha and generated_at, where generated_at is
    the current time in UTC formatted as RFC3339. Write it to the `--out` path. Sidecar mode
    returns an error on a bad profile or an unwritable output, so a failure is visible in the CI
    log even though the calling step is best-effort.

    Add a single shared SHA validator used by all three modes: a commit SHA is accepted only
    when it matches 7 to 40 lowercase hexadecimal characters. Sidecar mode treats a rejected
    `--sha` as a hard error. Comment mode treats a rejected `--head-sha`, or a rejected sha
    inside a sidecar file, as absent — the corresponding footer element is simply omitted and
    the run still exits 0 (D-04). This is the concrete V5 control: it is the only path by which
    a string read from a file or an event payload could otherwise land in the comment body.

    Audit the render function against the same rule and fix any violation: no file path, no raw
    profile line, no JSON field other than a validated sha and a computed number may appear in
    the body. Numbers pass through the rounding helper and a fixed-precision formatter; the
    timestamp is generated by the tool; every other character in the body is a compile-time
    literal in the renderer.

    Add `testdata/backend-profile-hostile-paths.txt`: a well-formed profile whose file-path
    fields carry markdown and HTML metacharacters and a pipe character, so a naive renderer
    would both break the table and inject markup. Add a test named
    `TestRenderComment_NoUntrustedInterpolation` that renders against it and asserts the body
    contains none of the metacharacter sequences present in the fixture's path fields, while
    still reporting a correct backend percentage — the test derives the forbidden substrings
    from the fixture at runtime rather than restating them, so the assertion cannot drift from
    the fixture.

    Add tests named `TestModeTotal_PrintsOnlyNumber` (drives `run` with a `bytes.Buffer` as
    stdout and asserts the buffer matches a 2-decimal number plus a single newline and nothing
    else), `TestModeTotal_MissingProfile` (asserts a non-nil error and an empty stdout buffer),
    `TestModeSidecar_Roundtrip` (asserts the written JSON decodes with exactly the three
    expected keys and that its pct equals what total mode printed for the same fixture), and
    `TestSHAValidation` as a table test over accepted and rejected sha shapes.
