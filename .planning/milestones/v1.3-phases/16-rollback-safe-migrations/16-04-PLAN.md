<objective>
Wire the two checks into the pipeline so a migration that breaks rollback cannot merge: a
`changes` prelude that computes the diff base once, an always-green-or-red guard job, and an
`n1-boot` job that pulls the previously-released image and proves it starts, stays healthy,
reads, and writes against the current branch's schema.

The wiring is where this phase is most likely to fail silently. RESEARCH Finding 2 refuted the
premise the original design rested on — a skipped `needs:` job does **not** count as success,
it skips its dependents — so the shape here is deliberately: unconditional jobs, conditional
steps.

Purpose: MGRT-01 / SC #1 and SC #2, decisions D-01, D-03, D-04, D-11, D-12 (as corrected by
RESEARCH Finding 2), D-13, D-14, D-16, D-19a.
Output: three new jobs and two `build-scan.needs:` entries in
`.github/workflows/full-pipeline.yml`.
</objective>

    Add an `n1-boot` job: `needs: [changes]`, `runs-on: ubuntu-latest`, a timeout in the
    5-to-10-minute range, `permissions: contents: read`, and **no job-level `if:`**. Every step
    that costs more than a second carries
    `if: needs.changes.outputs.migrations_changed == 'true'`. On a push touching no migration
    the job therefore succeeds in runner spin-up time while still reporting success to
    `build-scan`.

    Step sequence:

    1. Checkout with `fetch-depth: 0` and `fetch-tags: true`, and `setup-go` — both
       unconditional so the job has a working tree regardless.
    2. **Resolve the previous release tag** (gated): the same pinned `svu` install and
       `svu current` invocation the `release` job uses; export the result to `$GITHUB_ENV`.
    3. **True-bootstrap guard** (gated): if the resolved tag is empty, print a workflow notice
       explaining that no prior release exists and that the N-1 check is therefore not
       applicable, and end the job successfully. Implement this as an in-job step that short-
       circuits the remaining gated steps, not as a job-level condition (D-19a). It is dead code
       on this repository — `v1.x` tags already exist — and that is accepted.
    4. **Throwaway Postgres** (gated): `docker run -d` a `postgres:16` container on host
       networking with the credentials and database name matching the `Makefile`'s
       `TEST_DATABASE_URL` default, followed by a bounded `pg_isready` wait loop that fails the
       step with a clear message if the database never becomes ready. Use a gated `docker run`
       step and **not** the `services:` key — a `services:` container ignores step conditions and
       would start on every push (RESEARCH Pitfall D).
    5. **Apply HEAD's schema** (gated): `go run ./cmd/migrate` with the DSN in `env:`. This
       routes through `internal/db.RunMigrations` — the same embedded-source and bounded-retry
       path the application runs at boot (D-01) — so the schema under test is produced by the
       real code path rather than by a CLI the app never uses.
    6. **Pull the previous release image** (gated): pull `ghcr.io/danielrpof/drop-tracker` at the
       resolved immutable tag, with exactly one retry after a short sleep before declaring
       failure (D-04). Never pull a floating tag. The package is public, so add no login step
       and request no registry permission.
    7. **Run the previous release image** (gated): `docker run -d` on host networking with
       exactly two environment variables — the database DSN and the HTTP port. Pass nothing else.
       In particular the Phase 14 instance-gate variable must be absent, so the gate stays on its
       inert path and the probe routes answer with real query results rather than an
       authentication response; with the gate active a broken schema would return an auth status
       instead of a 500 and this whole check would become a permanent false green.
    8. **Health probe** (gated): poll `/health` until the first 200, then require a sustained
       run of consecutive 200s — 8 polls at roughly 2-second spacing is the recommended shape —
       before proceeding. A container that starts and then dies must fail here. On timeout, dump
       the container logs to the step output before failing so the red is diagnosable.
    9. **Read probes** (gated): `GET /watchlist` must return 200 with an empty array, and
       `GET /events` must return 200 with an empty events collection. These handlers run real
       sqlc queries, which is exactly what `/health` cannot check.
    10. **Write probe** (gated): `POST /watchlist` with a fixed literal body carrying an MBID, a
        name, and an image URL — supplying the image URL is what bypasses the art matcher and
        keeps this a pure database write with no outbound call. Assert a 2xx, then re-read
        `GET /watchlist` and assert the created row is present. This is what covers the poller's
        insert paths, which a read-only check would miss (S1).
    11. **Failure message** (gated, runs on failure): print a message naming the N-1
        compatibility rule and the expand/contract rule and pointing at
        `internal/db/migrations/README.md`. A red here must teach the rule, not report an opaque
        boot error (SC #2).
    12. **Teardown** (gated, always-run): stop and remove both containers.

    Every dynamic value crosses into `run:` through `env:`. Reuse the action SHAs already present
    in this file; add no new third-party action.
