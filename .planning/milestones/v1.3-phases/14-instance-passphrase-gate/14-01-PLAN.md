<objective>
Deliver the instance passphrase gate as one production-quality end-to-end slice: an
unauthenticated data request returns 401, `POST /session` with the correct passphrase mints a
signed stateless cookie, that cookie unlocks the data routes, `DELETE /session` clears it, and
with no passphrase configured the entire feature is structurally absent.

Purpose: prove the whole architecture — config → `internal/authgate` HMAC codec → chi Group
middleware → session endpoints → `cmd/server/main.go` wiring — on one path before any hardening
expands sideways from it. Every later plan in this phase builds out from this slice.

Output: the `internal/authgate` package (session codec, gate middleware, login/logout handlers,
Alerter seam), the `httpserver.WithAuthGate` functional option and protected route Group, the
`InstancePassphrase` config field, and the Go test suite proving the 401 → login → 200 → logout
contract plus the inert path.
</objective>

<assumption_delta_decision>
**Primary noun:** the instance session — anonymous, backed by a single shared operator secret.

**Decision:** `no-change`.

**Rationale:** this phase moves the app from unauthenticated to gated, but it introduces no
principal, no account, no identity. D-02 is explicit that the cookie payload carries only an
"authenticated until T" claim plus a nonce — no user id, no PII, no roles. Multi-user auth,
accounts, OAuth and RBAC are rejected in PROJECT.md and listed out of scope in 14-CONTEXT.md
`<domain>`. Generalising the session model toward multi-principal now would be speculative
architecture with no consumer; GATE-08 (key rotation without mass logout) is the only recorded
future extension and it does not require an identity model. No domain-model change is warranted.
</assumption_delta_decision>

  <context>
Locked decision D-09 specifies the `__Host-` cookie name prefix together with "Secure stays on even
for local http://localhost, no dev toggle". Research finding A1 establishes that Chrome rejects
`__Host-` and `__Secure-` prefixed cookies on an `http://localhost` origin because the scheme is not
HTTPS, while it does accept a non-prefixed cookie carrying the Secure attribute on that same origin.
Firefox accepts both. Production is unaffected either way — Phase 17 terminates TLS — but an
operator who sets INSTANCE_PASSPHRASE locally to test the gate in Chrome over plain http would loop
on the login form with no error shown. The planner has no authority to override a locked user
decision, so this is the operator's call. Everything after this task depends on the answer, so no
cookie-setting code is written until it lands.
  </context>

Create `internal/authgate/session.go`. Declare the unexported duration constants `sessionWindow` at
30 days, `renewAfter` at 15 days and `absoluteCap` at 90 days (hardcoded per D-07 — no env var, no
`SESSION_TTL`), and `sessionCookieName` set to the literal chosen in Task 1. `DeriveKey` returns
`sha256.Sum256` over a domain-separation prefix string concatenated with the passphrase, per D-01 —
exactly one secret, no separate signing key, no key-version byte. `Token` carries `IssuedAt`,
`Expiry` and a 16-byte `Nonce` filled from `crypto/rand`. `Sign` marshals the payload
deterministically, base64-encodes it with `base64.RawURLEncoding`, computes
`hmac.New(sha256.New, key[:])` over the encoded payload, and returns payload and MAC joined by a
single period. `Verify` splits on the period, decodes both halves, recomputes the MAC, compares with
`hmac.Equal`, then rejects when `now` is not before `Expiry`, rejects when `now` is not before
`IssuedAt.Add(absoluteCap)`, and finally reports `needsRenew` true when `now` is after
`Expiry.Add(-renewAfter)`. Every failure path returns the same zero Token and ok false — never a
distinguishing error string. Match the multi-paragraph "why not what" doc-comment density of
`internal/db/migrate.go`'s redaction block, citing D-01, D-02, D-06 and D-07.

Create `internal/authgate/alerter.go` with the `Alerter` interface declaring
`Alert(ctx context.Context, message string) error`, an unexported `noopAlerter` struct whose `Alert`
returns nil, and a compile-time `var _ Alerter = noopAlerter{}` assertion. Mirror

Create `internal/authgate/gate.go` with `Manager` holding the derived key, the `Alerter`, and the
`*slog.Logger`, constructed by `NewManager(passphrase string, alerter Alerter, logger *slog.Logger) *Manager`.
`NewManager` derives the key once and never retains the passphrase string itself beyond deriving
the SHA-256 digest it needs for the login comparison. `Authenticate` returns a
`func(http.Handler) http.Handler` closure shaped exactly like `echoRequestID`: read the session
cookie by name, call `Verify` with `time.Now()`, and on failure write the fixed JSON body
`{"error":"unauthenticated"}` with status 401 and return without calling next. On success, when
`needsRenew` is true, re-sign a Token whose `IssuedAt` is copied unchanged from the verified token,
whose `Expiry` is now plus `sessionWindow` and whose `Nonce` is fresh, and write the renewed
`Set-Cookie` on `w` before calling `next.ServeHTTP`. Add a `setSessionCookie` helper that builds an
`http.Cookie` via `http.SetCookie` with `Path` set to `/`, `HttpOnly` true, `Secure` true,
`SameSite` `http.SameSiteLaxMode` and the supplied `MaxAge` — never a hand-built header string. Add
a `writeJSONError` helper writing a fixed operator-authored body; it must never embed raw error text.

Create `internal/authgate/login.go` with `HandleLogin` and `HandleLogout` methods on `*Manager`.
`HandleLogin` wraps the body in `http.MaxBytesReader` bounded by a `maxSessionBodyBytes` constant of
4096, decodes a JSON object with a single `passphrase` field, and compares by hashing both the
submitted value and the configured value with `sha256.Sum256` and passing the two 32-byte digests to
`crypto/subtle.ConstantTimeCompare` — the digests make length unobservable per Pitfall 3. On a match
it mints a brand-new Token with `IssuedAt` set to now, a fresh `crypto/rand` nonce and `Expiry` at
now plus `sessionWindow`, ignoring any inbound cookie entirely (D-17 session rotation), writes the
cookie with `MaxAge` equal to `sessionWindow` in whole seconds, and returns 204 with no body. On a
mismatch it returns 401 with `{"error":"invalid passphrase"}` and sets no cookie. The passphrase must
never be read from the URL, the query string, or a GET form (Pitfall 14). `HandleLogout` calls
`setSessionCookie` with an empty value and `MaxAge` of -1, which `net/http` renders as `Max-Age=0`,
and returns 204 (GATE-06, D-10 — client-local only). Throttling, the fixed delay, the global counter
and audit logging arrive in plan 14-02; leave clean insertion points, not placeholder comments that
promise them.
