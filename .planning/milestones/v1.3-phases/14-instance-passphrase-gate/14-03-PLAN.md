<objective>
Give the SPA the other half of the gate: a global 401 interceptor that flips shared auth state, a
full-screen passphrase form matching the approved UI contract, and a Log out control — so a gated
instance renders a login prompt instead of a broken page, and a successful login restores the full
watchlist and history UI without a reload.

Purpose: GATE-05 and the client half of GATE-06. PITFALLS #23 is the failure this closes — a
server-side 401 contract with no client handling leaves a visibly broken app.

Output: `web/app/lib/authStore.ts`, the `apiFetch` 401 interceptor and CSRF header plus the two
session wrappers in `web/app/lib/api.ts`, `web/app/components/auth/PassphraseScreen.tsx`, the
`<App>` gate branch and Log out control in `web/app/root.tsx`, and their tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser DOM → `POST /session` body | The passphrase leaves the user's keyboard and must reach the server only through a POST body. |
| Cross-site page → the SPA's origin | A hostile page may attempt a form POST or an image GET at the gated API; it cannot set custom headers without a preflight the server denies. |
| Server 401 → SPA state | The server response is the sole enforcement signal; the client's auth flag is presentation only. |
| Static SPA bundle → public internet | The bundle is served unauthenticated by design (D-04) and therefore may carry no secret. |
